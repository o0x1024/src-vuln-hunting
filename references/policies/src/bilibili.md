# 哔哩哔哩 BILISRC 报告处理规则摘要
- 状态: secondary；置信度: 中
- 来源: https://security.bilibili.com/static/docs/BILISRC_V1.7.pdf（官方 PDF；本次直连被对端拒绝，内容经搜索引擎对该 PDF 的索引摘要获得，查阅于 2026-10-12）；规则版本/更新: BILISRC 漏洞处理和评分标准 V1.7（另有 V1.2 历史版本，奖励数值有上调）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 哔哩哔哩产品漏洞与业务安全情报两大类：漏洞情报（野外利用的未知漏洞线索、入侵线索、重要数据库被拖取线索、支付业务逻辑漏洞利用线索、蠕虫传播线索、大规模用户信息窃取线索、影响排序机制的工具方法等）与业务情报（黑灰产/异常利用链关键要素，如补贴、激励、权益风险）。
- 敏感信息提交边界：信息本身构成重要数据且有明确可复现技术漏洞的，走漏洞奖励计划；不构成独立技术漏洞但被用于业务风险行为的，按业务安全情报评估。

## 等级与奖励（V1.7 摘要）
- 漏洞等级：严重 / 高危 / 中危 / 低危 / 忽略；基础经验值最高 10。
- 严重：经验值 9~10 / 安全币 1000~1200（V1.2 为 500~1000，已上调）；核心系统权限（RCE、Webshell、SQL 注入获取系统权限、溢出）、泄露 10w 条以上可遍历重要敏感信息（需满足明文三要素）、核心账号/支付业务严重逻辑缺陷（批量改密、任意账号登录、无限制任意资金消费等）。
- 高危：经验值 6~8 / 安全币 300~600（V1.2 为 200~400）；一般系统权限、大量可遍历重要敏感信息泄露、核心业务敏感越权（后台弱密码、未授权访问、增删改查任意用户敏感信息）、获取大量内网敏感信息的 SSRF。
- 中危：经验值 3~5 / 安全币 30~100；需交互或前置条件影响用户的漏洞（一般页面存储型 XSS、JSONP 劫持、支付/账号敏感操作 CSRF）、非核心 DB SQL 注入等。
- 安全币约合人民币 1:10 汇率（V1.2 原文表述），仅用于兑换，具体以现行版为准。
- 业务安全情报：威胁等级 L1（低危，3~7 币/经验 1~2）、L2（中危，10~30/3~5）、L3（高危，100~200/6~8）、L4（严重，300~400/9~10）；奖励上限按威胁等级定，再按情报完整度 C1（线索级）~C4（策略高精准型）给比例，C1 为 10%~20%；业务情报金币约为同等级漏洞的 1/3。

## 忽略/不收项
- 业务预期内的资损问题、风险可控的问题：降级/忽略。
- 与其他漏洞部分环节重复的漏洞。
- 利用复杂度高、需特殊账号权限、需交互利用、需爆破难度较大字段的：降级/忽略。
- 不可复现/无影响的漏洞不收（等级体系含"忽略"档）。

## 测试红线
- SSRF：禁止利用 SSRF 进行内网渗透测试或其他有害行为，证明 SSRF 存在并且有回显即可。

## 报告要求
- 漏洞需可复现并产生实质影响；情报类需满足最小完整性要求：情报对象明确（攻击手段/工具脚本/接口行为/账号行为/攻击链等）+ 至少 1 个稳定可识别标识（脚本名+hash/版本、接口 path/域名/IP、关键特征）；核心行为成立（提供原始样本：脚本代码、二进制、请求样本、日志片段等）。

## 处理流程与时限
- 流程：报告 → 处理 → 完成；威胁情报分析调查时间较长，确认周期比普通漏洞长。
- 客户端安全问题受版本发布限制，修复时间按实际情况定。
- BILISRC 会挑选有代表性的威胁情报（经报告者许可）发布分析文章。

## 易错点
- V1.2 与 V1.7 奖励数值不同（严重 500~1000 → 1000~1200），引用时必须核对现行版本号。
- 漏洞与业务情报是两套体系：情报奖励有上限且按完整度打折（C1 仅 10%~20%），不要按漏洞价预期。
- "明文三要素"、10w 条可遍历等门槛决定严重档定级，数据量与明文程度直接影响等级。
- 官方 PDF 直连可能被拒（本次连接被关闭），需浏览器下载核对原文。
