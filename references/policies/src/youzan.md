# 有赞 YZSRC 报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://src.youzan.com/index.php?m=&c=page&a=view&id=13（查阅于 2026-10-12）；规则版本/更新: 《有赞外部威胁报告处理标准》V2.3.1，自 2026-07-01 起实施
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 有赞相关业务按风险治理优先级分为高系数/中系数/低系数业务三类（具体域名对照表为站内图片，公开文本未含域名清单）。
- 有赞云三方开发者系统（*.isv.youzan.com、*.isv-dev.youzan.com 等域名下）只收取高危及以上漏洞，且按对有赞的实际影响降分。
- 同时接收威胁情报（黑产、入侵、刷单、黄赌毒、黄牛插件、恶意注册、社区灌水等），按 Who/Where/How/What 四要素完整度计分。
- 明确不收：YZSRC 平台本身漏洞、应用市场中非有赞域名下的应用漏洞、AllValue 国际站商家自定义 C 端页面的 XSS、非有赞业务漏洞。

## 等级与奖励
- 五级：致命 / 高危 / 中危 / 低危 / 无影响（忽略）；1 安全币 = 1 人民币；贡献值用于荣誉。
- 各等级具体安全币数值表为站内图片，公开文本抓取不到数字，需登录平台核对。
- 信息泄露定级硬门槛：高危/致命级信息泄漏需泄漏 ≥3 个元组（真实姓名、身份证号、住址、手机号、银行卡号等）且影响数量 >1 万条，按重点业务属性和绝对数量评级；不满足则酌情降级。
- 特色奖励：季度贡献值 Top3 奖（需满足高危及致命漏洞数量条件）、"贼NB漏洞奖"每季 5000 元现金（可空缺）、报告写得好奖 10-50 安全币浮动、闪耀新星奖（首次注册提交有效报告送周边）。
- 有赞员工不得参与或通过朋友参与漏洞奖励计划。

## 忽略/不收项
- 无法利用类：Self-XSS、无敏感操作的 CSRF（含登出/匿名 CSRF）、无回显 SSRF、内网 IP/域名泄漏、管理后台泄漏、无敏感信息的 SVN/Jsonp/CORS、仅固定版本小众浏览器可触发的 XSS。
- 非安全问题：产品功能缺陷、网页乱码、样式混乱、静态文件目录遍历、应用兼容性问题。
- 流程类：多次确认无法重现、内部已知或已有白帽优先提交（如店铺/连锁内部垂直越权）、无实际意义的扫描器结果报告。
- 业务特例：AllValue 国际站自定义 C 端页面 XSS、应用市场非有赞域名应用、上传 OSS 导致的 XSS。

## 测试红线
- 测试规范遵循《SRC行业安全测试规范》；谴责以测试为借口的破坏、盗取隐私/虚拟财产、入侵、恶意传播漏洞或数据，违者追究法律责任。
- 线上增删改操作不得直接操作正常用户数据；自建测试数据需在标题或明显字段加【我是白帽子】字样。
- 修复前公开、损害用户利益、盗取用户数据：不计分并保留法律行动权利。

## 报告要求
- 报告必含四要素，缺项做忽略处理：【漏洞标题】（题目、影响域名、类型）、【漏洞描述】（入口、URL、参数）、【复现过程】（按步骤、体现危害、文字截图、注明工具名）、【修复方案】（可执行建议）。
- 书写规范清晰的报告可获 10-50 安全币额外奖励。

## 处理流程与时限
- 公开文本未承诺具体时限（承诺每份报告专人评估跟进）。
- 计分原则：同一威胁最早提交者得分；网上已公开不计分；通用漏洞在补丁下发 30 天内提交不计分；同源多洞合并、只计最早提交者；同一漏洞多个利用点按最高级别计一次；SaaS 同一漏洞多店铺重复提交合并处理；触发条件苛刻可跨等级调整。
- 建议/争议渠道：yzsrc@youzan.com 或公众号"有赞安全应急响应中心"。

## 易错点
- 【最重要】2026-09-01 起暂停接收和收录新漏洞（2026-08-31 官方公告），恢复时间另行通知；暂停期提交大概率无效，存量报告仍按原流程处理。
- isv.youzan.com 三方系统只收高危以上且降分，中低危白挖。
- 信息泄露不满足 3 元组/1 万条门槛会被降级，报告里要写清元组类型和数量。
- 奖励数字表是图片，纯文本抓取拿不到金额，定级预判需登录核对。
- 同源/同漏洞合并规则严格，一洞多交只有最早提交者得分。
