# SRC 行业安全测试规范（跨企业通用测试红线）

- 状态: official；置信度: 高
- 来源: https://security.mcd.cn/index.php?m=&c=page&a=view&id=1（公告编号 MCDSRC2022-1，发布日期 2024/10/17）（查阅于 2026-10-12）
> 参与此标准制定的组织：腾讯SRC、蚂蚁金服SRC、ASRC、阿里云先知、百度SRC、本地生活SRC、菜鸟SRC、滴滴SRC、京东SRC、LYSRC、蘑菇街SRC、陌陌SRC、360SRC、苏宁SRC、同舟共测-企业安全响应联盟、唯品会SRC、微博SRC、VIPKID SRC、网易SRC、WiFi万能钥匙SRC、完美世界SRC、小米SRC（排名不分先后）。
> 本规范被大量 SRC 直接挂载为站内测试规范；对未单独公布红线的 SRC 可作为默认行为基线，但个别平台条款优先。

## 14 条测试规范（要点全文）
1. 注入漏洞：证明可读取数据即可，严禁读取表内数据；UPDATE/DELETE/INSERT 类注入禁止用自动化工具测试。
2. 越权读取：能读取到的真实数据不超过 5 组，严禁批量读取。
3. 账号可注册：只用自己 2 个账号验证；不涉及线上正常用户账号；越权增删改用自有测试账号。账号不可注册且拿到账密的，进一步测试需先咨询管理员。
4. 存储 XSS：插入不影响他人的 payload，严禁弹窗，推荐 console.log 并用另一账号验证截图；盲打 XSS 仅允许外带 domain 信息；测试后删除插入数据，不能删的备注插入点。
5. 可 shell/命令执行：上传纯文本证明（如 1.php/1.jsp）即可；禁止下载/读取源码与敏感文件；不执行删除、写入命令；webshell 需写明地址和连接口令。
6. 扫号类：测试成功数量不超过 50 个；用户可感知（如登录提醒短信）的，不允许对他人真实手机号测试。
7. 自动传播类漏洞（社交蠕虫等）：只用与其他账号隔离的小号测试，不用有社交关系的账号。
8. 禁止对网站后台和部分私密项目使用扫描器。
9. 除特别获准，严禁与漏洞无关的社工，严禁内网渗透。
10. 禁止可能引起业务异常运行的测试（如 IIS 拒绝服务类）与 DDoS。
11. 不测未授权厂商、未分配项目、超出范围列表的资产；先联系管理员确认归属，否则法律风险自担。
12. 禁止拖库、随意大量增删改他人信息；禁止影响服务稳定性的扫描；禁止把漏洞用于黑灰产。
13. 敏感信息（源码、运营数据、用户资料等）禁止保存和传播；不知情下载需及时说明并删除。
14. 遵守《网络安全法》；禁止以测试为借口破坏、损害用户利益（含威胁公开漏洞/数据）；对第三方披露先获 SRC 授权；违规者将被追究法律责任。

## 易错点
- 这套规范是"测试行为上限"，不是收录标准：满足红线不代表漏洞会被收录。
- 各平台在 5 组越权、50 个扫号等数值上有自己的变体（如 UCloud 同为 5 组/50 个，多点 DMSRC 为 ≤10 组），以目标平台现行文本为准。
- 规范由多家 SRC 联合签署，引用时注明"行业规范"而非某一家政策。
