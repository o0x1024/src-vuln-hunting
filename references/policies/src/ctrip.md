# 携程 携程安全应急响应中心（CSRC）报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://sec.ctrip.com/bulletin/127.html（查阅于 2026-10-12）；规则版本/更新: 漏洞评分标准和奖励细则V8.1，公告编号 CSRC-2026-0915，发布 2026-09-15
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 本评分标准针对携程的产品和业务（V8.1 正文未再列 .qunar.com；上一版 V8.0 明确覆盖携程及去哪儿：*.ctrip.com、*.trip.com、*.occpay.com、*.qunar.com 及双方 APP；与携程完全无关的漏洞不计币）。
- 应用重要性分级（V8.1）：核心应用=*.ctrip.com（国内主站）、*.trip.com（国际）、*.occpay.com（程付通）；一般应用=ebooking.ctrip.com（酒店赫程）、携程通 b.ctrip.com、供应商 vbooking.ctrip.com 等；边缘应用=go.ctrip.com（招商合作）、sec.ctrip.com（CSRC 平台自身）、开放平台 u.ctrip.com、latitude.ctrip.com、careers.ctrip.com、铁友 tieyou.com、永安 wingontravel.com 等。

## 等级与奖励
- 等级：严重/高/中/低；货币单位携程币，1 携程币=1 RMB。按漏洞类型×应用分级给币（核心/一般/边缘）：
  - 命令执行（严重）11000/3700/1100；任意登录（严重）10000/3300/1000；越权查询≥3 个敏感维度如姓名+手机号+身份证（严重）8000/2700/800
  - SQL 注入（高）5000/1700/500；全回显 SSRF（高）4000/1500/400；越权查询<3 维度（高）4000/1500/400
  - 任意文件读取、XXE、有掩码越权查询（中）1000/350/100；普通越权操作（中）700/250/70；存储 XSS（中）800/300/80
  - 无用户敏感信息的越权查询、短信/邮箱轰炸（低）200/50/10、100/50/10
- 威胁情报另设奖励表：高危 100-300×系统系数（核心 10/一般 5/边缘 1），核心最高 1000-3000 携程币。

## 忽略/不收项
- 无危害项：产品功能缺陷、乱码、样式、静态目录遍历、兼容性问题；无法利用项（无敏感操作 CSRF、无意义异常、内网 IP/域名泄漏）。
- 地图 API key 泄露；反射型 XSS、self-XSS、pdf-XSS；URL 跳转；普通账户弱口令；单纯接口文档泄露（不能进一步利用）；客服操作失误导致的漏洞；SPF/DKIM/DMARC 邮件配置问题；GitHub 开源项目相关漏洞；正在内部整改中的漏洞（以审核回复为准）。

## 测试红线
- 敏感数据样本：严重级原则上需 1 项高敏感标识（身份证/银行卡）+至少 2 项可关联字段（姓名+手机号+身份证示例）；高危需 1 项高敏感标识+至少 1 项关联字段；提交样本不超过 5 条。
- 禁止恶意拖取用户数据、内网扫描探测等造成业务影响的行为，保留追究法律责任权利。
- 通用型漏洞（同一漏洞源多个表现）计 1 个，首位提交者得币；同一漏洞不得多平台重复提交（含去哪儿 SRC），已公开漏洞不计币。
- 短时间同一系统大量同类型漏洞（SQLi/RCE/XSS 等）视为无防护，仅受理前 3 个。
- 以测试为借口损害用户/平台利益、影响业务、修复前公开、盗取数据：不计分+法律行动；须遵守《携程SRC安全测试行为规范 v1.0》。

## 报告要求
- 描述尽量详细，附测试功能点截图、请求数据包；描述过于简单（如暴力破解只给登录页）会降级或忽略。

## 处理流程与时限
- 平台在线提交→审核→修复→复查（官网公示响应流程图）；处理时限未在公开页标注具体天数。
- 争议：在漏洞详情下评论留言联系审核，或发邮件 CSRC.security@Ctrip.com；按报告者利益优先处理，必要时引入外部人士共同裁定。

## 易错点
- V8.1（2026-09-15）已替代 V8.0/V7.0，旧版数值勿再引用；新样本量规则（≤5 条、维度组合）是定级硬门槛。
- 官网另有《携程SRC关于AI生成漏洞报告的处置公告》、历史《关于携程SRC暂停漏洞测试的公告》、《CSRC暂停接收去哪儿单一因子验证的相关越权漏洞》——去哪儿单一因子越权类当前不收。
- 分享/披露需求须提前邮件 CSRC.security@trip.com 评估，未经同意私自披露保留追责。
