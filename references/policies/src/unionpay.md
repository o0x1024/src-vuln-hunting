# 中国银联 银联安全应急响应中心（USRC）报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://security.unionpay.com/notice/detail?id=972（查阅于 2026-10-12）；规则版本/更新: 《银联安全应急响应中心漏洞处理流程及评级标准》新版，公告日期 2026-01-16（系统公告，自发布之日起施行）；旧版为 2017-12-01 公告（id=57）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 适用于"USRC 收到的所有漏洞"（银联相关安全漏洞），未公开列资产清单；应用按重要程度分核心应用系统/一般应用系统/边缘应用系统三档，奖励综合危害程度、利用难度、影响范围与应用重要度决定。
- 平台为银联自建（security.unionpay.com）；白帽子需注册 USRC 并关联绑定云闪付账号后方可登录提交。

## 等级与奖励
- 五级：严重/高危/中危/低危/忽略；奖励=积分（荣誉，月度/年度贡献榜）+金币（奖金或礼品兑换）+额外奖励；提交完整 POC 程序可酌情加积分。
- 金币比值≈1 元人民币；针对核心系统特别重大的安全漏洞视情况给予额外奖励（新版正文未再写明旧版"严重额外奖励暂定 1 万-2 万"的具体数字，以平台实际评定为准）。
- 【严重】可获取集中生产云服务器和系统权限（任意代码/命令执行、SQL 注入获取核心权限、上传 Webshell 可执行）；可获得大量持卡人个人信息（用户 ID、姓名、手机号、设备信息、财产信息、证件号码/照片、银行卡号、生物识别信息、密码类鉴权信息等）并影响身份安全；可获得核心应用系统业务数据（机构/交易/设备信息等）造成公司或用户损失。
- 【高危】逻辑设计缺陷（任意账号登录、任意改密、关键环节短信/邮件验证码绕过）；持卡人个人信息批量泄露（SQL 注入、越权、未授权访问）；一般应用系统业务数据批量泄露；其他信息泄露（任意文件包含/读取、源代码泄露、客户端加密算法可被破解）；能直接访问内网且可获取回显的 SSRF（须证明可访问内网，且不得对内网服务扫描）；资金损失（任意金额支付、任意账号支付）。
- 【中危】需交互获取身份信息（可获管理员权限的存储 XSS、重要敏感操作 CSRF）；越权（批量越权访问、查看他人信息、管理后台访问）；应用管理员弱口令；客户端可直接获取系统管理员/root；可远程窃取客户端数据；绕过限制获取优惠（大量重复享有受限优惠）；能访问内网但无回显的 SSRF。
- 【低危】无数据 SQL 注入；Jsonp Hijacking、非重要敏感操作 CSRF；一般信息泄露（路径/SVN/LOG/Phpinfo/文件遍历）；一般越权（越权修改删除他人信息）；一般逻辑缺陷（无限制短信/邮件、图形验证码绕过、非关键环节短信绕过）；反射型 XSS；URL 跳转；客户端本地漏洞（本地 DoS、命令截断、dll 劫持）；业务需要的撞库/爆破/遍历（不涉敏感数据）；无法证明的参数配置风险；内部员工弱口令；应用缺陷导致的远程拒绝服务（不含 DDOS/CC）。

## 忽略/不收项
- 不能复现的漏洞；无法利用的漏洞（仅能打自己的 Self-XSS、内网 IP/域名泄露、无意义的源码泄露）。
- 风险过低或难利用：用户名枚举、SPF 邮件伪造、无意义的 API Key 泄露。
- 无关安全的产品 BUG：功能缺陷、体验/设计问题、静态文件目录遍历、应用兼容性等。
- 非银联授权范围内或非银联安全漏洞（页面嵌入的第三方应用系统、外包厂商测试系统等）。
- 非安全漏洞导致的内容安全风险、业务隐私合规相关问题。

## 测试红线
- 禁止在任何公共渠道或自媒体（微博、论坛、社区、QQ 群、公众号、朋友圈等）公开漏洞细节。
- 严禁自动化漏扫或辅助工具高频扫描：被安全监控比对发现，有权直接终止其在 USRC 的全部权利并依法追责。
- 社工获取访问权限的，必须证明所获信息可直接利用发现后续风险，否则按低危第 13 条/中危第 8 条处理。
- 测试以证明漏洞存在可利用（POC）为止，严禁拖库、内网渗透等非法操作；SSRF 不得对内网服务扫描。
- 谴责以漏洞测试为借口的破坏、损害用户利益、盗取隐私/资金、恶意传播漏洞、营销恐吓等行为；须遵守网安法/数安法/个保法。

## 报告要求
- 漏洞必须可通过 POC 触发并产生实质性影响；建议 POC 用 python、C 编写。
- 同一漏洞只认定首个提交并证明真实存在的报告者；同一应用系统同一类型漏洞按正常等级只收前三个，后续不再认领（新版新增）。
- 通用漏洞（Struts2、Java 反序列化等）披露第 1 周内仅认定首次提交有效 POC 且证明银联应用受影响者；1 周后未修复的按首报规则处理。

## 处理流程与时限
- 五阶段：注册（绑云闪付）→提交→审核→处理→关闭。
- 时限：提交后 3 个工作日内开始评估，开始评估起 4 个工作日内完成审核；必要时联系白帽子补充信息。
- 申诉：收到结果一周内提出；按白帽子利益优先处理，必要时引入内部仲裁委员会（五位技术专家）共同裁定（旧版为引入第三方平台人士）。
- 金币兑换：每月第 1-5 个工作日发起申请，一般每月 15 日前发放；须先用云闪付 App 绑卡并在账号管理设置兑换主卡号。
- 联系邮箱：usrc@unionpay.com。

## 易错点
- 现行版本为 2026-01-16 新版（id=972），与 2017 旧版差异大：新增"同系统同类型只收前 3 个"、忽略项扩充（用户名枚举/SPF 伪造/内网 IP/无意义源码与 API Key）、SSRF 分级（回显=高危、无回显=中危）、远程 DoS 降为低危、争议改为内部仲裁委员会；旧版资料已过时勿再引用。
- 新版未写严重漏洞额外奖励具体金额，收益预期勿按旧版"1 万-2 万"硬套，以当期活动/评定为准；2026 年平台高频发布活动公告（夏日探宝营、端午破浪、暖春狂欢等），实际收益常由活动规则决定。
- 不绑云闪付卡无法兑换金币；高频扫描=直接封禁全部权利；通用组件漏洞有 1 周首报窗口期。
