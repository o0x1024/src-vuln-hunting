# Soul SoulSRC（Soul安全应急响应中心）报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://security.soulapp.cn/index.php?m=&c=page&a=view&id=6（查阅于 2026-10-12）；规则版本/更新: 《Soul安全应急响应中心漏洞处理和评分标准 V2.0_试行》，发布单位：上海任意门科技有限公司（Soul），发布日期 2026/07/21；修订记录 V1.0（2021-08-11）→ V2.0
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。
## 收录范围
- 覆盖：Soul Web 产品、Soul App（Android/iOS）、官方域名及相关资产、云基础设施、开放平台及 API，以及 SoulSRC 认可纳入范围的其它业务。
- 类型：Web 漏洞、App 漏洞、API 漏洞、云安全漏洞、身份认证漏洞、业务逻辑漏洞、安全情报、通用软件漏洞、第三方组件漏洞。
- 产品分级：核心产品（Soul App 核心功能、账号中心、支付及钱包、核心 API、核心业务后台）；普通产品（*.soulapp.cn、Web 业务系统、开放平台与 Open API、内部系统、数据分析平台、云资源、数据库管理平台、业务支撑系统）；边缘产品（活动页、静态站点、历史业务、小程序等）。
- 第三方合作资产按"是否承载 Soul 品牌+是否处理 Soul 用户数据"判定：承载品牌且处理用户数据→受理但原则上不高于对应等级边缘产品标准；可访问但不涉用户数据→受理并致谢、象征性奖励；纯第三方→不收，建议提交对应厂商 SRC。
## 等级与奖励
- 1 个安全币 = 10 元人民币；现金奖励可按等额折算京东卡。奖励表（人民币元，边缘/普通/核心）：
  | 等级 | 边缘产品 | 普通产品 | 核心产品 |
  | --- | --- | --- | --- |
  | 低危 | 20~50 | 50~80 | 80~200 |
  | 中危 | 60~100 | 180~300 | 300~500 |
  | 高危 | 480~640 | 600~800 | 1800~2400 |
  | 严重 | 900~1000 | 2700~3000 | 6000~10000 |
- 高质量报告奖：完整利用链、根因分析、完整 HTTP 请求、Payload、PoC/Exploit、修复建议、自动化复现脚本等可额外获奖。
- 严重漏洞专项奖：核心/重点业务高质量严重漏洞按季度额外评审，核心产品严重漏洞税后上限 5000 元。
- 季度奖：当季高危及以上漏洞 ≥3 且奖励排名前三：5000/3000/1000 元现金；无人达标则空缺。
- 年度特别奖励：现金、荣誉证书、定制礼品、年度安全专家称号。
- 安全情报奖励（独立于漏洞，整体从低、按治理价值弹性发放，以京东卡发放）：严重（规模化黑灰产团伙/重大资金损失/大规模数据倒卖）1000~2000 元；高危（成链条养号、引流、盗号、群控）300~1000 元；中危（新型手法样本、单点账号、风险预警）50~300 元。情报类型：社交诈骗（杀猪盘、冒充官方、刷单、虚假投资、AI 换脸）、违规引流、批量养号/盗号、群控刷量、数据爬取与倒卖、跑分洗钱等。
## 忽略/不收项
- 不予奖励：无安全影响（样式/UI/功能缺陷、普通报错日志）；无法验证（无法复现、无证明材料、推测性、无法稳定利用）；重复漏洞（相同根因/组件/利用链，仅奖首位有效报告者）；仅扫描器输出（Nuclei/Nessus/AWVS/Burp/AppScan/Acunetix/OpenVAS 等，需结合人工验证+完整利用链才可重评）。
- "信息"级（不计奖励）：页面样式/乱码/功能缺陷、普通报错、Self-XSS、无危害扫描结果、测试页面、推测性漏洞；无敏感数据的组件暴露、非敏感 Deeplink；仅 DNSLog、无法触达内网的 SSRF；确无数据且无可利用点的 Redis/ZooKeeper/Memcached 未授权访问。
- 已公开漏洞原则上不予奖励；与 Soul 无关的第三方系统、无法验证、无实际安全影响、产品功能缺陷（Bug）、UI/样式/兼容性问题不在奖励范围。
## 测试红线
- 负责任披露+安全港：提交后、经 Soul 书面授权前，不得向第三方泄露细节、不得发布/传播 PoC/Exploit、不得下载留存传播用户数据、不得影响业务或篡改删除数据、不得非法牟利。
- 测试最小化：仅以证明漏洞存在为限，验证成功立即停止；触及敏感数据立即停止并第一时间报告；禁止 DoS/DDoS、植入后门、维持访问权限。
- 禁止行为（取消资格并可能追责）：获取用户隐私数据、修改业务数据、长时间维持权限、留置 WebShell、拒绝服务攻击、恶意传播漏洞、未授权公开漏洞、利用漏洞谋利、威胁勒索企业。
- 纯第三方资产的测试可能不受安全港保护，测试前先确认资产归属。
## 报告要求
- 提交时提供：漏洞类型与受影响资产（域名/接口/App 版本）、完整复现步骤与 HTTP 请求包、PoC/Exploit 或一键复现脚本、复现截图或视频、影响说明与修复建议；客户端漏洞注明关键代码与系统/版本信息。材料不完整直接影响评级与审核时效。
- 通用型漏洞（同一 JS/框架/泛解析导致的多个 XSS 等）计为一个。
## 处理流程与时限
- 流程：接收 → 审核 → 复现 → 风险评估 → 修复跟踪 → 关闭，专人跟进。
- 时效：确认收到 1 个工作日内；给出结论并评级（已确认/已忽略）3 个工作日内；复查由报告者发起，必要时沟通确认。
- 修复时效：严重/高危 72 小时内；中危 3 个工作日内；低危 7 个工作日内；客户端按版本发布限制。修复失败/不完整/可绕过可重新提交，确认后按新漏洞处理。
- 每自然月第一周发布上月处理公告并致谢。
- 争议处理：邮件 sec@soulapp.cn 或平台微信 kym9356 申请复核；报告者合法利益优先；可共同邀请独立安全专家裁定，过程留痕。
## 易错点
- 1 安全币=10 元（不是 1 元），看奖励表时别按"币"误读金额；核心产品严重漏洞 6000-10000 元是本清单中公开金额最高的档位之一。
- 纯扫描器输出（Nuclei/Burp 等）明确不奖励，必须人工验证+完整利用链。
- 通用型漏洞合并计一个，泛解析/同框架批量 XSS 别拆多报。
- 修复时效承诺很紧（严重/高危 72 小时），复查修复失败按新漏洞计——修复验证窗口值得跟进。
- 情报奖励独立且整体偏低（50-2000 元），社交诈骗/养号类线索按情报线提交，别混进漏洞线。
- 联系渠道：sec@soulapp.cn、平台微信 kym9356；公开细节需修复完成+书面授权，且不得展示产品名称/用户信息。
