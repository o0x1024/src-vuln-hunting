# 知乎 知乎安全响应中心 报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://www.zhihu.com/term/info-sec（查阅于 2026-10-12）；规则版本/更新: 未标注（页面无版本号/日期）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。
## 收录范围
- 适用于知乎所有开放在互联网的应用及系统，包括但不限于知乎、盐言故事、知学堂等（官方《安全报告处置规则》第二章）。
- 同时接收业务安全情报：批量恶意注册、有组织薅羊毛、内部信息/用户数据泄露（网盘、GitHub 等第三方泄露）、支付类作弊（如苹果 iOS 代退款）、会员类作弊（如低价充值盐选会员）。
- 注：security.zhihu.com 与 src.zhihu.com 本次 DNS 解析失败，现行规则以 zhihu.com/term/info-sec 为准。
## 等级与奖励
- 漏洞/情报均分：严重、高危、中危、低危（低危酌情奖励）。奖励为现金（元）：
  | 等级 | 核心系统 | 非核心系统 |
  | --- | --- | --- |
  | 严重 | 3000-5000 | 2000-4000 |
  | 高危 | 1000-3000 | 500-1500 |
  | 中危 | 200-500 | 50-100 |
  | 低危 | 酌情 | 酌情 |
- 严重漏洞示例：RCE/GetShell、核心敏感数据 SQL 注入、任意用户密码修改、核心支付流程漏洞、域控/堡垒机等管控系统被控、海量多维敏感数据泄露。
- 高危示例：一般系统前台 SQL 注入、任意账号登录/重置、支付绕过、任意文件读取、最新版 App RCE、可进内网无限制获取核心区数据的 SSRF、核心系统存储型 XSS（可取任意/管理员 Cookie）。
- 中危示例：有限越权/信息泄露、需交互的存储 XSS/JSON Hijacking/重要 CSRF/CORS、有回显 SSRF（内网存活/端口）、二次验证绕过、一般系统敏感未授权访问。
- 情报分级：严重（如百万级用户敏感数据泄露）、高危（有组织薅羊毛传播广损失大）、中危（规则缺陷被批量刷券）、低危（破解版 APK）。
## 忽略/不收项
- 无效情报：虚假捏造/人为制造；仅给 QQ 群号/刷量站点/黑产广告但无证据明细；单个或少量用户的非规则性刷量；已发现或失效情报；无攻击路径与手法说明；仅说"外部有刷单服务"无可查验证据（需刷手真实订单、账号、手法）；单个电子面单截图（后台截图无准确时间亦无效）。
- 数据泄露类情报硬门槛：至少 20 条有效样本，含可追溯身份字段（知乎主页链接、手机号、邮箱、身份证号等）；售卖线索需卖家联系方式、完整聊天记录和收款方式，否则忽略。
- 降级：情报完整性较低；有刷量绕过但风控算法可覆盖/兜底。
## 测试红线
- 知乎反对一切以安全测试为借口，利用漏洞损害用户利益、影响业务运作、盗取用户数据等违法行为。
- 未经授权任何人不得对外披露漏洞/情报细节（包括在第三方平台存储、传播或讨论详情），或利用漏洞非法获利（第一章第 4 条）。
- 每份报告由专人跟进、分析、处理并及时反馈。
## 报告要求
- 情报必须提供：攻击路径（必须）、攻击方法（必须）、威胁来源、风险类型、发生时间、损失预估；技术分析越详细越影响评级。
- 情报完整性是评分重要依据；关键线索缺失直接影响收录。
## 处理流程与时限
- 官方规则未列明具体时限；承诺每份报告指定专人跟进、分析和处理，并及时反馈。
- 举报方式：SecurityResponseCenter@zhihu.com（第六章）。
## 易错点
- 数据泄露情报 20 条样本+可追溯字段是硬门槛，缺一条即忽略；只给"网盘链接"不给样本必被拒。
- 奖励分核心/非核心系统两档，同一漏洞定级相同但金额差近一倍，报告里应论证系统重要性。
- 规则页面无版本日期，引用时注明"查阅于 2026-10-12"并核对官方原文是否更新。
- security.zhihu.com 域名解析失败不代表项目关闭，官方规则托管在 zhihu.com/term/info-sec。
