# vivo vivo安全应急响应中心（vivoSRC） 报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://security.vivo.com.cn/assets/vivoSRC_process_1_4.pdf（查阅于 2026-10-12）；规则版本/更新: 漏洞处理流程 v1.4（2019-12-24；v1.0 2019-03-20 首发，v1.1 2019-04-09 更新定级标准，v1.2 2019-05-18，v1.3 2019-07-24 更新奖励规则，v1.4 新增移动端定级标准）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- vivo 自有业务：vivo 官网、vivo 商城、vivo 应用商店、vivo 游戏中心、vivo 支付、vivo 云服务、vivo 会员、vivo 社区、vivo 开放者平台、vivo 营销平台、FunTouch OS、vivo 浏览器、vivo 钱包、vivo 视频、AI 服务引擎、Jovi 语言、负一屏、i 管家、快应用平台等。
- 第三方业务（代理商系统、供应商系统等）单独归类处理。

## 等级与奖励
- 积分制：1 积分 = 1 元，积分可兑换现金或其他奖品；累计积分决定 vivoSRC 荣誉等级与排名，年度突出贡献者有专项奖励。
- 评定维度：漏洞利用场景、利用难度、危害程度、报告描述清晰度，并结合业务重要性与数据重要性。
- WEB 漏洞"严重"示例：直接获取系统权限（服务端/客户端，任意代码执行、任意命令执行、上传 Webshell）；严重逻辑设计缺陷（任意账号登录、任意账号密码修改、任意账号资金消费、支付交易严重问题）；严重信息泄露（核心 DB 的 SQL 注入等）。
- v1.4 新增移动端漏洞定级标准。

## 忽略/不收项
- 边缘应用、无敏感信息、不影响业务的漏洞在定级和分值上作降级评定。
- 未产生实际危害的才给予奖励（无危害不给奖励）。

## 测试红线
- 禁止以漏洞测试、证明危害为借口：损害用户利益、深入系统获取数据、影响业务正常运作、修复前公开、盗取用户数据。
- 侵犯 vivo 知识产权、以公开方式造谣抹黑 vivo 形象的：不予奖励，vivoSRC 保留追究法律责任的权利。
- 支持负责任的漏洞披露；谴责利用漏洞盗取用户资料、入侵业务系统、修改/窃取系统资料等行为。

## 报告要求
- 对每位恪守白帽子精神、保护用户利益的报告者给予感谢和回馈；报告描述需清晰（描述清晰度影响评分）。

## 处理流程与时限
- 对每份反馈及时跟进、分析、处理并给予答复。
- 奖励结算：每月第一周对上月所有兑换进行结算，到账一般不超过 20 个工作日（法定节假日等可能延期）。
- 争议解决：对处理流程、评定、评分有异议，通过 security@vivo.com 或微信公众号"vivo 安全应急响应中心"反馈。

## 易错点
- 规则 PDF 版本为 2019 年 v1.4，平台现行细则可能已更新，提交前以平台内最新公告为准。
- 描述清晰度直接参与评分，POC/危害证明写不清会被降分。
- 边缘业务、无敏感数据的漏洞会被降级，不要按主站标准预期分值。
