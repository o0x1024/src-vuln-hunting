# 马蜂窝 马蜂窝安全应急响应中心（MFSRC）报告处理规则摘要
- 状态: official；置信度: 中
- 来源: https://security.mafengwo.cn/notice/detail/13（查阅于 2026-10-12）；规则版本/更新: 马蜂SRC漏洞评分标准及奖励规则v1.0，生效日期 2019-07-15（另有《马蜂窝SRC漏洞提交及处理流程》id=20）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 马蜂窝名下所有产品及业务，域名包括但不限于 *.mafengwo.cn。
- 只接收马蜂窝移动客户端产品的漏洞，不接收 Android/iOS 系统自身漏洞；客户端漏洞以当前时间最新客户端为准（同一漏洞不可在不同版本间重复提交）。

## 等级与奖励
- 奖励贡献值=漏洞风险等级×业务重要性（倍数奖励默认为 1）；贡献值可在积分商场兑换现金奖励，可累积、仅供个人使用。
- 风险等级分值段（v1.0）：高危 11-15 / 中危 6-10 / 低危 1-5 / 忽略（未见“严重”档）。
- 高危（11-15）：直接获取操作系统权限（RCE/命令执行/WebShell 可执行/SQL 注入提权）、直接获取移动客户端权限、高风险信息泄露（DB SQL 注入泄露隐私、服务器敏感日志下载）、严重逻辑漏洞（任意账号登录/改密/资金消费、批量改密）、严重敏感信息泄露（资金/身份/订单核心 DB、绕过认证进管理后台、大量核心用户身份/订单/银行卡接口泄露）。
- 中危（6-10）：需交互获取用户身份信息的存储型 XSS、直接导致业务重要接口拒绝服务等。
- 低危（1-5）：轻微信息泄露（路径/git/SVN、客户端本地 SQLi 仅库名字段名、日志、配置）、URL 跳转、运维配置不当、组件权限、普通逻辑缺陷（短信/邮件验证码绕过）、客户端明文存密码、路径遍历。

## 忽略/不收项
- 不涉及安全问题的 BUG（功能缺陷、乱码、样式、静态目录遍历、兼容性）。
- 无敏感信息的信息泄露（无意义源码、内网 IP/域名/账号密码、路径信息、无敏感 logcat）。
- 不能重现的漏洞（纯属猜测、未验证、无实际危害证明的扫描器结果）。
- 其他平台提交过的同一漏洞（非首次提交不予审核）；网上已公开的漏洞不计分。

## 测试红线
- 禁止利用漏洞进行非法操作，包括但不限于拖库、进入内网——情节严重取消该用户所有贡献值并保留法律行动权利。
- 严禁白帽子在多平台提交相同漏洞刷奖励，一经发现严肃处理；恶意提交者封号。
- 坚决抵制利用漏洞损害用户利益、影响业务运作、修复前公开、盗取用户数据等恶意行为，保留法律行动权利。

## 报告要求
- 报告应详细规范：漏洞详情、原理、利用方式、修复建议可酌情加分；必须证明存在且可利用，未提供 POC/exploit 或无详细分析将直接影响评定。
- 同一漏洞修复前多人提交，以最先提交且清晰表述/可重现者为唯一受奖励者。

## 处理流程与时限
- 平台在线提交（Nuxt SPA，公告页 /notice、详情 /notice/detail/{id}）；具体审核时限未在 v1.0 中标注。
- 争议：邮件 mfsrc@mafengwo.com，注明漏洞标题、提交人、提交时间、联系方式（电话/微信）、申诉原因；按报告者利益优先处理。

## 易错点
- 现行公开规则仍是 2019 年 v1.0，等级分值段（11-15/6-10/1-5）与主流“严重/高/中/低”叫法不同，定级预判时勿套用其他厂标准。
- 官网为 Nuxt SPA，规则正文嵌在 __NUXT__ JSON 里，直接看 HTML 源码看不到正文。
- 多平台重复提交在 MFSRC 是“严肃处理/封号”级红线，不只是不计分。
