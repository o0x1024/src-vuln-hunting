# 小米 MiSRC 规则配置

仅当项目实际采用小米规则时读取。核对来源：[官方 V11.0](https://sec.xiaomi.com/#/notice/detail/244)，发布于 2026-09-11，查阅于 2026-09-17。已读取与本次扩展相关的网页文字和表格；未核读图片内规则、视频或附件。本文件为决策摘要，不是完整规则或永久有效的授权。后续运行复用有效项目快照；日期、产品、活动或条款适用性变化时核对原文。

## 适用与分流

先记录 project、policy_version、checked_at、section、适用产品/版本、实际攻击前提和证据引用。规则登记到现有运行说明，不新增宿主 API 字段。规则不清只阻塞相关定级、收录或奖励判断，不能抹去技术事实。

| 缺陷所在边界 | 规则入口 | 易错点 |
|---|---|---|
| Web/API、账号或服务端授权 | §4.2 | 在手机或设备上触发不自动变成移动/硬件漏洞 |
| 大模型服务、官方集成工具和 Agent | §4.2.4 | 实际信息安全影响优先于提示词名称 |
| App、HyperOS、终端权限 | §4.3 | 业务级别、系统/补丁、远程/近场/本地/物理前提分别核对 |
| 设备协议、固件、智能硬件 | §4.4 | 账号、风控、App 问题转相应 Web/移动规则；生态链归属单独核对 |
| 整车、核心零部件、车端组件 | §4.5 | 整车影响不能从单组件权限直接推导 |
| 面向大量用户的桌面客户端及其组件 | §4.6 | 内部/开发工具、第三方组件与业务无直接影响等不自动属于该奖励范围 |

客户端、云端、模型、硬件可以形成一条链，按实际根因和平台合并规则处理，不重复计奖。§2.3 涉及首报、内部已知、同根因、多参数与相互依赖链；公开通用问题的锁定期须按原条款核对，不能借用其他平台时限。内部已知库不可见时记录未知，不以未知阻止证据齐备的报告交付。第三方/生态链关联、商城售卖与服务端测试授权分别判断。

## 大模型：§4.2.4

- 区分云端模型/训练数据受损、服务权限控制、代理/插件引发的越权，以及普通响应内容。核心模型/数据/服务的严重影响、较有限的敏感数据或工具权限影响、服务可用性影响各有不同档位；不能仅凭“提示注入”定级。
- 纯越狱、非隐私 PromptLeak、内容违规、模型模拟终端、预期沙箱运行不自动收录；出现可直接验证的数据泄露、越权读取他人会话或隔离突破时重新按实际影响评估。受控账号和私有标记可证明边界，无需访问真实用户数据。
- 个人用户发布的 UGC 智能体/插件导致自身泄露有专门排除项。不能把“攻击输入来自用户文档”误判为 UGC 插件：官方工具执行器或平台授权缺陷仍需独立归因；归属不明记 rule_review。
- 中危可用性条款不授予资源耗尽许可；只判读已有事故或获准隔离验证材料。正常 sandbox 能力与宿主/内网边界分开；专用 SSRF 验证方式必须核对当前许可，DNS 事件不能补成任意内网读取。

## 移动端：§4.3

核心范围涉及最新版 HyperOS 预装米系 App、HyperOS 自身及小米汽车 App，合作定制应用与单发 App 等另有分类。三方组件、原生 Android 问题、仅旧机型/版本、网络劫持前提不能直接套用核心档位。明确客户端与服务端交互缺陷的归属。

- §4.3.1：公开问题、7 天关联排查期、3 个月修复期和三方组件规则各有独立条件，记录公开时间、厂商已知证据、是否已有修复版本；不能把“CVE 不满 3 个月”当统一拒收规则。原文修复期适用条件不清时交 rule_review。
- §4.3.2：报告需机型、系统版本、安全补丁、App 包名/最新版版本、调用链与截图、可复现 PoC 或 Exp 源码与 APK；多交互/适合演示的场景补视频，高危/严重必须详细视频。非 App 漏洞按原文适用例外处理。缺附件不否定已证明的漏洞，但尚不 ready。
- §4.3.3：仅缺 pinning、混淆、二进制防护、可重打包、allowBackup、包内密钥等配置现象有排除项；泄露的性质、读者权限与额外真实影响必须另查。仅 root/越狱后运行时修改的结果，不证明普通攻击者具备该能力。不能因为用了 Frida 观察就抹去已在正常环境独立复现的漏洞。
- 区分可恢复的本地 App 崩溃、持续性设备不可用、远程影响和系统权限；通用“本地 DoS 默认不投入”不能覆盖当前明确收录的例外，也不授予实际破坏设备许可。
- §4.3.5：远程、近场、本地、物理接触及普通/特权/受限进程有平台定义。记录通信协议漏洞还是应用消息、是否需安装 App、距离、接触与交互，避免把近场协议链按普通 Web 远程链算。

## 智能硬件：§4.4

评级同时依赖设备业务价值、网络可达性、交互/认证、真实执行能力与影响。互联网无交互控制、局域网无交互执行、局域网有交互/授权执行不能混用同一档位。

- 报告必需设备名、固件、调用链/截图、可复现 PoC 或 Exp 源码，复杂交互补视频；AI 静态审计结果须人工验证后提交。Agent 自评不能冒充人工复核。
- 固件明文、下载使用 HTTP、存在设备标识、调试接口开放但未获 shell 等不能单独计可提交成果。BLE 通道占用、本地自有设备 DoS、授权后 DoS/XSS、侧信道等有具体排除条款，不能只按通用漏洞名称判断。
- EOL 设备有“严重漏洞除外”的条件；EOL 不是抹去所有候选的快捷标签。生态链与小米信息相关性影响受理，生态链问题不计额外奖励；固件发布周期长也不能据此推断一定重复。

## PC 与汽车：§4.6 / §4.5

- PC 当前特别排除 Electron 配置、Preload、JS Bridge、Native API 暴露不规范导致的该类问题；即使存在技术影响，也须保留技术结论并单列小米奖励排除，不能泛化到所有平台。独立服务端根因不得因客户端使用 Electron 被自动排除。
- PC 需名称/版本、OS、调用链/截图、可复现证明、触发条件，复杂步骤建议视频；AI 静态/扫描线索需人工分析验证。已具本地执行权限后的同权限执行、部分 DLL/安装过程劫持、低影响配置、重打包和仅自身 MITM 等有专门排除；“本地”不等于所有权限提升都无漏洞。
- 汽车报告绑定整车型号或零部件软硬件版本、调用链、实际整车影响、PoC/源码与必要视频。整车/核心零部件/模块/单功能分级；单设备结果不证明任意车或整车接管。已知中继、泄露诊断工具、无可利用影响的故障注入等按具体条款处理。

## 奖励资格与报告交付

在 hypothesis_status、impact_status、submission_assessment、platform_status 之外，按需记录本地 reward_eligibility（eligible / ineligible / unknown / not_assessed）、reward_basis、missing_requirements；该字段是候选资格判断，非平台决定，不添加到未支持的 API。

| 机制 | 应核对的条件 |
|---|---|
| 基础奖励 | 业务分层、已证明等级、适用版本及条款；大模型严重/高危/中危参考贡献币区间为 600–1500 / 300–500 / 50–200，其余域按对应表查，不沿用 Web 数额 |
| 报告附加与特殊贡献 | §3.2/3.3，报告质量/日志/视频、平台实际确认；不是自动附加金额 |
| 手机守护计划 | §4.3.4，限定最新数字旗舰、官方最新稳定 ROM、默认/正常设置、浏览器版本、未公开 0day、特殊权限限制、标题与附件；重复场景、交互和影响折算分别查原表 |
| 活动与设备申请 | 活动 ID、状态、日期、报名/设备资格、叠加限制；专项资格不成立不自动取消普通项目测试许可或基础报告资格 |

[IoT 活动入口](https://sec.xiaomi.com/#/IoT) 在核对日的介绍仍含“无限期”历史文案，但对应 Bundle 卡片为已结束；不得承诺历史百万奖励仍有效，也不能从此推出全部 IoT 普通收录停止。具体活动冲突只挂起专项资格判断。

报告附 rule_ref（版本+条款）、产品层、已证明前提、排除项检查、附件/人工验证缺口与奖励依据。可提交不等于已获奖；缺专项资格与缺普通提交材料要分开。验证动作仍遵守 [执行边界](../../SKILL.md)；不批量提取训练数据、不刷坏设备、不制造真实资损来满足奖励门槛。
