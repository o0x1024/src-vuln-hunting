# 途牛 途牛安全应急响应中心（TNSRC）报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://sec.tuniu.com/notice/14（查阅于 2026-10-12）；规则版本/更新: 漏洞评分标准和处理流程更新公告，发布 2026-09-23（自新标准实施日起旧版文档立即失效）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 业务三分类（2026-09-23 新标准）：
  - 核心业务：核心交易入口（途牛 App/PC/移动网站/小程序核心交易功能）、打包旅游业务（跟团游/自由行/自驾游/定制游/邮轮的报价库存预订签约出团履约退改）、账户与身份体系（注册登录统一认证找回实名的会员账户）、订单与交易体系（下单/订单管理/退款/旅游合同/电子凭证）、资金及权益体系（支付退款结算余额储值提现、优惠券积分礼品卡）、核心数据系统（账号凭证/订单/支付/出行人身份资料/联系方式）、核心供应链系统（价格库存订单确认采购出团结算）。
  - 主要业务：单项旅游资源（酒店机票火车票门票签证租车接送机保险）、企业及渠道业务、一般供应商及商户系统、客服系统、内容与运营业务（攻略点评推荐搜索广告直播营销）、内部业务支撑系统。
  - 边缘业务：企业及品牌展示、活动及静态页面、低影响辅助功能、测试及历史系统、途牛 SRC 及非主营平台（原则上按边缘评定）。

## 等级与奖励
- 等级：严重/高/中/低/无 五级；贡献值用于荣誉，安全币用于礼品兑换，两表数值相同：
  - 核心业务：严重 220-360 / 高 120-180 / 中 15-45 / 低 2-5
  - 主要业务：严重 70-110 / 高 36-60 / 中 6-18 / 低 1-2
  - 边缘业务：严重 20-32 / 高 10-16 / 中 1-4 / 低 0
- 严重级示例：直接获取系统权限（服务端/客户端）、核心业务数据库、RCE、WebShell、缓冲区溢出；严重敏感信息泄露（内部核心数据、核心源码、接口导致大量核心用户身份/订单/银行卡信息泄露）。
- 触发条件苛刻（如仅特定浏览器可触发的 XSS）可跨等级调整贡献值。

## 忽略/不收项
- 不属于安全漏洞的报告状态变更为“未通过”（无危害等级细则中含“无”级）。
- 修复前被公开的漏洞不计分；网上已公开的漏洞不计贡献值。

## 测试红线
- 反对以漏洞测试为借口进行破坏、损害用户利益的黑客行为，包括利用漏洞盗取用户隐私/虚拟财产、入侵系统、篡改敏感数据——不计贡献值并保留法律行动权利。
- 正常测试边界：不影响被测系统正常运行、不危害系统/平台用户隐私及数据安全。

## 报告要求
- 登录 TNSRC 平台在线提交；同一漏洞首位报告者计贡献值；同一份报告多个漏洞只按危害最高者计分。

## 处理流程与时限
- 流程：提交（状态“未处理”）→审核（专员工作日当天或次日；非漏洞→“未通过”，确认→“待修复”并按标准给贡献值和安全币）→处理修复（有进展第一时间反馈）→内部复查→联系白帽复查→“已修复”。
- 奖励发放：积分兑换，多漏洞积分可累加，未使用积分不过期；资料不全顺延至下一批次寄出。
- 争议：邮件 sec@tuniu.com，标题用【途牛漏洞处理异议】，专人优先处理；最终解释权归 TNSRC。

## 易错点
- 2026-09-23 新标准把业务重新分为核心/主要/边缘三档并更新了分值表，旧表（2018/2017 版）数值已失效。
- 边缘业务低危=0 分，SRC 平台自身漏洞按边缘评定，收益极低。
- 同一漏洞源多个利用点（同一 JS/发布系统/框架/泛域名）按最高级别只计一次。
