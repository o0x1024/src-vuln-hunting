# 从源码、路由与补丁建立假设

适用：用户已提供或允许读取的源码、发布包、依赖清单、补丁与实际调用栈。没有代码时继续黑盒分支，不从网上下载同名项目就当作部署代码。

## 最小模型

保存代码提交/包哈希、实际依赖版本、配置、部署关联和解析限制。按入口 → 中间件/过滤器 → 控制器/服务 → 数据或执行 sink 建立一条可追溯路径；每个跳转引用文件/符号/调用位置。模型猜出的调用关系标 unknown。

| 观察 | 下一步判断 | 反例与限制 |
|---|---|---|
| 控制器很多或使用插件路由 | 从实际路由注册、继承、注解和重写逻辑生成候选，再核对方法及身份 | 类名推导的路径不一定暴露；候选列表不授权批量请求 |
| 顶层对象有鉴权，引用了子任务/子资源 | 检查创建、更新、执行时的子对象归属与授权上下文 | 验证 ID 存在不等于验证有权使用；拒绝回显也不证明后台未执行 |
| 共享令牌/头/查询参数混用 | 跟踪来源优先级、空值、查询无结果及失败默认返回 | 有多个输入位置不自动构成绕过；正常公开分享是反例 |
| ORM 或查询构造器 | 核对具体调用、重载、参数绑定与原始表达式路径 | 一个 API 参数化不能证明所有 select/order/raw 分支安全；字符串可控也不必然可注入 |
| 修复增加了一处判断 | 对比修复前后的根因、同类入口和运行时调用；保存补丁来源 | 看到补丁文件不证明实际加载；旧版本标签不证明线上仍可利用 |
| 静态分析工具命中公共工具类 | 核对调用者、污点约束、鉴权与实际模块覆盖，再选择代表路径 | 数据库建立成功不证明构建/提取完整；工具报错和遗漏模块必须留痕 |

## Agent 与工具分工

Agent 擅长整理业务约束、源码关系与补丁差异。符号引用、AST/调用图、反编译和构建日志由工具提供；不能凭相似变量名补造数据流。先阅读已有输出，工具缺失时用可复核的局部检索降级，保留未分析模块。

审计范围大时采用双向收敛：从已确认外部入口向前追输入转换与约束，同时从查询、表达式、反序列化或文件消费者向后追真实调用者；两条路径在具体符号和参数处相接才形成可达假设。危险函数名、工具命中、示例代码或测试分支本身不证明部署暴露；保存未接上的边和被净化/鉴权阻断的分支。

动态验证优先使用两个受控身份、无害子任务或受控记录，分别观察入口拒绝与后台真实效果。代码证据只能支持其配置与可达条件，不能生成未执行的 HTTP 证据。继续使用 [验证门槛](verification.md) 和 [企业影响](impact-and-acceptance.md)。

## 历史研究的适用性

归档的 Yii、JimuReport、xxl-job 与 Next.js 研究用于提出上述检查点，具体版本/重载/配置必须回到目标核对。Next.js [维护者公告](https://github.com/vercel/next.js/security/advisories/GHSA-f82v-jwr5-mffw) 对中间件鉴权及托管部署有明确条件，不能从转载的严重度或 DoS 描述推断本次影响。

对应案例及纠偏见 [K05–K08、K16](research/crawl-xz-patterns.md)。若从修复推断更大影响，逐项列出尚未证明的连接；不为追求 RCE 添加依赖、写入持久化或扩大目标权限。

## 局部缓解与历史材料

一个已知路径返回404只证明该路径、入口、身份和时点的响应，不能单独证明整个CVE缓解已生效。核对实际版本、修复/配置是否加载、规范化发生层及同一根因的已知入口，用正常业务路径作服务可达对照；404也可能来自代理或路由。优先部署和补丁证据，不为证明全覆盖执行来源PoC或猜测大量变形。

暴露.git/.svn的某个元数据或历史文件不等于完整现行代码库、有效生产凭据或所有版本可达。限定获准材料，保留对象/修订/提交与部署关系；不要自动还原执行工作树、运行钩子或批量拉取历史秘密。Gitlab公开snippets也可能是正常发布，须先判断材料的预期读者。

## HTTP方法与服务器文件的区别

DELETE是HTTP资源操作，不是对URL路径对应文件执行本地删除。[RFC9110 §9.3.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.3.5)区分资源映射及由实现决定的底层存储效果（2026-10-09核对）。来源只有“DELETE /login会删登录面板”的命令示意，没有响应、路由实现和前后状态，不能补毁站/RCE或通用删除能力。

先静态核对已获准方法路由、主体/对象授权、处理器与实际状态效果；未知方法返回200/页面消失也可能是默认页、缓存或错误。需要状态变化的实验只能在明确获准可恢复测试对象中进行，并记录清理边界，不对登录页、系统配置或真实业务对象发送删除来验证一句建议。

## Git标记、成员可读与源码恢复

/.git/HEAD或refs名称仅候选；301/302常为登录/统一跳转，200也可能是应用默认页。先核对获准已有原件的类型与实际内容、读者和部署关系，再区分仓库标记可读、单个成员/对象可读、具备恢复某版本的材料与该版本实际秘密。

截图列出COMMIT_EDITMSG、hooks.sample、index、refs/wip等200，不能证明全部成员真实可读或完整源码已恢复；某个匹配器打印哈希/medium也不补这些条件。历史版本内容与当前部署分别保留，必要证据最小化；不按清单下载整个仓库/历史对象、运行hooks或使用恢复的真实凭据。

## PoC编码、分支与执行来源审阅

CVE名称、GitHub位置和base64编码都不能使脚本可信。先静态标出输入、解码、下载来源、解释器调用、权限条件与本地/远端副作用；截图中的远端下载后交给shell、写SSH授权文件和编码地址向外发送，分别是执行、持久权限变更与外联行为，不当成必要验证准备。

某个非root分支提前退出，不证明其他权限分支无害；同名工具/仓库历史版本也不绑定现在的代码。保留制品哈希及可见范围，未知外链保留缺口，不因自称检测函数或uname就运行整个脚本。本地静态阅读不访问图中下载站、不复制公钥到用户配置、不解码后执行或联网，也不把来源警告倒推每个同CVE制品都有同样行为。

## JAR提取、筛选与制品保全

JAR解包、筛除org/com/net/de目录、反编译剩余class，得到的是选择性视图；按包名前缀排除会漏应用代码，不能称全部相关类已审。截图还包含解包后删除原archive和可选删除class，均不是这项提炼的执行指令。

对获准制品先登记来源/版本/哈希与成员映射，在隔离目录保留原件，限制成员数、解包大小和路径。明确实际反编译成功、失败、排除和无法恢复部分；混淆/依赖/原生代码支线各留缺口。恶意样本分析不要求加载类/运行JAR或安装未知反编译器，未知gist只记未读，不自动执行xargs或删除制品。

## 模板移植与多步提取契约

把Nuclei模板移到Jaeles、或者多步将首响应的regex提取值用于后续请求，需要重审契约，不以重写完成等同检测语义一致。请求方法/字节、身份/会话、跳转、匹配器、提取变量缺失/多值及后续消费者分别登记；候选模板外链未读时不推其具体动作。

在获准离线样本中比较正常、匹配、无匹配、解析失败与提取值不存在的路径，记录新增请求和跨来源地址。源码片段/旧schema/工具成功并不证明当前版本行为；提取出来的URL、命令、文件名仍是不可信数据，不能由模板默认后续发请求/执行。未知工具容器或完整预装依赖也不代表可信、无副作用或已有范围许可。

## 探测产品、脚本制品与命令题名

## 插件声明版本与实际部署制品

WordPress插件readme的Stable Tag可用作源码候选线索，不能独立证明生产正在运行该版本：陈旧readme、自定义补丁、不同部署目录/包与禁用组件均可能造成差异。关联实际插件路径/启用状态、可提供的文件哈希、依赖、补丁和消费者，再选同版隔离源码审查。

只从获准既有制品/配置开始，保留无法确认的部署差异；不为取得版本无界枚举plugins/FUZZ，也不自动下载、安装或执行同名插件。源码中找到路径仍需确认入口可达与身份/业务条件，不把公开readme本身认定为漏洞。

## 本地枚举的权限位、所有者与扫描窗口

文件枚举图混合权限位查找、可执行文件、时间文字筛选、strings/file和下载执行未知脚本；这些输出分别描述元数据/候选，不直接证明root执行。setuid/setgid位与UID0所有者是不同条件，挂载/解释器/实际执行身份及可控输入需独立证据。

限制深度会留下未遍历范围，ls输出中的月份文本不能概括准确修改时间或全部可执行对象。优先获准已有元数据/源码和隔离小型普通文件，保存范围、权限/所有者、时间字段与实际消费者；不从Web测试许可继承主机根目录遍历，不下载chmod或执行枚举脚本，也不尝试提权。

## 版权年份与部署补丁状态

页脚版权年份是展示内容，可能固定、动态或跨部署复用；旧年份不证明软件过期、无人维护或未打补丁。把展示日期、制品构建/部署时间、依赖版本、补丁状态、启用配置与资产当前归属分开记录。

旧页脚可排序为待核线索，后续依赖已有同版制品、实际消费者与明确版本证据；保留新版仍用旧页脚、旧包有补丁等反例。搜索结果或年份差异不足以确认漏洞，也不扩展到未授权遗留资产。

## 文件年龄区间与名称数据库时点

图中find -mtime NUM被解释成最近最多NUM天并不准确；[GNU年龄区间说明](https://www.gnu.org/software/findutils/manual/html_node/find_html/Age-Ranges.html)按24小时区间取整，0对应不足24小时，1对应24至48小时，+/-和-daystart另有语义（2026-10-09核读官方索引相关摘录）。atime、ctime与mtime描述不同事件，ctime不是文件创建时间。

locate只搜索所选名称数据库，更新频率/目录覆盖与当前实际文件分别记录；[GNU名称搜索说明](https://www.gnu.org/software/findutils/manual/html_mono/find.html#Fast-Full-Name-Search)指出可能过时。name/path/type/depth是选择条件，print、exec、delete则是不同动作，不把整张速查图当只读枚举脚本，也不运行sudo updatedb或删除来源路径。

## 正则模式输入与匹配输入的资源复杂度

ReDoS候选需关联实际正则、引擎/版本、匹配模式、攻击者可控字符、长度限制/超时、调用线程与共享资源。可控字符串进入固定复杂模式，和用户文本被当成正则模式编译，是不同输入边界。[OWASP ReDoS说明](https://community.owasp.org/attacks/Regular_expression_Denial_of_Service_-_ReDoS)解释回溯与重复/重叠路径，也说明算法实现存在差异（2026-10-09核读相关段落）。

先静态查同版源码和已有耗时轨迹，以获准隔离副本的有限正常/近边界输入比较匹配结果、CPU时间和外层超时。单次网络慢还可能是排队/网络/后端；客户端regex存在不证明服务端同样使用。来源只有首段未给具体模式，不补整个线程，不用长串、高并发或生产阻塞来制造证明。

## 数据库校验错误与初始化副作用

数据库连接的“验证”可能已经进入驱动、连接参数和初始化消费者，后续返回400/SQL语法错误不能证明此前无副作用。[Metabase2023官方复盘](https://www.metabase.com/blog/vulnerability-post-mortem)把暴露的setup_token、setup校验入口及H2/JDBC消费者联系起来，也区分后续补丁、已初始化状态与管理员入口（2026-10-09核读）。这是历史条件，不意味着当前所有校验API匿名可执行。

旧图同时显示H2触发器错误与DNS/HTTP回执，应按请求、唯一关联标记、时间、真实执行上下文核对，普通DNS/单个回连不足以独立证明任意主机命令。复盘与图片中的2023时间也不能并入其2021帖子日期作为当年证据。审阅获准既有代码/脱敏日志，定位入口保证→驱动选择→参数解释→发生副作用的时点→错误返回；安全拒绝必须在危险消费前。不要运行图中的触发器、解码外传载荷、读取系统信息或创建数据库连接来补证。

## py2app制品层级与字节码版本

py2app应用可同时含Mach-O启动/扩展、Python源码、依赖归档和字节码；[维护者实现说明](https://py2app.readthedocs.io/en/latest/implementation.html)列出Resources里的启动脚本/主脚本、Python依赖zip及Mach-O依赖，历史目录名不能硬套当前制品。找到Mach-O或binwalk标记不代表其中所有内容都是同一种Python字节码，更不证明原始源码完整恢复。

[Python MAGIC_NUMBER文档](https://docs.python.org/3/library/importlib.html#importlib.util.MAGIC_NUMBER)把头部绑定字节码版本；[decompyle3维护者说明](https://github.com/rocky/python-decompile3)限定所支持/测试的3.7–3.8字节码（2026-10-09核读）。改成猜测头不能改变原操作码版本或补全损坏数据。对获准既有提取文本绑定制品hash、成员位置、真正格式/编译版本、工具版本、失败和无法还原部分，结果只是候选程序表示；不挂载来源dmg、执行包、安装分析器或批量解包未知文件。
