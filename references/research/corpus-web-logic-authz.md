## 真实手法清单

（按语料出现频次排序；每条给出可命中的资产形态、成立原因、案例 id）

1. **单参数对象引用直改（水平越权）**｜形态：`?file_id=`、`?order_id=`、`/user/{id}`、`?contact_id=`｜原因：服务端只用 id 取对象，不比对当前会话归属｜案例：12085（`/wcm/v1/file/download` 仅凭 file_id 下载其他企业合同）、2688（`get_my_order_detail?order_id=` 读他人订单）、7421（`user_id` 可遍历批量给他人发消息）。
2. **管理后台“全租户”动作接口缺租户/角色校验**｜形态：`/admin/api/.../delete`、`/api/v1/.../all`、管理菜单下的批量删改｜原因：后端只校验“已登录/是管理员”，不校验作用对象属于本租户｜案例：11492（越权编辑所有服务台）、11513（越权删除所有标签）、10368（越权删除所有用户空间）、17246（`registry.example.net` 权限绕过）。这是 `test-tenant.example.net` 34 条的统一根因。
3. **基础设施组件未授权访问**｜形态：Grafana、Actuator、Nacos、Harbor、Druid、Swagger、Prometheus、XXL-JOB、Zookeeper、Ollama｜原因：组件默认无鉴权或默认口令，公网可达即等于后台｜案例：6050、10358、23961（XXL-JOB 默认 accessToken）、24584（Actuator 弱口令泄漏账号密码与 token）、23279（Zookeeper 公网）。
4. **付费/会员权益只在前端判断**｜形态：导出、下载、生成、预览、模板原文件、训练营作业墙｜原因：前端置灰 + 后端接口不查权益/订单｜案例：2051（不付款使用收费模板音乐）、24636（edu 0 元购入付费视频）、24679（templates 匿名批量取付费模板原文件）、24926（付费 SVG/PPT 匿名可取）。
5. **遍历/批量造成的规模化泄露**｜形态：工资条、发票、审批单、工单、通讯录、`userids=` 数组｜原因：自增 id + 无速率/无归属校验｜案例：10506、11141（未授权读全部客户工资条明细）、17096（差旅平台可看所有人发票）、24707（OA 审批记录批量可读）、22835（contact 接口可爆 id 达 7 亿，含会员类型/手机号/经纬度）。
6. **双账号写操作越权（改/删他人内容）**｜形态：模板标题、海报素材、评论、待办、数据表、笔记｜原因：写接口同样只认对象 id｜案例：2037（改他人 h5 模板标题）、11055（删他人海报素材）、17276/17278（删改他人评论）、2466（替换他人数据表）、24473（改任意用户笔记）。
7. **协作/分享状态机绕过**｜形态：只读文档、关闭批注、锁定私密文件夹、回收站、分享链接｜原因：状态位只在前端生效，接口不校验当前文档状态与分享策略｜案例：2072（关闭批注仍可批注）、7070（只读状态仍可评论）、6177（绕过锁定私密文件夹）、11381（回收站越权查看他人）、24369（共享文档权限绕过）。
8. **审核/审批/准入环节可跳过**｜形态：团队号审核、应用管理员审核、绩效成绩开放时间、学生认证｜原因：把“待审核”当成展示态，接口未拦截｜案例：11506（绕过团队号审核）、11509（绕过管理员审核）、7404（未开放可提前查绩效）、24826（未校验学生认证领权益）、10365（绕过审核使用系统功能）。
9. **登录/二次验证/令牌处理缺陷**｜形态：`twiceverify_flag` 类 cookie、绑定第三方账号接口、后台登录页、`appSid` 进 URL｜原因：二步验证只由 cookie 标志位表达，绑定/登录接口不做真实校验｜案例：6785（adm 两步验证绕过）、8314（openadm 二次验证绕过）、24362/24372（前台绕过任意登录）、24535（会话令牌作为 URL 查询参数）、24914（短信动态码放 GET）。
10. **组织维度参数固定不变，一个值打穿全系统**｜形态：`compid`、`orgId`、`group_id`、`scope`、`pmway.ding.token`｜原因：把“组织固定 token”当鉴权，实际对所有用户相同｜案例：7269（token 全站相同 + orgId 固定，所有导出处可越权导出）、11131（`scope` 值对照即可改他人 SSO 配置）。
11. **未认证签发存储凭证/签名 URL**｜形态：KS3/KOS 上传 policy、`md5` 参数、CDN 全局下载密钥、对象存储桶｜原因：签名服务不校验调用方，或 key 由客户端参数决定｜案例：24924（服务中心未登录签发 KS3 上传凭证）、24939（KOS 未认证签发上传与读取链接）、24609（md5 参数未校验导致任意 key 写入）、24923（前端泄漏 CDN 全局签名密钥）、24531（匿名获取生产桶读写凭证）。
12. **字段级/范围属性越权**｜形态：可见范围成员、水印、公告权限、应用邀请码、SAML SSO 配置｜原因：只校验“能进这个页面”，不校验“能改这个字段”｜案例：17055（把通讯录外用户加进可见范围）、11460（给他人文档加水印）、24498（非管理员取企业应用邀请码）、24448（任意应用 SAML 配置越权读取）。
13. **IP 白名单/403 可被请求头绕过**｜形态：`X-Forwarded-For`、`client_ip` 类参数、仅靠 403 的目录｜原因：白名单取自可伪造头，或仅前端路由拦截｜案例：24945（信任 XFF 绕过白名单）、24789（开放平台内部接口 XFF 绕过）、10518（企业管理后台 IP 伪造）、7691、11037（`light.example.com` 403 绕过）。
14. **管理后台弱口令/默认凭据**｜形态：可视化部署平台、邮件、反馈后台、Zabbix guest、phpmyadmin｜原因：默认/通用口令、guest 未禁用、后台对外｜案例：1866、2240、2557（guest 未禁用）、6525、6526、6260。
15. **以前端权限门为唯一屏障**｜形态：隐藏菜单、灰化按钮、`/latest` 新版入口内的会员功能、内部效率工具入口｜原因：翻 JS 拿到接口即可直连｜案例：11945（翻 js 找到流程图接口，普通账号用超会功能）、23692（后台登录认证前端绕过）、24302（越权访问系统内部功能）。

## 参数与对象定位技巧

- **从一个“自己的对象”出发**：正常走完创建→编辑→导出→删除，逐包记录出现过的 id 字段；同一资源的详情/列表/导出/下载/历史版本是不同权限入口，分别收包。
- **优先怀疑单参数即可取数的接口**：`?id=`、`?file_id=`、`?order_id=`、`?contact_id=`、`/xxx/{id}`、`/xxx/{id}/download`。案例 12085 的判定语句就是“该接口仅根据 file_id 下载，未判断当前用户权限”。
- **区分 id 形态决定验证成本**：自增整数（订单号、成员 id、工单 id）可直接用自建第二对象验证；UUID/hex 不要猜，从自己对象的分享页、导出链接、通知消息里取；组织固定值（`compid`/`orgId`/`group_id`）往往一账号一值，取到即全站可用（7269）。
- **重点查“数组/批量”参数**：`file_ids`、`userids`、`addStaffs`、`FieldIds`。语料把同一接口的批量形式单列成洞（11384 明确写“file_ids 参数越权多处越权”），说明逐元素授权常被漏。
- **判断归属校验缺失的三步**：A 的会话 + A 的对象 → 正常；A 的会话 + B 的对象 → 是否返回 B 内容/是否真实改状态；B 的会话复看 B 的对象 → 状态是否被改。只有第 3 步能证明写操作生效。
- **错误码也是证据**：`403`→`200`、`空列表`→`他人数据`、`提示需权限`→`直接成功`，对比同一请求只改一个参数即可。
- **隐藏接口从静态资源取**：前端 bundle / sourcemap 里搜 `/api/`、`admin`、`export`（11945 即“翻 js 发现该接口”）；内部平台入口可由 `swagger`、`/debug`、`actuator` 暴露的映射反推。
- **批量验证边界**：只用自己创建的 2–3 个对象交叉引用；不遍历真实用户 id；需要表达规模时，用“id 为自增且无速率限制”推断可爆空间（22835 的写法），而不是真的批量抓取。

## 证据形态

语料中被判“已完成”的报告，证据几乎都能归到四种形态：

1. **双账号同请求对照**：A 号（受害者）/B 号（攻击者）各截一次，请求体只差一个 id 或一个 `scope` 值（11131 明写“大号 scope=1234 / 小号 scope=1111”；22832 明写“大号 ID … 小号 ID …”）。这是写操作越权最被认可的形式。
2. **完整 HTTP 报文 + 对方数据落地**：贴 raw request（Cookie 可打码），响应里出现他人姓名/订单/合同/手机号；2688、12085、7421 都是这个结构，并在正文用一句话点明“仅根据 X 参数”。
3. **自建资源的干净闭环**：6838 用 `test111/test222/test333` 三个自建账号互改密码，既证明可遍历又不碰真实用户，这类证据最不容易被质疑。
4. **影响量化描述**：写清“覆盖范围 + 数据字段 + 规模”三段。7269 写“该系统所有导出处……影响资金管理的回款单、销售开票、产品管理、CRM 管理”；22835 列“用户名称/头像/会员类型/起止时间/手机号/ISP/经纬度，可爆 7 亿 id”；12085 写“其他企业用户创建的合同”；11141 写“全部客户的姓名手机号工资条细节”。

四类形态的判定要素可直接对照：

| 形态 | 必须出现的要素 | 语料例 |
|---|---|---|
| 双账号同请求对照 | 两个身份标识、同一 URL、唯一变量（id/scope）、两侧结果 | 11131、22832、11055 |
| 完整报文 + 他人数据 | raw request、被改参数高亮、响应中的他人字段 | 12085、2688、7421 |
| 自建资源闭环 | 自建账号命名、互测前后状态、可遍历性说明 | 6838 |
| 影响量化 | 覆盖功能清单、字段清单、id 空间或客户范围 | 7269、22835、11141 |

补充：正文里的粘贴习惯是「入口 URL → 操作步骤（编号）→ 抓包位置 → 请求包 → 改哪个参数 → 结果截图」，几乎不写修复建议；部分报告还附“修复后复查”形成二次结论（如 24679 标记已修复）。

## 高频被忽略模式

以下仅是“被标为已忽略”的形态统计，**语料不包含忽略原因**，可能因重复、不收录、低价值或环境已变更，不能据此判定该类问题无效。

- **打包提交**：`多处垂直越权打包提交`、`多处越权打包提交`、`水平越权查看团队信息-打包提交`（11374/11376/11428），一封报告塞多接口，常被整体处理。
- **同功能点重复/补充**：同一标题出现“已忽略 + 已完成”两版（11485/11486、22998/23000），或“补充--编号 xxx”（24824 及其补充 24981）。
- **纯前端门/低于业务影响的绕过**：23692（后台登录认证前端绕过）、17047（禁止申请但能申请）、23248（标签数量上限）。
- **无数据外泄的“操作型”问题**：23811（读公告）、23824（群搜索）、23810（撤回公告），影响面难量化。
- **基础设施类重复**：Prometheus/Actuator/Swagger/Harbor 反复出现（17254、23728、23729、12863），同类组件在别的域名已被收录时容易判重。
- **需要受害者交互或只能影响自己**：22967/22969（登录劫持类）、23747（快捷登录凭证泄露），取证链不完整时容易被搁置。

## 可复用检查清单

1. 拿到任一业务对象后，列出它的**全部入口**（详情/列表/导出/下载/历史/回收站/分享），每个入口单独做 A/B 对照。
2. 对每个含 id 的请求做「只改 id」实验：先用第二个**自建**对象，确认返回他人数据或状态改变。
3. 写操作必须回查受害者对象终态（2037/2466 式），仅 200 不算成立。
4. 管理端菜单逐个点开，抓“删除/编辑/下线/分配”类接口，检查是否带 `orgId`/`tenantId` 且后端是否比对。
5. 检查所有 `*/admin/*`、`*/export/*`、`*/download*`、`*/upload*sign*` 路径：能否不带 Cookie、带空 Cookie、带他人 Cookie 调用。
6. 对数组参数（`file_ids`、`userids`、`addStaffs`）构造“一个自有 + 一个他人”的混合数组，看是否只校验首元素。
7. 权益类功能（导出/下载/生成/预览）在**拦截响应**后直接重放请求，确认服务端是否复核订单/会员。
8. 找组织维度固定值（`compid`/`org_id`/`group_id`/`token`），用第二账号比对是否相同；相同即可推全站影响。
9. 对分享/协作对象分别切换“只读、禁批注、锁定、链接过期”，在每种状态下重放写接口。
10. 审核/审批流中把“待审核”对象 id 直接拿去调用通过后的接口（11506 团队号审核、11509 管理员审核式）。
11. 对白名单接口追加 `X-Forwarded-For`、`X-Real-IP`、`client_ip` 之一，观察是否从 403 变 200。
12. 对签名/凭证接口在未登录态调用一次；再改 `md5`、`key`、`path`、`bucket` 参数，确认 key 是否由客户端决定。
13. 翻前端 bundle/sourcemap 找未在 UI 出现的 `api` 路径，优先测“会员/内部/管理”语义的接口。
14. 提交前自检：证据是否含双身份、是否只改一个变量、是否量化范围、是否清理自建对象。

## 相对现有文档的增量点

对照 `references/by-type/idor-access-control.md` 与 `references/by-type/business-logic.md`，本文补充的是**办公套件 场景化的可执行细节**，不重复通用方法论：

1. **资产-手法映射表**：`test-tenant.example.net`（众测后台“所有 X”删改）、`s.example.com`/秀堂（模板、表单、回收站）、`work.example.com`/`member.example.com`（企业 SSO、邀请、权限）、`docs.cn`/`woa`/`app-woa`（协作、评论、公告、helpdesk）、`contract.example.com`（合同 file_id）、`hr.example.com`（绩效/工资条）、KS3/KOS（凭证签发）。现有文档只讲“按业务建模确认归属”，未给域名级起手点。
2. **“管理后台全租户动作”模式**：现有 idor 文档强调对象与父级归属；语料显示更常见的是“管理端批量删改所有资源”，需要专门检查 `orgId/tenantId` 是否参与 SQL 条件。
3. **未认证签发对象存储凭证**：现有文档仅在签名 URL 段提“取决于签发规则”，未给检查点（匿名调用签名接口、`md5`/`key` 可控、前端泄漏 CDN 密钥、桶策略）。
4. **会话/令牌层缺陷清单**：`twiceverify_flag` 类 cookie 决定二步验证、`appSid` 出现在 URL 查询串、短信码走 GET——现有 authn 文档未覆盖这类“标志位即鉴权”。
5. **私有化/内网组件未授权**作为独立高发类（Grafana/Nacos/Actuator/XXL-JOB/Druid/Swagger/Prometheus/Zookeeper/Ollama），并给出“默认口令 + XFF 白名单 + 默认 accessToken”三条固定检查。
6. **数组参数逐元素授权**：`file_ids`/`userids`/`addStaffs` 的混合数组实验在现有两份文档中都没有。
7. **证据模板**：双账号 `scope` 值对照、三自建账号互测（6838）、影响量化的“字段清单 + id 空间”写法，可直接作为报告骨架。
8. **收录风险专章**：打包提交、同功能多版、纯前端绕过、无数据外泄操作型、组件类重复，这五类是语料里“已忽略”最集中的形态（原因未知，仅作风险提示）。
9. **业务逻辑侧重差异**：现有 business-logic 文档以金额/幂等/竞态为核心，语料中几乎没有竞态与金额精度证据；实际高发的是“权益校验缺失”和“状态位只在 UI 生效”，权重应前移。
10. **动作门槛**：语料大量案例依赖“两个自建账号 + 一个可枚举 id”，说明最小实验的资源准备应固化为「至少 2 个自建账号 + 2 个自建同类对象」，而不是临时找目标。
