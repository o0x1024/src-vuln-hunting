## 上传类真实手法

业务位置（按语料出现频次）：① 头像/企业 logo/图标（2359、2165、7674）② 反馈与工单附件（2493、9627、24749）③ Excel/数据导入 .ashx/.jhtml（9498）④ 简历/证件照/论文查重/全文翻译等增值功能（2233、5191、5192、10113）⑤ 开放平台与低代码 Demo（10806、10808、11422）⑥ 对象存储预签名与上传凭证（24399、24538、24632、24930、24935、24963）。

| 手法 | 做法 | 案例 |
|---|---|---|
| 前端校验绕过 | 前端判图片有效性，直接改包上传其它类型 | 7674、9627、10049 |
| 后缀/MIME 绕过 | 改 filename 为 .php/.jsp/.html，或改 Content-Type | 6137、6347、6578、2288、2407 |
| 未授权上传 | 接口本身不校验身份，匿名可写 | 6296、7164、10705、10750、11503、10917 |
| 导入型 RCE 说法 | 导入接口接受任意文件并声称可执行 | 9498、10113 |
| 对象存储/预签名 | 拿上传凭证或直接 PUT 生产桶，可覆盖/托管 | 24399、24538、24632、24930、24935、24963 |
| 存储桶副本 | 先传七牛/KS3，再由 CDN 回源生成同域副本 | 2493 |

**「仅上传未执行/未接管」为什么有时成立、有时不被认可**：

成立侧（被判 严重/高危/中危）：1979（可上传 html 且**能解析**，严重）、1980（ruok.legacy 上传 html，严重）、2705、6721（html 上传并解析，中危）、6578（认证后绕过图片类型**执行 html**，中危）、6296（未授权上传**导致执行 html**，高危）。共同点：文件落点与**业务同源**，响应由服务端决定为 `text/html`，访问即执行——这已越过「存储」进入「主动内容」。
降级侧：2359、2165（头像/图标任意上传，**低危**）——只证明类型限制缺失；2493（CDN 回源副本，**低危**）——独立缓存域、只能下载。
不成立侧：6074（「未限制上传类型」）、2407、2288（php 上传但落点不可执行）、10049（前端绕过但无消费路径）——**均被忽略**。

可总结的判据：
1. **执行/消费路径**是分水岭，不是文件后缀。同源直出 HTML（1979/1980/6578）> 可下载附件（2493）> 仅存储成功（2359）。
2. **是否匿名/未授权**对等级的拉动比文件类型更大：未授权上传+可执行落在高危/严重（6296、9498），认证后的同能力多为中危（7674、9627）。
3. 落在**平台设施**（对象存储、上传凭证、CDN 回源）而缺业务内消费路径时，即使证据极完整也常被忽略——24749（匿名 PUT + MD5 存在性预言 + 未认证下载，逐条 PoC）与 24538（未授权 ks3token + fuzz 出可 list/put 的桶）都是**已忽略**；反过来，24399 因证明「拿高权限 token 覆盖生产文件」被判中危并已修复。
4. 「可上传 exe/木马，管理员查看时可能上当」只能支撑中危（9627），不能当 RCE（9498 的严重来自导入接口的实际执行）。
5. 老式 `.ashx/.jhtml` 上传不等于 RCE：9498 记 严重、2407 记忽略，差别在返回体与后续调用能否执行。

分级锚点：严重=可执行/可 getshell（1979、1980、9498、10113）；高危=未授权可写或已 getshell（6296、7164、10917、11503）；中危=认证后绕过或有明确消费面（6137、7674、9627、10806）；低危=仅类型缺失或只能下载（2359、2165、2493）。

## 开放重定向与 URL 跳转

被判有效的条件（不是「有 redirect 参数」）：
- **能挟带一次性凭据**：11230（`svc.example.com/login?rcb=`，构造 `https://baidu.com\@test.example.com/test` 利用前后端 URL 解析器不一致绕过白名单——后端 OR filter 认为 host 是白名单内的 test.example.com，浏览器实际去 baidu.com；再结合微信登录授权 code 回传兑换 app_sid → 账户接管，**高危**）。同类思路在 11342（悬空存储桶接管域名后窃取微信 code，**严重**）复用。
- **账号域+白名单绕过**：16967（`account.example.com/debug/checkcdn?cb=`，白名单在前端 JS 的 `whiteList` 数组里明文可见，多接口一并通过，**高危**）；标题级旁证 12668、12683、12781、12690/12691（「任意URL加载绕过并实现XSS」「在野利用」）。
- **在野利用**：12598（云文档任意跳转，在野利用，高危）、12781。
- **HTML 注入导致跳转**：22811（流程图/思维导图备注 → 评论注入 → 跳转，**高危**）、23274（邮件组名称注入，且**无外部域名提示框**，中危）、23388（eml 导入 base64 HTML，bypass 外部链接提示，中危）、23299（审批意见注入，低危，需同企业成员）、23309（日程附件 `linkPc` 可改，低危，且 办公套件 会议客户端点击附件**无提示直接跳转**）、11639（社区 HTML 注入，低危）。

被忽略的模式（同一手法不同结论，值得逐条对照）：
- 纯 `?returnurl/?redirect=` 落在主站、活动页、社区发帖处、QQ/微博分享接口：2201、9200、9567、11553、11564、11810、12747、12748、23034、23035、23393、23412、23629、23978、24294、24389、24550、24551、24639、24752。12747/12748 的报告大段抄「重定向危害非常大」的通用论述、写到第三方分享接口即止，是典型的**无影响链**写法。
- **登录页跳转不自动加分**：10954（「办公套件主站登录页面URL跳转」，标高危仍**已忽略**）、12603（templates「登录的地方」，已忽略）；而同站**登出**处被判中危（12602、1509）。说明校验点位置不等于影响，能挟带 code 才算。
- 重复提交同一点位：11414 → 11425（「重新提交」）双双忽略。
- 白名单绕过但停在「加载任意 URL」：12837（weboffice webshape 绕过白名单，高危仍忽略）。
- 同组件不同结论：22811（diagraming 评论，高危）vs 23084（同接口，中危）vs 22806（mindmap，忽略）；22825（HTML 注入→docs 跳转 + bypass 提示框，中危仍忽略）vs 23274（同手法中危已完成）。判定不稳定，提交时要把「谁触发、受害者是否需要登录、是否有提示框」写死。

## CSRF

写类型 4/5 完成，读类型 1/4 完成——**读类型明显更难被认可**。

- 写类型：11851（`crm.example.com/Base/Main.aspx`，老 ASP.NET `.ashx` 无 token，可改资料/改设置/**未授权加成员/改权限/解散企业**，中危——用「多动作打包」体现影响面）；22927（`vaf.example.com/proxy/ocr/.../folder/create`，JSON Content-Type 仍成立，中危，注意这是**代理域**而非业务域）；9927（chuangkit `fillInfo.do` 表单 POST，中危）；23147（`whiteboard.example.com/.../task/delete?taskId=`，GET 删除 + PoC 遍历 5000–5100，低危但**已完成**）；23151（legacy 单词提醒开关，低危**已忽略**——只影响本人提醒设置，无可指认后果）。
- 读类型：8916（`designer.example.io` JSONP 劫持**打包**多条，中危已完成——但它的说服力来自「订单/协议信息可被跨域读」+ 打包成一份）；8845（`account.example.com/p/user/me/devices`，作者证明「删掉 Referer 即绕过」，仍是设备列表读取，**已忽略**）；6522（qr.example.com 登录二维码 JSONP 组合成「假面攻击」让你登进攻击者账号，逻辑链很长，**已忽略**）；23057（`idPhoto/add` 加图片，**已忽略**）。

为什么读类型更易被忽略：
1. 缺「状态变化」这个默认锚点，必须额外证明**字段私密性**与**跨用户可见**；只证明「能读到自己的数据」等于没证明。
2. JSONP 类必须证明 `callback` 真的进了 `script src`、返回体不是公开数据；8845/6522 都停在「接口能被跨域调」。
3. 打包提交在写类型能加分（11851、8916 成功），在读类型反而稀释单点影响（6522 的八步链条被整体判无影响）。
4. 只影响当前账号自身设置的动作（23151）在两类里都最容易忽略。

判据：写类型看**动作后果能否被企业识别**（删协作数据、加成员、改权限、解散团队）；读类型先选「他人不可见即异常」的字段（设备、订单、协议、工单、简历），再谈 CSRF。

## 高频被忽略模式（声明：语料不含忽略原因）

切片**没有忽略原因字段**，以下仅为可观测特征与推断，不能当作平台规则：
1. 主站/活动页/社区发帖处的纯外跳，只写「可钓鱼」（9567、24550、24752）。
2. 登录页跳转（10954、12603）——与「登出处可跳」的结论相反，说明点位信任度不自动折算影响。
3. 同一参数重复提交（11414/11425）、同组件换图形类型（22806 vs 22811）。
4. 只证明「可上传/未限制类型」，无执行与消费路径（6074、2407、2288）。
5. 平台设施类：匿名桶写、MD5 预言、上传凭证（24749、24538）——疑与「预期公开/非业务数据」判定有关。
6. 拒绝服务与配置类（9099、9104、8914、8052–8055）——与「同族有人被收」并存，判定不稳定。
7. 读类型 CSRF 与「只影响自己」的动作（8845、6522、23057、23151）。
8. 纯响应头缺失、版本过低、无 PoC 的框架漏洞（24329、8045）。

## 可复用检查清单

1. 上传点先问三件事：落点是否与业务同源、响应 Content-Type 由谁决定、下载是否 `attachment`。三者定「会话/钓鱼/仅存储」。
2. 见到 `presign / token / signature / sts` 字样，先判断是「业务内消费」还是「平台设施」；后者要额外证明覆盖或越权读。
3. 上传默认按「最小无害标记文件」验证，落到执行层前先确认该项目允许，且不部署 webshell、不覆盖既有对象。
4. 跳转点先找**一次性凭据**:`code`、`ticket`、`sso_token`、`rcb/returnurl/cb`。能挟带才是高危。
5. 白名单绕过往两类打：前后端解析器不一致（`\@`、`@`、`//`、编码差异）、白名单在前端 JS 明文暴露（16967）。
6. 判断跳转是否「有提示框」：企业客户端/邮件客户端的无提示跳转（23299、23309、23388）比浏览器跳转更值钱。
7. 业务字段 HTML 注入造成的跳转要单独评估：这类常被判「HTML 注入」而非「跳转」，但等级看受害面（22811 高危 vs 23299 低危）。
8. CSRF 写类型优先选**不可逆、可被企业感知**的动作：删协作数据、加成员、改权限、解散团队（11851、23147）。
9. CSRF 读类型先证明字段私密性（他人设备、订单、协议、工单），否则不要提交;JSONP 必须证明 `callback` 进 `script src`。
10. 记录防护形态：token/Referer/Origin/SameSite/JSON Content-Type，逐项说明是「缺失」还是「可绕过」（8845 的删 Referer 即绕过要写清）。
11. 点击劫持必须补一步：嵌入后**带有效身份**且有敏感控件，并演示一次可逆操作（对比 24861 与 8187）。
12. 类型标签不可信（23887 名为点击劫持实为 HTML 注入），以自己的复现结论命名。
13. 轰炸类要写清「谁被骚扰、消耗什么资源、单次成本」，并只发少量验证（10100、11423）。
14. 拒绝服务/版本匹配类默认不提交：语料里同族结论互相矛盾，且与授权边界冲突。
15. 报告固定加一段「前提与边界」：受害者角色、是否需登录、是否需同企业、哪些影响未验证（11342 的排除法写法）。

## 相对现有文档的增量点

现有 `file-upload.md`、`open-redirect.md`、`csrf.md`（以及 `clickjacking.md`、`cors.md`）已覆盖：上传四段拆分与不混称 RCE、仅上传成功/Content-Type 可伪造不充分、跳转需记录浏览器最终 URL 与整链、OAuth 凭据需证明到达受控落点、CSRF 三条件与 SameSite/Origin 区分、读不到响应≠动作未执行、点击劫持需身份+敏感控件、CORS 需真实私密数据读取。以下为本文可并入的增量：

1. **上传的「消费路径」判定顺序**：现有文档说「需实际访问/处理路径」，但没给顺序。建议补：同源直出 HTML > 同源下载 > 独立 CDN/附件下载 > 仅存储成功，四级对应 严重~忽略（1979/1980、2493、2359、2407）。
2. **「平台设施」这一独立类别**：对象存储、预签名凭证、上传 token、CDN 回源副本（24399、24538、24632、24749、2493）。现有文档只在多租户一句带过。要点是「缺业务消费路径 → 常被忽略；证明覆盖生产文件 → 中危已修复」。
3. **未授权 vs 认证后对等级的影响**：现有文档未区分。语料显示未授权上传+可执行直接高危/严重（6296、9498、10705、11503）。
4. **跳转与一次性凭据的绑定**：现有文档提「OAuth 凭据泄露需证明到达受控落点」，但未给「找 code/ticket/rcb」的入口枚举与「前后端解析器不一致」的具体绕过族（11230、16967）。
5. **HTML 注入型跳转作为独立链路**：现有文档没有。语料中它占 2024–2026 跳转完成件的大头（22811、23274、23299、23309、23388、11639），且判级取决于「是否有外部域名提示框」和「受害面」。
6. **登录页 vs 登出处的判定差异**：可复核结论——登录页跳转常被忽略（10954、12603），登出处可被认（12602、1509）。现有文档无此经验。
7. **CSRF 写/读分型与判据**：现有 `csrf.md` 未分型。建议补「写类型看企业可感知后果，读类型先证字段私密性」，以及读类型占 4 条中 3 条被忽略的实证（8845、6522、23057）。
8. **代理域 CSRF**：22927 的请求落在 `vaf.example.com` 而业务在 `stats.example.com`，说明「跨站页面 → 代理域」同样成立，现有文档未提。
9. **GET 型删除 CSRF + 批量遍历**：23147 用 GET `?taskId=` 删除并以 JS 循环遍历区间验证，被记低危已完成；可作为「如何在不造成实际破坏下证明可枚举」的写法。
10. **点击劫持的「忽略样本特征」**：现有文档只说要证明动作可达，未给反例特征——纯 iframe 加载截图、响应头缺失清单、首页（24861、24329、23849）在本语料全部忽略。
11. **杂项收录梯度**：未授权接口+量化数据为严重（22997）、子域/桶接管为严重（11342）、轰炸/并发为中低危（10100、11423、11444、11445、10262）、DoS 与配置类不稳定或忽略。现有 `vulnerability-catalog.md`/`impact-and-acceptance.md` 可引用此梯度作实证。
12. **历史判级与现行协议的冲突要显式标注**：11032 等 7 条同模板「版本命中 + 公开 DoS PoC」被记高危，与「版本命中不能替代确认」「不做资源耗尽」冲突；建议在文档中加一句「历史判级不作为方法复用」，防止被当成可复制套路。
