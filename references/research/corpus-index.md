# 匿名 SRC 成交语料索引

来源：匿名化的历史众测/SRC 归档（来源与厂商已隐去），本地路径 `vulns/`，**20,765 条**漏洞档案（2019-01 至 2026-10），每条含 `detail.json`（结构化字段+正文）与 `doc.md`（渲染版），另有 3,297 个 PoC `.zip` 与 22,700 张截图。

提炼日期 2026-10-20。这是**单一厂商的单项目语料**，不是行业频率统计；引用时必须标明项目与年份，不得外推为"所有 SRC 都这样"。

## 它是什么、不是什么

- **是**：真实提交 → 真实审结的闭环记录，含标题、类型标签、等级、评分、状态流转与正文取证过程。可直接回答"这类写法在这个项目上有没有被判有效"。
- **不是**：`已忽略` 有 4,009 条，但归档**只有状态名，没有忽略原因**（检索"重复/不收录/无效"等关键词，命中的只是状态变更提示语）。所以"被忽略"可能是重复、已收录、低价值、环境变更或未修复，**不能反推为漏洞不成立，也不能当作收录规则**。
- **不是**：正文写的是当时的自述，未经复现。载荷与命令可作线索，判定标准仍以本 skill 协议为准。
- **不是**：`组件漏洞` 10,083 条（48%）是 NVD 式 CVE 批量导入（8,875 个 CVE、341 个组件，99.8% 仍为"审核中"），只有 9 条已完成。它是**组件风险清单**，不是挖掘技法语料，不要当作成交样本引用。

## 使用规则

1. **先看年份**。同一形态在不同年份结论会反转：PDF 转换泄露内网 IP 在 2022 年成批中危结算，2025 年后同类不给等级；DLL 劫持 2020 年 61% 完成，2025–2026 年 0/18。引用前核对最近一年口径。
2. **区分"技术成立"与"结算"**。语料能证明的是后者。写假设时用"该形态在该项目被判有效的证据是……"，不要写"这是漏洞因为语料里有"。
3. **不要复制载荷当结论**。正文里的样本文件、栈回溯、cookie 标志位只能指向检查点；实际确认仍走 [验证标准](../verification.md) 与 [影响与收录](../impact-and-acceptance.md)。
4. **脱敏不可逆**。本目录所有文件中的凭据、内网地址、个人数据已替换为 `<redacted>`；引用时保持脱敏，不回填原始值。
5. **不得据此扩大授权**。语料里的资产、内部系统、众测环境一律不是默认可测目标；测试范围仍由用户与项目规则决定。

## 复核方法

归档为纯文本可复算，无需重新抓取：

```bash
# 按子类看过审率
jq -r '[.main,.sub]|@tsv' vulns/2025/*/detail.json 2>/dev/null | sort | uniq -c

# 取某类型正文样本（含状态）
grep -l '释放重引用' vulns/2025/*/detail.json | head -20 | xargs -I{} jq -r '.vulnerability.detail' {}
```

归档 `detail.json` 的 `vulnerability` 字段含 `main/sub/level/score/status/team_name/url/detail`，`vulnerability_status` 数组是状态流转历史。`doc.md` 顶部的表格含渲染后的状态与等级，适合人工抽检。

## 与其他语料的关系

[x-corpus.md](x-corpus.md) 是公开社交媒体的**他人自述**，覆盖面广但无审结信息；本目录是**单项目审结结果**，覆盖面窄但可直接判断"值不值得投"。两者冲突时：技术可行性参考 x-corpus，收录口径参考本目录，且以当前项目规则为最终依据。
