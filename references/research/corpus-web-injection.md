要点：

- **类型标签在两层不一致**：标题层 21 条写「代码注入」，正文层 14 条写「命令注入」，内容同族（log4j、shiro、fastjson、actuator、nginx CVE 混在一起）。做统计时不能把两层相加当成 35 条；本文按一族处理，并保留原标签引用。

## SSRF（真实触发点类型、回连与盲打方式、内网可达性证明、被认可的影响形态、案例 id）

触发点并非集中在单一形态，语料里可归为六类，且高危几乎全部出自第 3、4 类：

1. **文档/媒体导出与格式转换**：简历「另存为」的 `/html-transfer-dpr/htmlToPic`、`/htmlToPdf` 由服务端取 URL 后渲染（`[10941]` 中危 已完成、`[10942]` 中危 已完成）；简历解析 `/tools/assess/resume_parse/v1/parse_pdf`（`[22941]` 中危 已完成）；文档导入 `tools/kdoc-upload/api/meta/v3/upload` 的 `storage_url`（`[24555]`、`[24617]` 已忽略）；票据 OCR `/folder/api/v1/receipts/ocr` 的 `file_url`（`[24570]` 已忽略）。
2. **收藏 / 网页解析 / 预览截图**：收藏夹 `/2c-cloud/office/v5/collections/check_url_access`（`[23006]` 中危 已完成，明确写「可以爆破内网 ip 和端口」）；同一功能的全回显与半回显变体（`[23386]`、`[24784]`、`[24796]` 均已忽略）。
3. **webhook / 事件订阅 / 回调地址配置**：低代码流程「添加 webhook」填 `url` 后「发送测试数据」（`[23039]` 低危 已完成）；开放平台「事件与回调 → 订阅配置 → 请求地址」`POST /v7/developer/apps/<redacted>/settings/batch_update`（`[22980]` 中危 已完成）。
4. **低代码/开放平台远程数据源与服务端校验**：`Q-Linker` 远程数据源直接读元数据（`[12678]` 高危 已完成）；`/api/data/remoteLookup/test`（`[12679]` 高危 已完成）；`/api/console/apps/<redacted>/path/check`（`[12654]` 高危 已完成）；`/oauth/v2/adm/companies/<redacted>/token_cfg/check`（`[12607]` 高危 已完成）；邮箱域名配置 `POST /api/manage/v1/domain`（`[12646]` 高危 已完成）。共同点是「填一个地址让后端去验连通性」。
5. **图片/站点图标抓取**：`/groups/v1/team/groups/<redacted>/favicon?url=`（`[11432]` 已忽略）。
6. **组件默认开启的抓取能力**：Sentry 默认开启 source code scrapping 导致 blind SSRF（`[6723]` 中危 已完成）；Jira 自带 SSRF（`[1638]` 高危 已完成）。这类入口不在业务参数里，靠指纹识别而非业务建模获得。

回连与盲打方式（语料中实际使用过的四种，按证据强度排序）：

- **全回显**：响应体直接带回目标内容。webhook 测试把 `url` 指向云厂商元数据地址后「响应包中可以看到回显」（`[23039]`）；收藏夹把内网页面渲染成预览图再落到对象存储，下载即得内网页面（`[23386]`）。这是最强形态。
- **错误信息回显**：请求失败时把 `dlUrl`、`err`、`statusCode`、DNS 解析器地址拼进报错（`[24555]`）。比状态码更细，且不需要目标内容回显。
- **差异响应码判活**：内网 IP 存在返回 `200`，不存在返回 `504 upstream request timeout`，据此遍历网段（`[23394]` 中危 已完成）。这是语料里最节省请求、最容易被审核接受的盲打证明方式。
- **带外域名接收**：自建带外域名收完整回包，并复用回包中的 Token 再打一次证明凭据可用（`[24831]` 已忽略）。

内网可达性证明的三条实战路径：

- **状态码二分**（`[23394]`）：先建立「通 → 200 / 不通 → 504」的对照，再谈网段。对照组是这个方法的全部说服力。
- **黑名单绕过 + 二次呈现**：直接填内网地址被拦，改用在线短链服务把内网地址包装成公网短链，后端跟随后取到内网页面，并把结果作为预览图落盘（`[23386]`）。绕过点不在协议/编码，而在「后端会跟随重定向」。
- **代理层凭据泄露**：请求被转发给内部 Squid 代理，响应里带出代理账号口令（`[24175]` 高危 已忽略）。

被认可的影响形态与定级关系（重要，且与直觉相反）：

- 「读到云元数据」不等于高危：`[23039]` 全回显读到元数据目录仍定**低危**，而 `[12678]` 同为读元数据定**高危**。差别不在能力，在资产所处网络位置与可触达范围。
- 中危是本类最常见的落地等级，覆盖「无回显但能证明内网可达」（`[22941]`、`[23394]`、`[23006]`）。
- 有 `[24766]` 这种「回显 + 连内网数据库」仍只是中危且状态为已修复的样本，说明**能力上限不是定级的自变量**。
- 语料对「带外回连」的态度不是一刀切：JNDI 带外（`[7427]`）与带外取回后复用 Token（`[24831]`）均未过审，但 blind SSRF `[6723]` 仅提供触发 URL 即中危已完成。因此不能宣称「带外一律不收」，只能说本案的带外证据未能支撑其自评等级。这条与现有 `ssrf.md`「DNS 回连只证明解析行为」一致。

## SQL 注入（注入点位置、DB 类型线索、盲注/时间盲注与工具、数据取证边界、案例 id）

注入点位置（按语料出现频次排列，括号内为可直接照抄的入口形态）：

- **GET/POST 查询串里的业务 ID 与筛选字段**：`authorized_party`（`[23949]`）、`noteids`（`[23935]`）、`filter_UserIds`（`[23635]`）、`uid`/`uuid`（`[1643]`）、`filterTime`/`filter_CompanyIds`（`[23635]`）。这类参数常被前端下拉框「钉死」取值，测试时必须自己改包。
- **JSON body 里的字符串字段**：`fetchSlideType` 对应 `title` 字段，payload `title'and(select*from(select+sleep(5))a/**/union/**/select+1)='` 触发 5 秒延迟（`[1500]` 高危 已完成）。JSON 体不是防护，`Content-Type: application/json` 与注入无关。
- **加密参数 `condition`**：把查询条件整体加密后 POST 给后端，解密后仍拼接进 SQL（`[9497]`、`[9757]`、`[9512]` 均已完成；`[9758]`–`[9761]` 同系统同参数已忽略）。这是本语料最有辨识度的一类注入面——**看到参数加密不能停止判断，要找到解密后落点**。
- **`.ashx` 处理器 + 查询构建器**：`POST /Base/Grid/Ashx/Grid_GetTableHTML.ashx`（`[13007]`、`[23239]`）、`POST /Base/Ashx/Common_More.ashx`（`[23387]` 严重）、`GET /App/Index_New.ashx?_method=GetData_VisitTotal`（`[23635]` 严重）。走「高级搜索」「商机总览」把用户选择的筛选条件拼进表头/排序。`?_method=` 这种伪路由参数不影响注入。
- **路径中的裸 ID 段**：`/admin/api/v1/suite/workspace/recommend_apps/rules/10815/update`（`[23953]`）。RESTful 路径段是最容易被排除在参数测试之外的位置。
- **客户端历史包**：手机 APP 「历史包中有那么一个」`POST /api/v1/app_badges/batch_get`（`[23271]`）。入口来自客户端存量请求，不在 Web 页面上。

DB 类型线索与证据边界：切片正文中 `MySQL`、`MSSQL`、`Oracle` 作为**显式标注均未出现**（关键词统计命中 0），数据库类型只能从 payload 方言反推：`sleep()`、`database()`、`length(database())=6`、`0x` 十六进制比较、`extractvalue(1,concat(0x7e,user(),0x7e))` 属 MySQL 方言（`[1500]`、`[23935]`、`[23949]`）；而 `[23949]` 用 `'|| … ||'` 包裹函数，`.ashx` 栈下的 `||` 语义需实测（MySQL 需 `PIPES_AS_CONCAT`，MSSQL/Oracle 默认即拼接）。**语料没有一条记录「报错信息里的驱动名」这类确凿指纹**，不要据框架名推 DB。

盲注 / 时间盲注的实战序列（`[23935]`，可复用度最高）：

1. `noteids=1'and%20length(database())=6%20--'` —— 先用 `length(database())` 判定库名长度，建立「语法正确且参与运算」的证据。
2. `noteids=-1'and case when (database()=0x6e6f74656462) then sleep(0) else sleep(3) end--'` —— 再用 `case when` 做「零延迟 vs 3 秒」的**差分**对照，而不是单点 5 秒延迟。
3. 库名以十六进制表达，避免引号被网关处理。

工具：全切片 `sqlmap` 命中 **0 次**，67 条正文样本全部是 Burp 手工构造单条请求 + 人工对照响应。这不是说工具不可用，而是说**语料中过审的样本没有一条依赖扫描器输出**；现有 `sql-injection.md` 已写「工具结论仍需证据复核」，语料进一步显示实战报告以手工最小验证为主。

数据取证边界（语料内实际所做，可作为上限参照）：

- 只取常量级证明：`user()` 回显（`[23949]`）、`database()` 长度与名称（`[23935]`）、延迟差分（`[1500]`、`[23635]`）。
- **先自建数据再测**：`[23370]` 明确「以当前业务员身份新建一条线索 要有数据比较好判断注入」；`[23635]` 写「有数据可以更好判断注入 没数据可以用堆叠延时证明」——无数据时退化为延时证明。这是降低对真实业务数据依赖的标准动作。
- 权限门槛要写清：`[23953]` 说明「账号为企业创建者账号，以下所有 cookie 都需要企业创建者的 cookie」，避免审核按越权复测。
- 切片中**没有任何一条导出真实用户表、账户表或凭据**。全部 224 条 SQLi 标题也无「拖库」表述。

## 证据形态（这些类别高过审率的原因：可复现、影响直接）

三类的过审率差异本身是证据形态差异：SQL 注入 71.4%、命令/代码注入 76.2%、SSRF 48.2%。

- **请求包 + 业务路径是共同骨架**。成功样本几乎都写成「打开某页面 → 点某按钮 → 抓包」，再贴完整原始请求（含 `Host`、`Referer`），审核可原样复放。`[11303]` 连「子域名解析成 IP 相互碰撞得到 host、绑定 host」的取址过程都保留了。
- **可对照的响应差异**替代「我认为存在」：5 秒延迟（`[1500]`）、3 秒差分（`[23935]`）、`200` vs `504`（`[23394]`）、403 vs 成功（`[23901]`）。差异+基线成对出现，是最高性价比的证据。
- **影响直接到数据或权限**：SQL 注入天然带「读到数据库身份/库名」，SSRF 天然带「读到内网/元数据」，命令执行天然带「代码执行」。不需要再论证危害。
- **反面**：SSRF 过审率掉到 48%，对应的正是「只有带外回连」「只有状态码没有对照」「写实但未定位被突破的限制」这三类写法；30 条审核中集中在 2026，说明该类的证明标准仍在变动中。
- 一个必须保留的不确定性：切片**没有「忽略理由」字段**。上面把「版本命中」「仅带外」与被忽略相关联，是描述性共现，不是已证实的判据。

## 高频被忽略模式（并声明语料不含忽略原因这一证据边界）

> **证据边界**：语料每条仅含 标题/类型/等级/状态/年份 + 正文自述，**不含审核意见、忽略原因、重复判定来源**。以下「模式」是从自述内容与最终状态的共现中归纳，不能被当作平台规则；共现也不排除「同批被判重」「资产下线」「超出收录范围」等未记录原因。

- **仅版本命中，无复现**：nginx CVE-2021-23017 共 4 条，3 条已忽略（`[12613]`、`[12617]`、`[17156]`）、1 条已完成（`[12068]`）；`[2796]`（Struts2，自述「工具检测出来的…没有复现」）已忽略。**同形态结局不一致**，说明版本命中不是必然拒绝，而是结果不可预测——这本身就是应当避免的理由。
- **仅带外回连**：`[7427]`（log4j JNDI → Collaborator）严重却已忽略；与同期有进一步证明的 log4j 条目形成对照。
- **SSRF 回显能力参差，但不构成单调规律**：无回显（`[22899]`、`[11432]`、`[24831]`）、半回显（`[24784]` 标题即写）、全回显（`[24796]`、`[23386]`）三类**都有被忽略的样本**；同时 blind SSRF 又有 `[6723]` 中危已完成（证明仅给出触发 URL）。结论只能是：回显能力不是唯一变量。
- **疑似通用/重复**：`[6945]` 标题带「疑似通用」；`[9758]`–`[9761]` 与 `[9497]`/`[9757]`/`[9512]` 属同一系统、同一加密参数 `condition`，前者忽略后者完成——这是切片内最明显的重复/拆分痕迹。
- **资产疑似退役**：团队字段为「办公套件会员-废弃」「智能云文档产研部-旧」的样本中，`办公套件会员-废弃` 共 11 条有 5 条忽略。字段名本身提示资产状态，但语料未把它写成忽略理由。
- **只证明代理/中间层行为**：`[24175]` 高危，内容是请求被转发到内部 Squid 并泄露代理凭据，仍已忽略；被突破的规则（业务是否本应允许出网）没有被论证。

## 可复用检查清单（编号 8-15 条）

1. 先按「填地址让后端去验」枚举入口：webhook、事件订阅回调、域名/白名单校验、低代码远程数据源、文档/图片/OCR 导入、收藏与预览。语料中高危 SSRF 全部出自这一类。
2. 每个 SSRF 实验先建立**可判活/判死的对照组**（通 `200` / 不通 `504` / 超时时长），再谈网段与端口；没有对照组的探测结果不写进结论。
3. URL 过滤重点测「后端是否跟随重定向」而非编码：把内网地址包装成公网短链或自建跳转，观察后端是否取到第二跳。
4. 区分四级能力并分别取证：DNS 解析 → 已归因的服务端请求 → 差异响应/错误信息回显 → 内容回显或元数据读取。等级只按实际到达的最高级写，不按类型套。
5. SSRF 定级不要只写「读到元数据」，要同时说明资产所处网络位置与可触达范围；语料中同能力跨「低危—高危」。
6. SQL 注入优先测被前端钉死的取值（下拉框、`filter_*`、`page_size`、排序/列名），以及 `_method=`、`.ashx`、路径裸 ID 这类「非典型参数位」。
7. 遇到加密参数（如 `condition`）不要停在「已加密」：定位解密后的落点，按明文拼接逻辑重新构造。
8. 时间盲注用**差分**而非单点：`case when (<条件>) then sleep(0) else sleep(3) end`，并先跑一次无 payload 基线。
9. 判定 DB 方言靠语法对照（`sleep`/`database()`/`0x`/`||`/`extractvalue`），不靠组件名与框架名。
10. 注入前先以自有权限创建一条业务数据，让查询有行可返；无数据时退化为堆叠延时，并在报告中写明退化原因。
11. 取证止于常量：`user()`、`database()`、库名长度即可结案；不枚举表、不导出真实记录、不留凭据样本。
12. 报告中固定写清所需身份（普通用户 / 企业创建者 / 需特定 cookie），避免审核按越权口径复测。
13. 命令/代码注入入口优先从中间件与组件指纹找（actuator、shiro、fastjson、log4j、confluence、yapi），业务参数拼接在本语料无成功样本。
14. 拒绝以「版本号命中 + 公开 PoC」结案；要么补齐可复核的触发链，要么按待补证处理，不占用严重级表述。
15. 提交前自查是否与既有条目同系统同参数（重复是语料中可观察的忽略诱因之一），并核对资产是否处于废弃/旧版状态。

## 相对现有文档的增量点

1. **新增两类 SSRF 触发面**：`webhook/事件订阅回调地址配置` 与 `低代码 Q-Linker 远程数据源`。现有 `ssrf.md` 只列「URL 导入、预览、截图、PDF、webhook、代理或下载」，未把「配置类地址校验」与「服务端连通性测试」作为独立入口，而语料中 2024 的高危全部来自这里（`[12607]`/`[12654]`/`[12678]`/`[12679]`/`[22980]`）。
2. **补三种被认可的内网可达性证明**：状态码二分（`200`/`504`，`[23394]`）、错误信息回显 `dlUrl`/`err`/`statusCode`（`[24555]`）、黑名单绕过后的图片回显（`[23386]`）。现有文档只写「内网差异响应」一句，没有可操作的构造方式。
3. **补「短链/跳转服务绕过 URL 黑名单」**（`[23386]`）：现有 `ssrf.md` 只提「重定向每跳和实际目的地必须仍获准」，未把「后端跟随重定向」列为优先测试点。
4. **量化定级反直觉**：同能力 SSRF 在语料中跨低危（`[23039]`）到高危（`[12678]`），支持并强化现有「能力不等于等级」的判断，同时给出「资产网络位置」这一具体变量。

6. **补「先自建数据再测」的准备步骤**（`[23370]`/`[23635]`）：现有文档只在二次注入处提到「创建允许的测试数据」，未把它提升为普通注入的前置步骤。
