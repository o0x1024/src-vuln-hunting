# PC 客户端本地攻击面（语料提炼）

来源：`work/slices/pc-client.md`（匿名 SRC 档案切片，cases=303，已完成=125，已忽略=138，其余审核中/已修复/已确认）。仅提炼该切片与现有 `references/by-type/desktop-client.md` 可核对的内容；用户目录、账户名、内网地址、硬编码密钥一律记为 `<redacted>`。

## 语料画像

| 子类 | 条数 | 占比 | 已完成 | 完成率 |
|---|---|---|---|---|
| DLL 劫持 | 119 | 39% | 50 | 42% |
| 权限提升/绕过 | 76 | 25% | 20 | 26% |

要点：

- **DLL 劫持是本地攻击面的绝对主体（39%）**，但完成率随时间单调衰减：2019 年 6/6、2020 年 36/59（61%）、2024 年 4/23（17%）、2025 年 0/11、2026 年 0/7。同类技术在同一产品族内"早期批量收、后期需附加条件"是本语料最强的结构性信号。
- **提权/绕过完成率最低（26%）**，且 2026 年 31 条中 0 条完成——多数处于审核中或已忽略。该子类大量集中在 `cloudsvc` / `updatesvc` / `ipcsvc` / 轻客户端 IPC 命名管道一族，说明这一段是当前最密集的探索区，也是最密集的争议区。
- 2026 年样本量（64）超过历史任何年份但完成 0~2 条，与"当年新提交尚未裁决"的时期效应混杂，**不能用它推断"该类漏洞不再被接受"**。
- 逻辑漏洞完成率最高（53%），其中"文档加密/只读限制被绕过"（15029、5575、11640、17182）与"客户端信任服务端校验"（24853）占多数，定级普遍偏低危/中危。

## DLL 劫持

### 劫持点定位（真实手法）

1. **Procmon 动态比对**：正常运行业务动作，过滤目标进程的 `LoadImage`/`CreateFile`，找 `NAME NOT FOUND` 后仍出现在加载结果里的同名模块。11913（词典产品）即按此路径发现 `dict.exe` 调用 `zlibwrap.dll`。
2. **导入表/导出转发静态读**：22813/22814/22816/22817 一族统一用"导出转发"描述——把 `crypt.dll` 导出用工具导出后转发到 `cryptOrg.dll`，再把恶意同名 DLL 放回安装目录，业务功能不受影响。这是本地攻击面里质量最高的形态，因为它同时满足"替换成功"和"用户无感"。
3. **调用栈回溯**：6026/6027/6028/6022/6031 都把"劫持发生时的栈"作为报告主体，并在修复建议里写"`LoadLibrary` 改用绝对路径"或"`SetDefaultDllDirectories`"。栈里的调用方模块名直接指出是哪个 exe 的哪个功能路径。
4. **离群模块审计**：1772/1484 这类老报告只写"安装目录 `addons` 下 `anchor.dll`"、"不再使用的 dll 文件仍在源码内加载"，属于"残留模块"型——即功能已废弃但仍在链接表内。

### 触发条件（四类，决定了判定）

| 模式 | 投递位置 | 触发动作 | 案例 |
|---|---|---|---|
| 文档同目录 | 与 poc 文档同一目录 | 双击文档 → 由 文字/表格/演示/PDF 组件打开 | 6027、6026、6025、6028、6022、1775 |
| 安装目录投放 | `appdir\`、`addons\`、`tools\` | 执行带特定参数的程序，或主程序启动时自动拉起 | 6031（`miscapp.exe -regoldinfo`）、1770（`pdfupdate.exe` 自动调用） |
| 启动即加载 | 安装目录 | 仅启动进程，无需任何业务动线 | 24264（`cloudsvc.exe` → `profapi.dll`）、24352（`appdir\crypt.dll`） |
| 服务/提权链 | SYSTEM 服务的可写目录 | 启动服务 | 9152、6078、6266、5447、5494 |
| 当前工作目录 | 受控 CWD | 任意启动方式 | 11784（标题即"CWD DLL 劫持"） |

关键判定点：**"需要管理员"在这批语料里基本不成立**。办公套件 Windows 版默认安装到 `%LOCALAPPDATA%\<Vendor>\<Product>`，24226 明确记录"普通用户对所有 办公套件 二进制拥有 FullControl，已在测试机通过 ACL 验证，无需 UAC 即可替换任意 DLL"。所以同目录 DLL 劫持的初始权限门槛是"普通用户"，真正的门槛在下面两条：

- **是否需要用户额外交互**：6027 的 poc 在打开文档后还要再点"文件 → 选项"才触发，交互链明显长于 6026（双击即弹）与 6028（关闭文档时触发）。三步与一步的区别，在同一子类里对应不同的定级与收录结果。
- **是否只影响自身上下文**：24227 自己写明"当前测试未证明远程触发或权限提升，主要描述为本地 DLL 搜索路径劫持"；24461 自己写明"未执行破坏性替换，不夸大为已完成真实攻击链"。这两条都主动降级了口径——说明报告自我降级与被忽略高度相关，但**因果方向无法从语料确认**。

### 为何是 42% 而非更高

可观察的相关性有三条，语料不能证明因果：

1. **时间窗效应最强**：2020 年批量 36 条完成，2025–2026 年 18 条 0 完成。同一产品、同类写法（crypt.dll 转发）在 2020 年可收、在 2025 年被忽略（22813–22817）。
2. **形态差异**：带"转发 + 无感运行 + 提权或持久化影响"的条目完成率明显高于"仅弹计算器"的条目。24264 与 24352 虽标注忽略，但正文都写到了 SYSTEM 上下文或全功能转发——说明**证据形态并非充分条件**。
3. **语料边界**：本切片只有标题、等级、状态与截断到 900 字的正文，**不含忽略原因字段**。因此"为什么这 53 条被忽略"在本语料内不可回答，只能记录为待核对项，不得在报告中引用为事实。

## 本地提权与权限绕过

被认可的证明方式，按证据链强度排序：

1. **服务 ACL 错配 + 二进制目录可写 + SYSTEM 上下文实证**（9152、6078、6266、5447、5494）。证据链固定为四段：`PsService64 -nobanner config <svc>` 显示 `BINARY_PATH_NAME` 与运行账户；`icacls` 显示 `Users` 对父目录可写；普通用户可 `sc start`；启动后恶意代码在 SYSTEM 上下文执行。9152 额外指出"该服务默认 `DEMAND_START`（非自动启动）"，因此必须证明"低权限用户能主动拉起"这一步，否则链条断开。
2. **安装/升级脚本以 root 执行 + 用户目录符号链接**（24770、12019、12091）。三种具体底座：`/var/lib/dpkg/info/office-suite.postinst` 遍历 `/home` 逐用户部署 desktop 文件且不检查符号链接；`~/.config/user-dirs.dirs` 注入命令在重装时以 root 执行；把 `/opt/vendor/.auth/license2.dat` 换成指向 `/etc/group` 的软链接，等权限被改成 666 后篡改 sudo 组。共同点是"root 进程信任用户可写路径"，而非某个二进制缺陷。
3. **命名管道 IPC 三缺陷叠加**（24769、24452、24576、24776、24416、24525）。可复用的检验点非常具体：管道安全描述符为 `D:NO_ACCESS_CONTROL`（`SetSecurityDescriptorDacl(sd, TRUE, NULL, FALSE)`）；请求头中调用方 PID 由客户端自填且未调用 `GetNamedPipeClientProcessId`；`OpenProcess(PID)` 失败后 `fail-open` 回退到 `GetCurrentProcess`（PID=0 即得 SYSTEM 令牌）；随后 `CreateProcessAsUserW` 执行请求方给出的任意命令行。24452 给出了 IDA 函数级证据（`sub_41C670`），并记录"`UseStrictValidationForIPCElevation` 注册表值不存在"这一使能条件。
4. **签名/完整性校验缺失导致任意文件覆盖**（22970）：`reportsvc.dll` 可由 `writer.exe Run` 调用，`-upoffice` 参数把 `files\appdir\` 下任意文件复制进安装目录覆盖，且不校验数字签名与 hash。
5. **macOS TCC 越权**（11464、11465、11466）：`launchctl unload -w com.<vendor>.loader.plist` 触发重载，plist 指向 `/tmp/*.dylib`；在 SIP on、M1、最新版条件下取得麦克风录音、摄像头偷录、屏幕截图、下载目录读取。根因写在修复建议里——"上传 App Store 的版本未启用 hardened runtime"。
6. **沙箱绕过**（12809）：JS 宏 `Application.Run` 调 VBA 函数绕过 JS 引擎保护，再经 `kernel32` 的 `VirtualAlloc`/`RtlMoveMemory`/`CreateThread` 建线程，双层绕过 办公套件 沙箱与 Defender。

证明强度的分界线：**"能弹 calc" 不等于"完成提权"**。被认可的条目都同时给到"起点身份"与"终点身份"（普通用户 → SYSTEM / root / TCC 已授权能力），并留下可复核的所有者字段或进程树。

## 客户端信息泄露与本地逻辑

- **调试输出泄露秘密**（6127）：拆分/合并加密 PDF 时把编辑密码经 `OutputDebugStringW` 打出，任意本地进程用 DebugView 即可读取；报告附带 `kb` 栈回溯定位到 `kp2wapp` 的 `getPluginDESKey` 路径。这是最容易被忽略、成本最低的一类。
- **TLS 校验缺失导致内容外泄**（17108）：上传云盘时不校验证书有效性，接受自签证书；攻击者 `create_ap` 建热点 + `iptables` 重定向 80/443 → mitmproxy，取得完整 pptx 内容。写这类报告必须同时交代"受害人的操作"与"攻击者网络位置"，否则会被当成普通 MITM。
- **本地 IPC 返回会话凭证**（24776）：`ipc.dll` 的 `getLoginInfo` 明文返回 `app_sid`，`\\.\pipe\_Thrift_IPC_Administrator` 的 DACL 为 `Everyone: FULL_CONTROL`。影响描述到"无需密码与短信即可接管云账号"，比"管道可连"高一个层级。
- **文档格式侧读取**（22915 XXE、12713 路径穿越、24710 XXE+SSRF、24530 越界读、24485 EML 自动加载远程资源、24500 DOCX 自动加载外部图片）。共同点是"打开文件即发起出站请求"，可作为 0-click 泄露链的起点。
- **硬编码密钥族**（24525、24224、24852、24967）：`24525` 的 Linux 更新 socket 用硬编码 AES-128 密钥解密命令后直接 `QProcess::execute()`，且 `/tmp/updatesvc` 权限 `srwxrwxrwx`；密钥字节记为 `<redacted>`。`24967` 是签名体系内嵌 RSA 私钥可伪造插件签名。两者都属"设计层信任"，比单点内存破坏更值得优先验证。
- **URL 协议与浏览器桥**（24461 记录 HKCU 下 12 个 `office*` URL Protocol 全指向 `launcher.exe`；24226 记录 `runhost.bat` 作为 3 个 Chrome 扩展的原生消息宿主，命令含 `%*` 未过滤转发给 `writer.exe`）。协议注册项与原生消息宿主是本地攻击面的稳定入口清单。
- **客户端逻辑**：15029/5575/11640 一族证明"只读/不可复制"限制可由划词翻译、拖出新窗口再复制等方式绕过；24853 证明付费功能校验纯客户端信任，中间人改写响应即免费使用；24878/24972 属"补丁不完整 / 基线 CVE 仍落在受影响区间"。

## 高频被忽略模式

以下模式在本语料中出现频率高、且多为已忽略状态。**声明证据边界：切片不含忽略原因字段，故此处只描述"被忽略案例的形态",不推断具体否决理由。**

1. 单点同目录 DLL 劫持：无转发、无提权、无远程，仅"同名 DLL 被加载"（2024–2026 年集中出现，如 23909、24227、24352）。
2. 需多步交互才触发：打开文档后还要再点菜单项（6027 形态）。
3. 报告自述未闭环：明确写"未破坏性替换""不声明为 RCE 或提权"（24461、24227）。
4. 仅 marker/弹窗，无影响延展。
5. 与既有 CVE 或旧补丁相关：`CVE-2018-6400` 不完整修复（24878）、2015/2016 基线（24972）、`CVE-2025-2783`（22823）。
6. 纯客户端信任付费/权限校验，中间人改响应即绕过（24853、23664、11194、11159）。
7. 文档限制解除类：强制解除编辑限制（24391）、VBA 密码破解（24392）、PDF 转图不受加密影响（17182）。
8. 硬编码密钥/自签证书类重复提交（24224、24852、24967、24971）。
9. 只影响自身流量的 MITM（5363 与 17108 的差异即在此）。
10. AI/Agent 侧间接注入与数据外带（23878、23889）——与本地二进制无关，属另一归口。

## 可复用检查清单

1. 记录产品版本、安装包 SHA256、OS 版本与位数、SIP/UAC 状态、安装路径是否被手动指定（5494、5447 明确"仅手动指定目录时成立"）。
2. 先判安装根目录 ACL：默认 `%LOCALAPPDATA%` 安装意味着"无需管理员"，这一点要实测 `icacls` 而不是假设。
3. 枚举本地 SYSTEM/root 服务，逐条核对 `BINARY_PATH_NAME`、运行账户、启动类型、服务 DACL、二进制父目录可写性五项。
4. 对每个服务检查"普通用户能否 start/stop"；`DEMAND_START` 服务必须额外证明可被低权限拉起。
5. 枚举命名管道：安全描述符是否为 `D:NO_ACCESS_CONTROL` 或含 `Everyone` ACE；是否导入 `GetNamedPipeClientProcessId`。
6. 检查 IPC 请求头中身份字段是否由客户端自填，以及错误分支是否 `fail-open`（`OpenProcess` 失败回退 `GetCurrentProcess`）。
7. 检查安装/升级脚本：是否以 root 遍历用户目录、是否降权、是否检查符号链接（`postinst`、`user-dirs.dirs`、`.auth` 目录）。
8. 用 Procmon 对目标进程做一次完整业务动线的模块加载比对，优先保留"被加载但构建时缺失"的模块。
9. 优先做导出转发型 DLL（改名原 DLL 为 `*Org.dll`），以"业务功能无异常"证明隐蔽性。
10. 检查 `HKCU` 下 URL Protocol 注册项与浏览器原生消息宿主脚本，看是否存在未过滤的 `%*` 转发。
11. 检查更新链路：是否明文 HTTP、签名算法（MD5 vs RSA/X.509）、是否校验目标文件 hash 与签名（24226、22970）。
12. 检查客户端 TLS 校验开关：对云盘上传、登录、更新三类流量分别验证自签证书是否被接受。
13. 抓调试输出：对加密文档的拆分/合并/打印动作挂 DebugView，检查是否泄露口令或密钥。
14. 检查硬编码密钥与私钥（`.rodata` 静态字节、插件签名根），并说明"任何可读二进制的用户即可提取"。
15. 每条提权链都产出"起点身份 → 终点身份"的成对证据（whoami / 进程所有者 / 令牌），并附进程树或替换前后文件对比。
16. 报告按"已验证事实 / 未执行的替换链 / 待厂商复核边界"三段写，避免把推测写成闭环。

## 相对现有文档的增量点

现有 `references/by-type/desktop-client.md` 是 4 行表格的条件实验设计（localhost 服务与 IPC / 更新器与高权限 helper / WebView 与桥接 / 通信账户设备），核心原则是"记录初始权限""本地监听不等于互联网暴露""已能改介质后执行同代码不自动获得新边界"。本语料带来的增量：

1. **可判定的 ACL 双条件**：现有只写"跟随输入到验证与高权限操作"。语料给出两个必须分别取证的检查点——服务启停权限、服务二进制父目录写权限——并证明缺一即链条不成立（9152 的 `DEMAND_START` 说明）。
2. **IPC 缺陷的具体假设集**：现有只写"来源/身份/消息校验"。语料把它拆成 NULL DACL、自报 PID、`fail-open` 回退、危险能力直达、严格校验开关默认可选五个可独立检验的缺陷。
3. **修正"需要管理员"的直觉**：现有文档未区分安装位置。语料实证默认装到用户可写目录，同目录 DLL 劫持的初始门槛是普通用户（24226 ACL 验证；24352 亦如此声明）。
4. **"文档同目录"作为独立投递原语**：现有把文件解析与更新器混谈，未把"恶意 DLL 放在受害者会双击的文档旁"列为独立一类，而这正是本语料最大的投递面。
5. **导出转发作为首选验证形态**：现有未提。语料显示"转发全部导出 + 业务无异常"是质量最高、也最难被驳回的写法。
6. **时间窗视角**：现有文档无历史分布。语料给出 2020 年收 61% → 2024 年 17% → 2025/2026 年 0% 的衰减曲线，可用于在选题阶段判断某形态是否已有大量存量。
7. **证据形态清单**：现有只有"版本/OS、调用链/截图、PoC、初始与最终权限、视频"一句。语料补出栈回溯、Procmon `NAME NOT FOUND`、服务 `config` 输出、`icacls`、进程树、替换前后文件大小、marker 文件、管道安全描述符八种具体载体。
8. **报告范式**：现有无。语料中 24461 提供"已验证事实 / 未执行链 / 待复核边界"三段式，可直接作为本地攻击面报告模板。
9. **Linux 与 macOS 分支**：现有标题仅 Windows/macOS。语料给出 Linux `postinst` root 执行 + 用户目录软链接（24770、12019、12091）与 macOS `launchctl` plist 重载指向 `/tmp` dylib 的 TCC 越权（11464/11465/11466）两套具体手法。
10. **补丁/基线视角**：现有无。语料出现"旧 CVE 修复不完整""基线版本仍落在受影响区间"两类线索（24878、24972），可作为存量复测的入口。
11. **证据边界声明**：现有文档未声明"语料不含忽略原因"。本切片 138 条已忽略条目只有标题与状态，任何关于否决理由的陈述都缺证据支撑，必须在引用时显式标注。
