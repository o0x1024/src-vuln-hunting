## 真实注入点清单

1. **文件名 / 文件夹名 / 重命名（网盘类元数据）**
   功能位置：`d.example.com/api/folder/new?foldername=`、`/api/folder/rename`、`banber/templates.example.com/folder/create_folder`、`s.example.com/api/index/updateFile`。
   载荷与绕过：名称字段直接落 HTML，无需协议绕过；`<img src=x onerror=...>` 即可。老站无 CSP，页面框架为同源直出。
   影响为何成立：目录列表、侧栏、分享页都会渲染该名称，同目录协作者打开即执行；2019 年直接命中后台管理员会话。
   案例：1723、1968、2497（旁证：1508 打到后台管理员 cookie）。

2. **单据/资料的备注与名称（进销存、CRM 等业务后台）**
   功能位置：`ecdn.example.com` 销售订单/采购订单/收款单"单据备注"、`crm.example.com` 客户价格体系备注、职员/仓库/账户姓名。
   载荷与绕过：该处过滤了尖括号关键词但**未覆盖全部 on 事件**——`<button/onfocus=alert(218)>`（7988）、`<x onclick=alert(15)>click</x>`（9324）。思路是拿被拦的 `onerror` 换 `onfocus`/`onmouseenter`/`onmouseleave`。
   影响为何成立：备注在列表行内渲染，任何能看这张单据的同事、上级、财务都会中；采购/资金流是强横向移动面。
   案例：7988、9324、7459。

3. **标签 / 分类 / 筛选条件的"名称"（配置型元数据）**
   功能位置：CRM 知识库"新增标签"`identityName`、提醒中心"提醒分类"`className`、校本资源库"更多筛选"条件名。
   载荷与绕过：`<img/src=1 onmouseenter=alert\`6\`>`（反引号当括号用，10331）、`<d3v/onmouseleave=[4].some(confirm)>click`（10074）、文本类型筛选名直填（23864）。
   影响为何成立：分类名会进下拉框与筛选器，由他人主动选择时执行；改一处元数据即覆盖多个列表页，比逐条内容更省事。
   案例：10331、10074、23864。

4. **思维导图 / 流程图"插入链接"**
   功能位置：`diagram.example.com/docapi/diagraming/canvas/msg`、在线文档思维导图链接节点。
   载荷与绕过：链接 URL 字段未做协议白名单与属性编码，href 直出；试 `javascript:`、`" onmouseover=`、`x" autofocus onfocus=`。
   影响为何成立：图形被分享/协作打开时渲染；PC 客户端内嵌 webview 与 web 端同一数据，命中面翻倍。
   案例：23085、6555、6865。

5. **群聊"自定义页面"/书签（协作套件）**
   功能位置：`oa.example.com/api/v1/chats/{id}/bookmarks`，群主/管理员写入，群成员消费。
   载荷与绕过：自定义页面 URL + 标题；23871 修复后 24322 用同一接口的新编码变体再次成功——**修复是按点打补丁**。
   影响为何成立：群内全员可见，点开即执行；一个高活跃群等于一次批量投递。
   案例：23871、24322。

6. **企业管理后台写入、普通员工消费（宣传栏/推荐应用/工作台小组件）**
   功能位置：`oa.example.com/admin/api/v2/suite/workspace/banner`、`.../recommend_apps/rules`、`open-admin.example.com/admin/v1/workbench_block/...`。
   载荷与绕过：banner 图片链接、推荐应用"添加链接"URL、工作台图文块内容；先用 `https://qq.com` 之类定位串在 BP 历史里找字段，再替换。
   影响为何成立：方向是**管理员写入 → 全员工作台渲染**，受害者是被动的普通员工，不需要社工管理员去点别人的内容，链路比"用户写→管理员看"更稳定。
   案例：23143、23874、23952。

7. **日历日程 / 待办标题（含免同意拉人）**
   功能位置：`calendar.example.com` 日程标题、待办"新建待办-标题"、`oa.example.com/api/v2/3rd/todos` 附件。
   载荷与绕过：标题字段直填；配合可枚举的 userid 把任意 办公套件 协作用户拉为参与人（23885），无需对方同意。
   影响为何成立：日历/待办是高频首屏，被拉入者在自己的列表里直接渲染，属语料中的高危档（13008、13009）。
   案例：13008、13009、23885。

8. **审批单 / 云文档附件引用**
   功能位置：`app-oa.example.com/api/v3/workflow/approval_instances`、合同审批附件、轻审批指定审批人。
   载荷与绕过：附件选"云文档"后改附件名/链接字段；审批人可被指定为任意协作用户（23886）。
   影响为何成立：审批人通常是财务/法务/主管，打开即中；与"可指定任意审批人"组合，把只能自看的字段变成定向投递。
   案例：23886、9513。

9. **服务台 / 工单 / 客服机器人（前后台双渲染面）**
   功能位置：`oa.example.com/api/v1/chats/{id}/messages`（工单消息）、服务台"推送详情"按钮、数据看板"满意度调查/评价与反馈"。
   载荷与绕过：同一字段在客服前台与 `work.example.com` 管理后台各渲染一次，两处都要试；按钮/链接类组件优先。
   影响为何成立：客服与后台管理员看到同一份数据，命中角色多；机器人消息等价于群发。
   案例：23888、23967、23891。

10. **开放平台开发者后台（自动回复 / 自定义菜单 / 消息群发）**
    功能位置：`open-admin.example.com` 开发者后台自动回复、自定义菜单、`/admin/api/v1/open/apps/{appid}/messages`、`assign/drafts`。
    载荷与绕过：自动回复文本、菜单 URL、消息 card；注意 URL 上的 appid 必须是**攻击者自己应用**的，再通过"成员管理"把受害者加成应用管理员。
    影响为何成立：消息按可见范围推到群或指定成员，受害者在协作客户端内直接渲染。
    案例：7392、23957、24723。

11. **邮件（插入超链接 / 签名 / 草稿）**
    功能位置：`mail.example.com/api/v4/mail/send` 正文超链接、`/api/v3/mail_setting/sign`、`/api/v1/mail/draft`。
    载荷与绕过：三处都是富文本落地，`href` 与签名 HTML 各自没有统一过滤；草稿箱是"未发送也能存"的落地点。
    影响为何成立：公共邮箱多人共用，一封邮件命中整个小组；草稿/签名是长期驻留，重复触发。
    案例：23251、23252、23254。

12. **上传点：SVG / HTML 后缀 / Content-Type 欺骗（文档与设计类主战场）**
    功能位置：海报素材与背景上传、开放平台插件图标 `?is_avatar=1`、模板举报附件、`project.example.com/files/fileInfo/upload`。
    载荷与绕过：`<svg xmlns=...><script>alert()</script></svg>` 直传（11420/11421）；改后缀为 `.html` 被成功解析（7280）；PNG 内容但服务端按 `Content-Type: text/html` 回源（9306）；插件图标传 html（23367）。
    影响为何成立：文件域与主域同源时直接拿到会话；不同源则退化为"官方域名托管任意页面"的钓鱼/挂马面（24830 的边界表述、24840）。
    案例：11420、23367、9306。

13. **头像 / 图片上传（个人资料面）**
    功能位置：词典产品上传头像、上传图像、海报 AI 设计上传图片、便签图片上传。
    载荷与绕过：优先 SVG；退化为"头像 URL 被拼进 `<img src>`"时试 `" onerror=`；或改 content_type。
    影响为何成立：头像会出现在成员列表、评论、分享卡片，属于"被动高曝光"字段。
    案例：17009、10211、23644。

14. **全局搜索 / 全文解析结果（二次渲染）**
    功能位置：云文档"搜索解析全文"结果页、好友列表搜索。
    载荷与绕过：内容里预埋 payload，等解析器把命中片段当 HTML 拼回；关键词高亮是最容易漏编码的拼接点。
    影响为何成立：受害者无需打开原文档，只要搜到关键词就执行，属高危档（23683）。
    案例：23683、12687。

15. **表单 / 轻应用设计器（配置即代码）**
    功能位置：`test-tenant.example.net` 表单 `name`、多维表格字段默认值、轻应用"表单设计-上传附件"、`lightapp.example.com/f/{appid}/form`。
    载荷与绕过：`%` 之类字符先做定位（11523 明确提醒"这个 % 很重要"）；字段默认值 `<input onfocus="alert(document.cookie);" autofocus />` 免交互（23086）；附件上传点单独测（12739）。
    影响为何成立：设计器写的是**模板**，所有填表人/查看表格的人都会渲染；一处配置覆盖全体使用者。
    案例：11523、23086、22984。

16. **JSONP callback / postMessage / 落地页参数（DOM 面）**
    功能位置：`open.example.com/previous/enterprise-entry?callback=`、`account.example.com/login` 的 message 监听、`www.example.org/public/app/landingPage` 的 `dpl` 参数、AI 简历编辑器跨页消息。
    载荷与绕过：`?callback=javascript:alert(document.cookie);`（16993）；postMessage 未校验 origin + innerHTML sink，用 iframe + 构造 `{status:"success",result:"..."}` 触发（10474）；landing page 的 base64/JSON 参数解出 `javascript:` 后进自建 iframe（24840）。
    影响为何成立：不需要受害者交互即可跨页接管（24607 的 0 点击表述）；同源 iframe 内执行等于拿到该域身份，不必偷 Cookie。
    案例：16993、10474、24607。

17. **反馈 / 举报 / 附件对象的 url 字段**
    功能位置：`get.example.com/feedback/api/v2/submit/` 的 `attachments[].url`、意见反馈 `product_name`、举报附件落点。
    载荷与绕过：JSON 里把 `url` 直接换成 `javascript:alert(document.cookie)`（22897，附件仍填合法 pdf 名以过校验）；`product_name` 二次渲染未过滤（5555）。
    影响为何成立：反馈列表在内部后台/客服端展示，点附件即执行；字段语义是"URL"但被当 href 直用。
    案例：22897、5555、9306。

## 富文本/文档/分享场景专项（编辑器过滤绕过、文档预览、分享链接、评论与昵称等）

- **编辑器过滤的真实强度在前端，不在后端**：10298 明确写"前端对 xss 语句进行过滤，但是后端未进行过滤，修改数据包…成功解析"。所以编辑器里打不进去时，先抓保存包再改，不要在 UI 里硬碰。
- **黑名单只挡了最常见的几个词**：语料的绕过全部落在"换事件名/换标签/换引号"上——`onfocus`（7988）、`onclick`（9324）、`onmouseenter` 反引号（10331）、`onmouseleave`+`some(confirm)`（10074）、`<svg onload>`（16974）、`<button/>` 自闭合配 `autofocus` 免交互（7988、23086）。
- **编码层绕过**：十进制实体 `&#106;&#97;&#118;...` 拼出 `javascript:` 过词表（23154）；属性引号逃逸仍是主要手段，语料里同一接口常有"标题能过、URL 不能过"的不一致。
- **修复复测要换同族参数**：7453–7459 是对同一产品七个字段的"修复绕过"连发；24322 是 23871 的 bypass。说明修复按字段打补丁，**复测必须回到同一 sink 的其他入口**，而不是原 URL。
- **文档预览与分享**：12895（文档分享）、23272（附件 `linkUrl` 换 `javascript:`）、24840（落地页 `dpl` → iframe `javascript:`）、23646/23647（`docs.example.com` / `sg.docs.example.com` 代码注入，高危）、23322/23423（国际云文档"在野利用"，严重）。分享型漏洞的成立点是"接收者点开即渲染"，因此报告要把"谁打开、在哪个域、什么角色"写全。
- **评论、昵称与文档类特有面**：2252（智能写作评论）、10918（WebOffice 社区评论）、10996/10997（AirSheet 提问/回答）、9529/10072（CRM 姓名）、9901（主播卡片姓名）、1997（docs/contact）——昵称类字段的特点是"别人看不到内容、但一定会看到你"。此外 23683（搜索解析全文，高危）与 1981（上传 Excel 数据简报，可在 QQ 群社工）说明文档产品的 XSS 面不止"正文"，还包括解析器、导入器、检索索引。

## 证据形态（被判定完成的报告怎么证明执行）

- **通用四段式**：`# 详细说明`（一句话功能点 + 完整 URL）→ `# 漏洞证明`（编号步骤，每步一张截图）→ 原始请求包（含测试号 Cookie，务必替换为 `<redacted>`）→ 触发点截图。42 条已完成样本几乎都是这个结构（23085、23143、23871 最典型）。
- **"执行"的证明方式**：`alert(document.cookie)` 或 `alert(<随机数>)` 的弹窗截图；免交互场景用 `autofocus`+`onfocus` 让截图里没有鼠标（23086）；DOM 场景给 source→sink 或 PoC 页面（10474 用 Burp DOM Invader 生成 iframe PoC）。
- **"影响"的证明方式**：账号被盗链路写成"受害角色 → 打开哪个页面 → 执行后能读什么"。1508/1598/1654 直接写"打到后台管理员 cookie"；1570 写"可获取所有浏览该活动用户的 cookie"。
- **量化写法（值得抄）**：24840 用实测字节数与键数描述影响——"533 字节 Cookie、139 个 localStorage 键""同源请求 200、105071 字节业务数据"，并显式声明做不到的部分（"没能覆盖桶里别人的对象…这条伤害不成立，不作为主张"）；虽被忽略，但其证据与边界表述质量是语料最高的。语料**未提供**浏览器/版本、CSP 记录、跨账号一致性、修复前后对照，引用时不要假设已证明。

## 高频被忽略模式（并声明语料不含忽略原因这一证据边界）

**证据边界**：切片每条只含标题、类型、等级、状态与少量正文，**没有"忽略原因"字段**。以下是从"同产品同字段、不同状态"的对照中归纳的可观测特征，属假设级线索，不能当作平台收录规则使用。

1. 在 SRC/安全中心自身站点发现（5105、6416、6538、6602、23176、23410、23409，共 7 条全为忽略）。这些目标是安全平台本身，与主营产品的影响面不同。
2. 纯占位内容（6418、6419、6789 标题就是 `test`；23637 标题为"测试"）。先自查标题是否说明了"谁受影响"。
3. 同根因拆分或打包（6252–6256 连续五条 edutest 逐个提交；10071–10088 CRM 十余个字段分别提交）。批量提交前先确认是否已被判为同一 sink。
4. 上传点批量铺开（22957–22964 八连、12658–12661、12731–12733、22987–22992）。同一上传组件在不同业务模块复用时，第二条起极可能撞重复。
5. 与已完成案例同产品同字段（6693 vs 1496/1508；7278 vs 9679；10330 vs 10080；10331 vs 10079；10033 vs 10032；24751 vs 22923；10470 vs 10474）。高度疑似"重复"或"修复后未复现"。
6. 需要自交互才算触发（依赖本人点自己写入的内容）。与 skill 现有判定一致：Self-XSS 不计。
7. 同一 URL 的"其他功能点"补充件（17086 对 17085、23069 对 23085、23741/23744 同标题两条）多为补充信息而非独立漏洞。

## 可复用检查清单

1. 先用唯一无害标记（如 `xssmark`）走一遍正常写入，确认字段落在 HTML 文本、属性、JS 字符串还是 DOM sink，再决定载荷形态。
2. 优先扫"名称型元数据"：文件名、文件夹名、标签名、分类名、筛选条件名、角色名、模板名、字段名、单据名。语料里这一类占多数且最易复用。
3. 同一产品只测一个字段就停是浪费：拿到一个 sink 后横向枚举同模块其他"名称/备注/标题"字段，但**提交时合并成一条**，避免被判拆分；提交前再查是否有同产品同字段的已完成案例、标题是否说清"谁受影响"。
4. 编辑器/富文本先在前端试，失败立刻转抓包改 body；前端过滤不代表后端过滤（10298）。
5. 事件处理器黑名单绕过顺序：`onerror` → `onfocus`+`autofocus` → `onmouseenter/onmouseleave` → `onanimationstart` → `<svg onload>`；每个都要配对应触发动作的截图。
6. 协议型 sink（href/src/callback/url 字段）先试 `javascript:`，再试十进制/十六进制实体编码，再试 `data:text/html`。
7. 上传点分三步判：能否传 `.svg/.html`；回源 `Content-Type` 是什么；文件域与主域是否同源。三者决定是"直接拿会话"还是"只能托管钓鱼页"。
8. 有"分享/协作/拉人"能力的功能（群、日历、待办、审批、附件）务必测"能否把受害者拉进来"，这决定了漏洞是"等他来"还是"送到他面前"。
9. 管理后台写入、前台消费的字段（banner、推荐位、公告、工作台组件）优先于用户侧字段，因为受害者是被动打开。
10. DOM 面单独走一遍：`postMessage`（origin 校验 + sink）、JSONP `callback`、落地页 base64/JSON 参数、`location.hash` 进 innerHTML。仅凭静态搜索到 `innerHTML` 不算证据。
11. 每个疑点都写反例条件：若该字段在输出前被 `textContent`/实体编码、或页面有有效 CSP、或 sink 不可达，就记"该条件下未复现"，不要升级成漏洞。
12. 报告固定四段：功能点+URL / 编号步骤+截图 / 原始请求包（`<redacted>`）/ 触发截图 + 受害角色说明。
13. 声称影响前先量化：能读到哪些字段、多少条、哪个账号身份；做不到的边界要写明（参照 24840 的写法）。
14. 修复后复测走"同族参数 + 同 sink 其他入口"，不要只重放原 URL（7453–7459、24322 的教训）。

## 相对现有文档（references/by-type/xss.md）的增量点

现有文档已覆盖且本文件不重复的部分：唯一无害标记定位输出上下文、source→sink 浏览器核对、存储型"写入—存储—触发"三链、CSP/沙箱/Trusted Types 记入结果、Self-XSS 与仅本人可控的排除、postMessage/clobbering 转 `dom-messaging.md`、报告必填字段。

本文新增可并入的点：
1. **注入点目录化**：现有文档只举例"搜索/评论/昵称/上传内容"，缺"名称型元数据"这一大类（文件名、标签名、筛选条件名、角色名、模板名、字段名、单据名）。语料显示这是最高产的一类，建议在"最小实验"前加一节注入点枚举清单。
2. **"管理员写入 → 全员消费"作为独立链路**：现有文档只在调研补充里提到"入口/渲染面差异"（H1 #192210）。语料 23143/23874/23952/23957 显示反方向更稳定，且不需要社工管理员，建议写成与"用户写→管理员看"并列的第二条链。
3. **修复复测策略与批量提交边界缺失**：现有文档无复测章节。7453–7459（七字段连发）与 24322（对 23871 的 bypass）证明修复按点打补丁，应加"复测回到同 sink 其他入口"；同 sink 多字段须合并为一条、同上传组件跨模块不重复交（22957–22964、6252–6256 被忽略最集中）。
4. **上传→XSS 的三层成立条件**：同源直出 HTML（9306）、SVG 以 `image/svg+xml` 回源（11420、24460）、跨源仅能托管钓鱼页（24830、24840）。现有文档只在"导出消费者"一句带过，建议独立成段并给出判定顺序。
5. **DOM 面证据要求细化**：postMessage 需同时证明 origin 校验缺失与 sink（10474、24607、24943）；JSONP 需证明 `javascript:` 进了 script src（16993）；落地页需证明参数解码后进 iframe（24840）。现有文档只说"保存浏览器运行证据"，粒度过粗。
6. **等级锚点**：语料给出可参考的落档——需协作/点开为多为中危（327/450 存储型）；免交互或落在资金/审批/全文检索为高危（13008、13009、23683）；在野利用或 XSS→RCE 为严重（23322、12659）。可作为"类型名称不决定等级"的实证补充。
7. **证据形态模板与量化写法**：四段式报告结构 + 24840 的字节数/键数/边界声明写法，可并入 `reporting.md` 交叉引用。
8. **忽略模式的可观测特征**：7 条特征（含 SRC 自身站点、占位测试、拆分提交、上传点批量、同字段重复）可减少无效提交；须同时标注"语料不含忽略原因"这一证据边界，避免被当成规则。
