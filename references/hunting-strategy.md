# 项目选题与探索决策

在广度覆盖、业务深挖、重新分配预算或处理研究线索时读取。目标是在约定成本内增加独立、可复现、符合项目规则的发现；候选数量、链条长度和载荷数量不是产出。用户指定业务时在该业务内排序，不自行转到另一项目。

## 先判断是否值得投入

复用当前项目规则和发现记录，按需补齐一份简短选题记录：

| 因素 | 决策用途 |
|---|---|
| 资格与范围 | 项目是否开放、是否需预报名、活动窗口、业务/地区/版本/环境限制；资格影响奖金或收录，不自动等于缺少测试授权，两者分别判断 |
| 可用条件 | 能取得的普通角色、第二身份、受控资源、客户端版本、实际工具与动作额度；缺条件记录获取成本，不伪装已有能力 |
| 业务与变化 | 权限边界、付费能力、异步处理、新功能/部署/修复差异及其来源；新资产只是调查信号，不能据此声称低竞争或高收益 |
| 已有积累 | 本项目已确认事实、历史覆盖、可复用正常流程、已知问题与修复状态；外部重复情况不可见时保留未知 |
| 下一步价值 | 哪个未知会改变判断、一次实验的成本/副作用、结果如何影响继续或停止；奖金和漏洞名不能代替此判断 |

同等条件下优先可达到的边界、较强线索和可复用流程。允许为未知入口、业务规则和研究启发预留探索份额，不要求先估出严重度。排序用证据和简短理由；不编造命中概率、奖金预测或重复率。

## 分阶段使用门槛

1. **启动**：先核对资格、范围和动作许可，辨明当前项目明确排除项。规则未知只阻塞依赖它的判断。纯信息收集仍按自身交付范围执行。
2. **探索**：正常流程、数据流、部署变化或可靠研究提供了具体依据，即可提出待验证解释；写清未知、区分性实验和停止条件。影响可以尚未建立，不因暂时不能证明高危而淘汰。
3. **验证**：先验证入口/解释是否成立，再补真实攻击前提、边界与业务结果。证据不足的假设保留 needs_evidence；被反例否定的本次条件记录 not_reproduced。明确排除且没有可信新增影响或规则例外时停止投入。
4. **交付**：达到 [影响与收录](impact-and-acceptance.md) 的 ready 门槛即整理独立报告；不为延长链条扣住成熟成果，也不以不完整提交抢占时间。外部提交遵循已有提交授权。

## 有依据的发散与组合

从当前事实选择可能改变结论的邻近方向，例如同一对象的列表/导出/异步消费者、角色撤销前后、客户端与服务端校验差异、修复前后共享路径。它们是可选推导方向，不是必须全排列的清单。每个新候选只需短记“事实引用 → 未知关系 → 下一步及其两类结果 → 继续/停止条件”；选入实际验证后再补全实验记录。

组合线索时逐边写清：已有能力与证据、它能提供给下一步的输入/身份/资源、尚未证明的连接、允许的最小验证。下一步必须真正消费上一步输出；同域名、两处现象共存或历史文章中的箭头都不证明可组合。各边的目标和动作独立满足授权；不能借组合升级到生产秘密使用、内网访问或资源接管。

优先执行能区分两种解释的实验。失败后根据新证据修订一处前提或换方向；仅换编码、关键词、标题或理论终点不算新增依据。分支数量与深度由剩余共享预算及信息增量控制；有界多步实验可作为一个实验单元，不要求每轮只发一个请求或只能研究单个状态边。

遇到不易解释的差异时，按 [专家式推理](expert-reasoning.md) 建立能预测结果的小模型，选择能区分解释的观察；共用机制的迁移要保留关键差异，不能按相似名称复制结论。

## 投入与停止

明确区分四种情况：项目/用户禁止；动作已授权且条件具备；工具/身份/预算缺失；证据已充分或继续无价值。只暂停依赖缺失条件的分支，不把工具缺失写成禁止，也不为解除禁止换工具。

先统计无效会话、签名失效、重复基线、工具自动重试消耗，再决定是否需要更多预算。现有总上限内可按证据调整各阶段份额并记录；没有足够上限时按 [预算规则](scope-and-rules.md) 交付缺口，不通过拆假设、换工具或重启续额度。有限预算下可先做无副作用预检；不要发出无法承担状态核对和清理成本的变更。

成熟发现与未完成探索分别交付。已有材料或独立获准、低成本实验可能揭示新的实质影响时，可以另立分支继续；不能扩大真实数据获取来追级。复盘按独立根因、有效报告、首份合格报告耗时、无效请求和补证成本评价，并保留未测范围；没有真实回执就没有平台接受率。
