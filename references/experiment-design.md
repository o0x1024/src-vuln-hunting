# 可复用实验、会话与业务判定

涉及登录后重放、状态流程、多个角色或组合验证时读取。这是宿主适配的行为契约，不表示本 skill 已提供执行器；只用当前真实可用的工具能力，缺失时按 [工具契约](tool-contracts.md) 降级。

## 真实攻击前提

区分实验准备者、攻击身份、受影响身份。准备者可以在既有许可内创建两租户样例或配置测试条件；攻击步骤只能使用声明的攻击身份能实际获得的权限、ID、令牌和资源。逐项记录来源及证据：普通注册/合法邀请、正常公开入口、独立已证明的前置缺陷，或仅由测试准备者提供。

受害者动作需注明是否正常可达，以及点击、登录、审批、安装或特殊设置条件。管理员复制秘密给低权限账号、关闭防护、调试构建特权、仅本地修改响应都不能隐去。用 B 的私有 ID 验证 A 的对象授权可证明已知 ID 条件下的缺陷；若现实中 ID 的获得方式未知，就明确这一利用限制，不自动否定边界缺陷，也不声称任意接管。部署版本/配置未知不能用本地 PoC 补成事实。

## 从正常流程生成实验单元

保留可复用请求模板和依赖关系：前置步骤 → 资源/动态值 → 核心操作 → 权威结果读取 → 允许的清理。每个模板保留方法、精确 URL/编码、参数位置/重复项、Content-Type、会话引用、动态值来源和作用域。不要把一次成功 HAR 当成永久可重放脚本。

- Cookie、CSRF、nonce、签名、时间戳和对象 ID 按身份/会话/资源隔离；派生签名在修改业务字段后由已知合法机制重新生成。只会重算签名并不证明越权。
- 执行前做最小身份/资源有效性核对；未变化且仍有效的基线可复用。401、登录页、过期 nonce 或签名错误先修复依赖，不算目标阴性。刷新授权与额度沿用现有边界；恢复失败不反复登录。
- 多步骤流程有界执行，标明每步输入来自何处和失败后能否继续。写操作前登记意图/幂等标识，结果未知先查状态，不能重跑整个流程。
- 保存模板与每次实际请求的关联；凭据使用受控引用，原始证据与脱敏比较视图分开。不要将未经核实的动态提取表达式当作已成功取值。

## 一次实验如何产生可信结论

先写预期规则、实验变量、正常对照、支持结果、反例和结果观察窗口。一次只改变一个解释因素通常更易归因；若必须组合改变，注明无法区分的因素并设计必要对照，不机械限制多步骤业务。

结果判定渠道先用已有正常证据或获准普通标记核对是否可见、是否到达预定处理步骤。多种解释竞争时，按 [专家式推理](expert-reasoning.md) 选择预测结果不同的对照；观测失效不能记作漏洞阴性。

响应比较分层进行：传输/HTTP → 应用错误与语义字段 → 实际身份和资源归属 → 权威业务终态。时间戳、随机 ID、排序等噪声仅在独立比较视图归一化；不删除权限、金额、所有者、签名或原始字节证据。状态码/长度差异只定位问题，业务成功需要真实结果。

异步场景保存 operation/job/trace ID 与对象标记；在已授权的窗口/次数内查询权威状态，区分 queued、completed、failed 和未知。超时或尚未入账是待确认，不是成功或失败；旧缓存、上轮资源和别的身份产生的结果不能归因给本轮。

解析/输入变体以正常流量、文档、错误或本地代码提供的机制线索为依据。支持格式未知时，可以在已授权的低副作用动作上，用小型普通标记验证支持与否；再判断是否进入同一业务语义。415、忽略字段、空成功和落入另一功能分别记录。不要要求“已知支持”才能发现支持情况，也不无依据排列全部编码/媒体类型。

连续探索输入空间时按 [定向 Fuzzing](targeted-fuzzing.md) 绑定种子、生成规则和结果反馈；先单变量，有约束或共同处理机制依据时安排必要交互对照。候选数不等于请求数，未测试的相似候选不继承代表样本的结论。

## 测试资源生命周期

按当前实验记录资源归属、唯一标记、创建/依赖状态、可变操作占用、到期与清理方法、预计请求/逻辑操作/费用额度。共享可变对象串行使用；需要独立对照时用独立获准资源。普通读取额度不授权创建订单、短信、云资源或其他收费动作。

执行前预留结果核对与允许的清理额度。清理只针对明确归属、获准删除且没有后续证据依赖的测试资源；要求保留的资源按约定交接。失败或不确定清理记录真实状态，不能标已完成；禁止重复创建新资源掩盖遗留状态。报告说明重建前提，不能依赖过期凭据或不可再用的样例来承诺复现。
