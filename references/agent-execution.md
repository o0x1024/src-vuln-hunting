# Agent 执行循环

## 分工与任务粒度

Agent 适合提取关联、提出假设、解释差异、组织报告。批量枚举、精确比较、时间测量、并发、凭据注入和证据保存交给有明确契约的工具。所有操作继承 [授权与预算](scope-and-rules.md)。

默认由当前助手完成闭环。仅在用户或宿主已允许并行执行时分配独立工作；共享预算、去重记录和资源占用状态。同一账号、订单、优惠券等可变资源不得被多个实验同时修改。多份模型判断一致不是独立漏洞证据。

## 每个假设的最小记录

探索队列先用 [选题与探索](hunting-strategy.md) 的短记录；选入实际验证后，记录 `id`、观察依据、目标与测试类别、预期规则及来源、测试身份/资源引用、前提、单次实验、确认条件、替代解释、停止条件和证据引用。受保护业务、预期影响、规则适用性和攻击前提可以标未知；下一步应说明如何缩小其中一个关键未知，而不必先补出整条影响链。达到交付阶段再按收录标准逐项补齐。可以用短表或结构化对象，不写长篇内心推演。

例：另一个测试租户的私有导出是否可读。依据是已观察的导出接口；确认条件是隔离会话下取得该租户自建文件的唯一标记；反例是公开分享、有效委派、缓存或凭据串用。

## 选择下一步

发现阶段按 [资产发现](asset-discovery.md) 选择能补齐入口、角色或业务关系的采集，不要求事先证明漏洞影响。进入漏洞验证后，按 [选题与探索](hunting-strategy.md) 比较业务价值、具体线索、真实可达条件与验证成本；允许影响尚未知但有区分性实验的候选。明确忽略且无可信新影响或规则例外时停止；不能仅因影响链暂未完整而停止正常探索。比较预期影响、信息增量、成本与副作用；不按 CVE/XSS/逻辑漏洞名称固定排序，不编造概率得分。

- 信息收集：按来源/角色/功能分批提取与确认，交付发现图、观察和缺口，不自动执行漏洞验证。
- 广度覆盖：优先建立入口与角色覆盖，保存值得深挖的候选；发现与验证共享预算，保留双方份额。
- 业务深挖：优先研究权限、状态转换和约束；从一条正常流程建立模型。
- 线索验证：优先补齐最短证据链和排除误报，避免转为全站扫描。
- 报告复核：区分已有事实与缺失材料；只有测试本身获准时才补测。

当当前方向不再产生新信息，切换到其他有依据的假设。为未探索的入口保留适量预算，由任务规模决定；不要一开始生成数百个无依据的测试任务。

## 一轮实验

1. 按 [实验设计](experiment-design.md) 核对目标、具体动作、真实攻击前提、身份与资源；复用仍有效的基线及隔离会话，准备动态依赖、结果判定及清理额度。
2. 预先写明观察什么结果才支持假设、什么结果会否定本次解释。不能看到结果后悄悄降低确认门槛。
3. 工具执行一个有界实验，捕获请求、响应、时间、错误与业务状态；在发出有副作用请求前登记操作意图。
4. 同时检查支持证据、替代解释与结果判定渠道是否有效；按 [专家式推理](expert-reasoning.md) 保存预测被支持或推翻的依据。工具/观测错误转入恢复，不计为漏洞阴性结果。
5. 按 [验证](verification.md) 决定技术假设状态，再分别评估实际影响和可提交性；只有达到 [收录门槛](impact-and-acceptance.md) 才进入待提交候选，立即更新 [持久化记录](state-and-evidence.md)。

## 失败恢复与停止

| 观察 | 处理 |
|---|---|
| 401、登录页、Token 过期 | 核对身份与会话，按现有权限刷新；无法恢复则标记该分支受阻 |
| 超时、连接错误、工具退出失败 | 保存错误；在预算内有限重试。失败不代表已覆盖 |
| 写请求超时或进程中断 | 先读业务状态/操作记录确认是否生效，禁止盲目重放 |
| 429、封禁、显著服务异常 | 暂停该目标，遵守恢复窗口并降低负载；不轮换身份绕过限流 |
| 技术成立但影响未建立 | 有机制依据且能缩小关键未知时做有界补证；无信息增量则保留线索，不能用危险动作强造影响 |
| 命中明确忽略/内部已知条件 | 保留技术事实和规则依据，标记收录排除，不继续为抬级扩大验证 |
| 相同前提与输入持续无新信息 | 记录本次未复现，换假设；不增加无依据的变体 |
| 规则撤销、范围拒绝、预算耗尽 | 停止相关主动动作，保留证据并收尾；不自行提高上限 |
| 意外真实敏感数据 | 停止扩大获取，限制保存与展示，仅保留必要脱敏证据 |
| 必要信息缺失 | 一次说明缺少什么及影响；继续无依赖分支 |

一次工具故障不直接终止整个任务。允许改变工具或实验设计，但替代工具必须满足相同边界；不得绕过明确拒绝。

## 收尾判断

约定的必需覆盖已执行、候选均有处置、证据与清理记录完整，才标记完成。还有必须工作受阻或预算耗尽，标记部分完成/等待输入并说明差距。发现数量不作为通用完成门槛；没有漏洞时也交付覆盖与局限。规则和完成契约由用户/宿主决定，Agent 不能删掉困难项来通过验收。

对纯证据判读/报告复核，完成只表示本次审阅交付，不宣布原挖掘 Run 完成。包含实际资源变更的任务，清理已完成或已交接需要记录真实结果；仅写建议不算执行。多分支有工作可继续时维持 running，停止执行后才汇总为部分完成。
