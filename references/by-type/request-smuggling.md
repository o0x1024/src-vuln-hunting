# HTTP 请求走私与 desync

适用信号：前后端协议转换、请求边界解析差异、连接复用

## 检查与最小实验

先从配置、日志和正常流量确认协议链：客户端 HTTP/2 不代表后端也使用 HTTP/2。请求字节长度、重复 framing 头、协议降级和连接复用交由能够保留原始字节的专用工具记录。

本通用线上流程只收集线索。主动 framing 实验需要明确授权的隔离环境和专用计划，确保后端连接、缓存和请求队列均不与真实用户共享；前端单独 TCP 连接并不能保证这些条件。

在隔离环境用可关联的两个自建请求和服务端逐跳日志确认前后端对边界/归属的分歧，并有规范请求作对照。不要从普通 HTTP 客户端自动修正后的请求推断原始 framing 已发出。

## 证据与反例

超时、400、连接重置和扫描器告警只是线索；必须排除网络重试/排队。HTTP/2、CDN 或某版本存在都不能单独证明有或无 desync。

## Agent 行为

不在共享生产连接注入后续请求，不拦截他人流量或制造响应队列污染。已授权隔离条件齐备时按计划执行，无需重复审批；否则暂停该分支而继续其他类型。

## 逐跳Connection字段移除与安全上下文

hop-by-hop是逐连接控制语义，需画出每个代理收到/移除/新增的字段及后端消费。[RFC9110 §7.6.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-7.6.1)要求转发前按Connection列出的字段名移除相应字段，并移除/替换Connection本身（2026-10-09核读）。不能把首段概括成所有相关内容都绝不缓存，也不能把规范处理预期当部署事实。

若某层依赖的身份/策略标记在后续转发中消失，核对生成与过滤顺序、缺失值的拒绝/公开回退和最终授权契约。只用获准配置/既有逐跳日志或隔离普通标记区分，字段丢失与framing边界/连接复用分歧分别判定，不能自动命名请求走私。来源未给完整后续机制，不在共享生产链改认证头或制造队列污染。

## 响应头注入与HTML正文消费的分界

%0A表示LF一个字节，CRLF是一对字节；[RFC9112§2.2](https://www.rfc-editor.org/rfc/rfc9112.html#section-2.2)描述行终止的CRLF与接收方可识别单LF的宽容处理，[§11.1](https://www.rfc-editor.org/rfc/rfc9112.html#section-11.1)将响应拆分绑定请求数据解码后进入响应字段/协议流（2026-10-09核读）。不能因路径含%0A或Set-Cookie字样就认为服务器生成了该响应头。

从获准既有日志/隔离普通标记追request-target→应用字段→解码/转换→真正响应头API→逐跳原始响应→正文边界/MIME→浏览器消费者。响应头值里的img文字不会自动成为HTML正文或执行事件，注入字段、响应拆分、XSS和Cookie身份影响各需单独证据；排版弯引号与ASCII又不是同一语法。保留安全头API拒绝、普通错误回显或仅文字显示反例，不导航旧URL、渲染活动内容或在共享缓存/连接注入后续消息。
