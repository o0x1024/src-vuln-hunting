# 竞态与 TOCTOU

适用信号：单次额度、检查后写入、跨接口共享状态

## 检查与最小实验

先建顺序对照和业务不变量，找操作共享的资源与可能的检查/使用间隙。既考虑同一接口重复，也考虑不同接口触及同一状态；一次请求内部也可能有短暂子状态。

由支持同步的工具调度获准的最小并发（通常两次），记录发出/完成时序与最终权威账本。HTTP/1 last-byte 与 HTTP/2 single-packet 是不同同步机制；单 TCP 连接不代表一个业务动作。工具不支持同步时如实记录，不能靠 Agent 连续调用声称精密并发。

## 证据与反例

多个 200、队列 ID 或短暂 UI 差异不代表重复效果。排除最终去重、异步一致性和正常活动例外；只在最终状态违反不变量时确认。一次未撞中不能证明无竞态。

## Agent 行为

同步突发必须符合并发和操作额度；不套用研究演示的大批量参数，不自动增加压力。成功即停，记录自建资源恢复；没有并发许可时继续离线状态分析。

## 归档案例补充：先分清生命周期与竞态

取消后券已释放但旧订单仍可结算，可能是跨阶段约束缺失，不能仅因用了两台设备就命名为竞态。重复创建优惠订单也可能在支付时被正确拒绝；分别保存创建、预占、支付和最终核销结果。见 [K02](../research/crawl-xz-patterns.md)。

一次券核销对应几个权益发放、一次转出对应几次余额扣减，需要关联到同一业务对象和操作 ID。会员有效期显示增长、多个任务完成或并发请求均成功，不能替代最终核销/账本证据；在已允许的最小并发内得到充分结果就停止，不继承公开演示的线程数或资金操作。

## 邮箱待验证状态与API key数量不变量

先明确邮箱未验证时是否允许创建key、单账号是否有key数量/唯一性约束，以及真正违反哪条规则；合法多key是反例。邮箱状态检查缺失与并发检查/写入间隙是两种机制，不能因一起出现便统称竞态。

比较获准隔离实现的顺序基线、状态绑定、幂等/去重及最终key对象，不以两个200或UI显示两项证明跨越不变量。线程数和空payload个数不提供精确同时执行证据，旧50线程/20次重放不成为许可。只分析已有配置/日志或最小获准同步对照；不生成生产凭据或照图反复制造密钥。

## 排队闸门与服务端同时消费

旧Turbo Intruder图配置30连接、每连接10请求、pipeline=False，循环只排30项，给它们同一gate后openGate，再complete(timeout=60)。这些是客户端排队/同步线索：容量配置不等于已发送300项，完成超时不等于事务提交，也不证明30次同时进入同一服务器临界区。

静态分析保留实际工具版本、队列项、连接协议、闸门动作与响应回调；全部table.add不是自动识别漏洞。真正竞态按顺序基线、同一对象不变量、服务端消费时点和权威终态证明，客户端闸门不能代替服务器证据。源Pastebin未读，不运行截图、重放业务请求或继承演示并发额度。

## Intruder null payload 重发不证明请求并发重叠

正文建议nullpayload发送同请求测race，没有调度、时序或业务结果。

在自有合成状态机比较串行、受控同时到达及幂等key变化，保留前后状态、事务边界和每操作身份，确认超过一次性约束。重复发送可能全串行或返回缓存，200多次也可能只提交一次；不发生产交易或资源消耗。
