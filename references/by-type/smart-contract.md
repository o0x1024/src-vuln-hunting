# 智能合约与链上状态

仅在当前项目包含明确授权的合约、链和测试动作，且有实际源码/字节码、部署或受控运行材料时选择。工具介绍、漏洞标题或挑战题图只产生研究线索，不构成启动真实交易的依据。

## 固定制品与业务模型

记录链/网络、合约地址与代码哈希、源码对应关系、编译/代理/实现信息、调用者角色、初始余额/权益、外部依赖和预期状态规则。未知项明确保留；不能从同名源码或历史版本推断当前部署。

权限、资产归属和一次性约束沿用 [业务建模](../business-modeling.md)。从已观察函数选择一个状态边，明确谁可调用、输入如何受控、哪些状态会改变以及哪些不变量应保持。

## 有依据的检查分支

| 信号 | 最小分析或对照 | 反例 |
|---|---|---|
| 函数看不到 modifier | 跟完整调用路径的权限检查，用两个受控调用者比较自建资源操作 | 缺 modifier 不证明缺鉴权，权限可能在函数体或下游检查 |
| 外部调用与分配/提款状态交错 | 在获准本地隔离模型核对可达的回调、必要身份、状态顺序与最终资产约束 | 标题含 reentrancy 或存在外部调用，不证明可重入或能取得资产 |
| 余额、奖励、份额或单次消费 | 对受控初始状态核对计算、重复调用和权威终态 | 静态告警或界面余额变化不能代替实际状态证据 |
| 静态分析器命中 | 回到具体代码、配置和调用者，保留工具未覆盖模块 | 工具支持检测不等于当前合约有漏洞，源帖等级不继承 |

## 实验与交付

优先使用已获准的本地测试、隔离副本或项目提供环境；保存初始化方法、输入、调用顺序和前后状态。初始资产/角色由测试者控制的能力不能省略成现实攻击者条件。不发起未授权链上交易、转移真实资产或用发现的私钥补条件。

交付源码/部署关联、预期不变量、可复核的最小状态变化、实际调用者能力与未验证连接；按 [验证](../verification.md) 和 [影响与收录](../impact-and-acceptance.md) 判断。没有足够部署/状态制品时仅保留候选，继续其他已获准分支。
