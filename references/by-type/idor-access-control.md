# 对象、功能与字段级访问控制

## 适用信号与前提

资源 ID、租户字段、管理接口、列表/详情/导出/批量接口、可写对象属性。先按 [业务建模](../business-modeling.md) 确认资源归属和共享规则，准备独立的 A/B 测试会话；垂直测试须有真实角色依据。

## 最小实验

1. A/B 分别创建带唯一标记的私有测试资源并验证正常可读；核对实际登录身份。
2. 在同一已知资源/动作上只更换测试身份，或固定身份只更换为另一个测试资源 ID；不要同时改变多个条件。
3. 保存应用结果与真实数据/状态。详情、导出、批量、不同方法和可写字段是不同权限入口，按已观察功能选择。

## 确认与反例

确认需要证明本来无权的身份读取到另一测试资源的唯一内容，或实际完成被禁止的动作/字段变更。HTTP 200、存在响应、UI 显示成功都不充分。

排除公开资源、分享链接、角色委派、同租户合法共享、后台继承权限、缓存和会话串用。签名 URL 可访问是否为漏洞取决于签发、使用和时效规则，不能仅因无需 Cookie 就认定未授权。

## 下一步、停止与报告

有证据时保存最小发现；无法确认归属则待补证。无第二角色时记录对应覆盖受阻，继续其他入口。仅使用已知自建资源标识，不遍历真实用户 ID、不批量导出他人数据。写操作只针对获准自建资源，并记录恢复结果。

报告附角色/租户别名、资源归属、对照请求、实际结果及共享规则证据。统一遵守 [验证标准](../verification.md)。

## 调研补充：可执行检查点

| 检查点 | 最小对照与判定 |
|---|---|
| 同一对象的不同入口 | 从正常流量找详情、附件、导出、历史版本等实际入口；对 A/B 自建私有对象各选一对，避免只覆盖列表接口。 |
| 对象与父级归属 | 比较 URL 父对象、body 对象、租户上下文的一致性；对象本身与所属项目都要验证，不能假设 UUID 就是授权。 |
| 功能与方法 | 仅对已观察且获准的方法检查低角色能否触发相同管理操作；菜单隐藏、OPTIONS 或 405 都不能证明实际授权。 |
| 批量与异步 | 用两个已知自建对象检查是否逐对象授权；任务创建、结果下载、分享撤销分别是检查点。 |

Agent 输出角色×对象×动作×状态矩阵；工具管理独立会话并保存服务端结果。响应里出现字段但归属不明，先补对象来源，不随机枚举 ID。字段级问题转 [API 属性授权](api-property-pollution.md)。

## 归档案例补充：关联入口和子对象

详情拒绝不代替列表、导出及下载的授权检查；父任务有权限也不代替引用子任务的权限。候选来自正常流量或获准源码，使用受控对象观察后台实际效果。共享令牌查无记录时检查失败分支，排除合法分享。见 [K03、K06–K07](../research/crawl-xz-patterns.md)。
