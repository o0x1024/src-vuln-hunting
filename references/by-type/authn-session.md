# 认证、会话与授权回调

## 适用信号与前提

登录、找回、验证码、会话刷新、JWT、OAuth/OIDC/SSO 回调。使用自建账号、独立浏览器/令牌存储及获准回调地址；短信/邮件触发纳入动作许可和次数预算。

## 最小实验

先走通正常流程并记录身份、Token 生命周期与状态。

账号/密码字段的规范化、解析和绑定差异，以及已知测试凭据核验，按 [定向 Fuzzing](../targeted-fuzzing.md) 选择输入和独立会话对照。未知密码猜测不因候选少而变为输入语义测试；认证尝试预算与普通读取预算分开。

按具体线索选一个实验：

- 登录/改密/退出/角色撤销：在规则要求失效的时点，用旧会话访问自建受保护资源，检查真实身份与结果。
- 密码重置：测试令牌是否绑定自建账号、用途、时效与步骤；改动一个维度，检查是否完成非预期状态变更。
- JWT：先确认用途、算法与验证路径，再用自有测试令牌检验签名/声明是否被接受；仅解码或修改文本不证明绕过。
- OAuth/SSO：从实际授权流程检查回调绑定、code 重放、客户端/会话关联及所用防护；只能向获准受控地址验证。

## 确认与反例

需要实际认证为不应获得的测试身份，或在应失效后继续完成受保护操作。登录前后 Session ID 相同只是线索；localStorage 存 Token 不自动等于泄露；state 缺失需结合其他流程绑定和防护判断，不能直接确认登录 CSRF。

排除刷新产生新令牌、SSO 自动重登、允许的会话存活策略、延迟失效、混用 Cookie、前端状态缓存。username 枚举与账号接管分别记录影响。

## 下一步、停止与报告

不得目标口令/验证码爆破、撞库或短信轰炸；频控可用有限自建账号观察，缺少阈值证据时待确认。离线凭据审计只有明确许可和独立预算时进行，不能用泄露生产凭据补测试条件。

报告记录预期生命周期、实际身份/操作、对照及限制，不保存可复用凭据。遵守 [验证](../verification.md) 与 [证据](../state-and-evidence.md)。协议细节按目标实现查阅 [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700)。

## 调研补充：可执行检查点

- 建立“未登录→仅密码通过→MFA 完成”的身份状态；在每一状态用同一个自建受保护资源作对照。页面跳转完成不代表 MFA 状态成立。
- 找回、换绑、邀请、邮箱验证令牌分开记用途；使用 A/B 自建身份检查账号与流程绑定。一次只变一个字段，先确认服务器实际接受的账号。
- 撤销后的会话验证要记录 access token、refresh token 与 SSO 是否重新签发；要求失效的具体策略是判定依据。
- 联邦协议按需读 [OAuth/OIDC](oauth-oidc.md)、[JWT](jwt.md)、[SAML](saml-sso.md)。不要把这些协议的缺陷统一套成“缺 state”。

## 归档案例补充：客户端封装与中间件

客户端签名重建只是恢复有效实验请求；还需核对服务端绑定的实际身份，避免把 UI 字段/新 token 当接管。中间件案例按当前部署、入口和补丁加载情况判断，维护者公告优先于转载的影响描述。见 [小程序](miniapp-security.md)、[源码审计](../source-audit.md)。
