# 系统命令与参数注入

## 适用信号与前提

网络诊断、文件转换、导出和系统工具参数。先观察正常功能、输入到执行器的数据流和组件版本。模板渲染与表达式入口读取 [SSTI](ssti.md)。

## 最小实验

针对确认的上下文使用非敏感、无副作用的常量/随机标记结果，先排除输入回显。

只在命令执行验证动作获准时使用短只读身份/常量输出，或获准受控接收端上的唯一标记；不把系统输出编码进外部请求。命令注入、参数注入、模板求值与任意代码执行分别记录能力。

无回显时优先读取已有日志/关联证据；时间验证需匹配明确许可与预算，不写文件或修改配置来获得回显。

## 确认与反例

服务端实际解释了不应执行的输入，结果与特定实验可归因。算术结果不等于任意系统命令；DNS 回连不单独证明 RCE；看到命令字符串不等于执行。

排除正常内置计算器、前端表达式、错误消息反射、网关预取与异步噪声。能力升级需要新的证据，不能从一个引擎特征推断所有 gadget 可用。

## 下一步、停止与报告

不写文件、不弹 shell、不驻留、不横向移动、不读取应用配置或凭据来放大影响。已有最小执行证据即停止该验证。保留执行上下文、身份（可证明时）、模板/组件条件和原始结果；遵守 [验证](../verification.md)。

## 调研补充：可执行检查点

- 区分 shell 语法注入与工具自身参数注入：shell 转义通过并不保证工具选项无风险；先从调用点和正常参数确认执行模型。
- 以最小可归因的常量输出作验证，排除输入回显；盲测需要独立带外归因或有许可的短时间对照。不能看到一次 DNS 就直接写 RCE。
- OS、shell、工具版本不同，解析规则也不同；先在本地复现语义，不调用未知反射方法，不遍历危险方法表。
- 模板计算单独读 [SSTI](ssti.md)，不要因渲染了一个算术值就宣布系统命令执行。

Ruby 的文件/URL 字段需跟到实际方法接收者与版本，区分 `Kernel#open`、`URI.open`、`File.open` 和应用自定义封装。Ruby 3.3 文档展示的 `Kernel#open` 实现会把首字符为 `|` 的输入转给进程管道，因此“字段本来用来打开文件/URL”不能代替消费者分析；不能从 Rails 指纹推断目标调用了该方法。先核对调用点、过滤与运行时版本，再用获准隔离环境或现有日志确认实际解释能力，线上不盲投命令。依据：[Ruby 3.3 Kernel#open](https://docs.ruby-lang.org/en/3.3/Kernel.html#method-i-open)，2026-10-09 核对；其他版本须重新核对。

## PHP禁用函数配置的观察边界

读取disable_functions只描述当前PHP进程加载的配置，先绑定版本、SAPI、配置文件与真实执行路径，不从本地/CLI值推Web运行时。[PHP官方配置说明](https://www.php.net/manual/en/ini.core.php#ini.disable-functions)指出该项作用于内部函数；PHP8起禁用会移除函数定义，允许用户态重新定义，而更早版本阻止调用（2026-10-09核对）。这不是目标已具RCE或任意函数恢复能力的证据，也不能当完整隔离边界。优先已有获准诊断，保持原配置，不执行来源PHP片段、重新启用函数或寻找命令执行链来扩大影响。

## 花括号展开与真实shell调用

无空格/美元符号过滤的命令注入建议，先区分直接argv执行、shell -c、实际shell/选项和当前引号位置。Bash的花括号展开可能产生多个词，但这不是所有sh或Windows执行器的通用语法，参数值本身也不自动重新进入所有shell展开阶段；具体输入到解释器的代码路径必须可证实。2026-10-09核对[GNU Bash花括号展开官方检索摘要](https://www.gnu.org/software/bash/manual/html_node/Brace-Expansion.html)与[展开顺序摘要](https://www.gnu.org/s/bash/manual/html_node/Shell-Expansions.html)；本次完整页面获取失败，不据此声称已阅读全文或当前目标使用Bash。

来源把hostname输出嵌进外部URL来做回连，会跨越系统信息披露边界，不作为默认最小验证。只用获准隔离环境的非敏感常量/现有执行日志来辨别展开、输入回显与真正命令/参数注入，不调用来源接收站或执行花括号/反引号载荷。

## Shell展开所依赖的变量与执行上下文

把变量、数组索引、空命令替换或位置参数插进路径，只在真实shell解析、当前变量值/选项/位置参数及引号条件下才可能形成所称命令；HTTP值、独立argv和Windows命令解释器不自动经历同一阶段。数组或算术子式还可能有额外消费，不把未知变量默认当空。

GNU Bash[展开顺序](https://www.gnu.org/s/bash/manual/html_node/Shell-Expansions.html)、[词拆分](https://www.gnu.org/s/bash/manual/html_node/Word-Splitting.html)与[命令替换](https://www.gnu.org/s/bash/manual/html_node/Command-Substitution.html)的官方检索摘要支持这些阶段分别分析；2026-10-09完整页面获取失败，当前部署/具体载荷并未实测。用获准源码/既有执行日志核对输入如何进入解释器及实际参数，不运行源cat/替换表达式、读取系统文件或按文本变化宣称WAF绕过。

源图只有终端输入，没显示执行/输出。核对shell调用、引号、IFS值/词拆分、glob选项、匹配到的全部路径与argv；多个匹配、不存在目标文件、直接argv调用或禁用展开均可破坏所称等价。命令字符串遮蔽不证明WAF被绕过或文件读取已获准，不执行源系统文件读取或创建真实命令调用。

## PHP动态可调用表达式与版本语义

旧图把system文字拆分/加注释、字符串调用、裸常量和$_GET键都列为可行过滤绕过；每种须先能进入PHP表达式求值，而不是普通模板文字、参数值或仅命令参数。[PHP变量函数手册](https://www.php.net/manual/en/functions.variable-functions.php)说明变量求值后的函数名可被调用，echo/include等语言构造不直接遵循同样规则（2026-10-09核读维护者正文）。
