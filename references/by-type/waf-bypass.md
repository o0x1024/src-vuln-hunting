# WAF 绕过与逐层解析差异

适用信号：已有具体漏洞假设受过滤影响，或正常流量/文档/代码/错误提示了某个可验证的接口解析差异；不作为无依据载荷扫描起点

## 先定位限制发生在哪一层

保存正常请求与被拦请求、身份、时间、响应指纹和唯一变化。先区分业务拒绝、认证失败、429、机器人挑战与内容过滤；403 或产品指纹不证明具体规则。没有漏洞证据时可先做有依据的普通标记解析观察；没有机制线索则返回正常业务/数据流分析。

画出客户端序列化→CDN/WAF→代理→框架解析→应用解码→解释器链；未知层标 unknown。Agent 提假设，工具保留原始字节和解码表示；工具自动规范化可能消灭你想测的差异。

请求行使用路径形式或完整 URL 时，保留实际发出的 request-target、Host、代理路径和最终处理器。两种表示响应不同可能来自路由、虚拟主机或代理选择变化；先以同一受控普通资源核对是否到达同一应用，再判断原输入边界，不能从“完整 URL 成功”直接推导 SQL 注入或 WAF 绕过。涉及其他 authority 的目的地需单独核对范围。

## 按条件选择最小变体

| 机制 | 适用前提与实验设计 | 常见误判 |
|---|---|---|
| URL 规范化/编码 | 对受控普通标记先比较编码、分隔符、路径规范化；证明后端落在同一资源后，再应用原假设的最小变体。 | 假定所有层解码两次；Cloudflare 的 RFC 与额外规范化模式并不相同。 |
| 媒体类型与 body 解析 | 文档、正常流量或框架代码提示替代表示时，可先以小型普通标记测试是否支持，再对相同字段比较语义；WAFFLED 摘要支持研究解析不一致这一方向。 | 切换后返回 200 实际是忽略 body、进入错误处理或未到原功能。 |
| 重复参数/结构差异 | 用不同标记辨明网关和应用取首/末/合并/拒绝的实际行为，记录每层值；再转 API 参数污染假设。 | 默认全部框架取末值，或发送了工具自动去重后的请求。 |
| 解释器语义等价 | 数据库、模板或命令上下文已经确定；先本地证明两种表达式等价，再验证过滤层差异。 | 只绕过关键字，但后端不再执行同一含义；把历史 JVM 方法序号当稳定接口。 |
| 检查范围/大小边界 | 优先读取授权配置，核对 body/header/cookie 检查范围、超限动作和托管规则。只在允许的常规大小/次数内做有界测试。 | AWS 的检查上限随组件/宿主服务而变；Continue、Match、No match 都需结合规则动作及后续规则，不能写成“超限必放行”。 |
| 路由与源站差异 | 已获准且已知属于该项目的路由/源站才可对照；Scope 在每个目的地重新核对。 | 同 IP、历史 DNS 或 Host 变体被当作新授权；无法访问就换身份/IP 规避限制。 |

Cloudflare 和 AWS 的厂商资料用于约束假设；没有该目标配置时不假定默认值。pmnh 的历史 SpEL 案例只支持“理解实际引擎后构造语义等价表达”的方法，不能当现成通用载荷。

多重删除/转义可能改变后续解析对象，但须先离线算清每一步结果，再核对实际解释器。历史帖子声称删掉 `alert` 后 `<scralertiot>` 会重组为 script，实际只得到 `<scriot>`；这不是成功正例。字符集、HTML 实体、URL 编码和脚本转义同样按真实处理顺序记录，不能把非 ASCII 字符的外观近似当作等价语法。

## 无害标记示例

下列只用于辨明解析方式，不构成漏洞载荷，也不授权发送；先匹配已授权接口与具体机制线索；格式支持未知时先验证支持情况。

| 对照 | 要回答的问题 |
|---|---|
| `term=probe-A` 与 `{"term":"probe-A"}` | 有依据的替代格式是否被同一接口处理，支持后最终字段值是否相同？ |
| `term=probe-A&term=probe-B` | 各层得到 A、B、数组还是拒绝？请求工具有没有先去重？ |
| `term=probe-A` 与 `term=%70robe-A` | 在已知 URL 编码参数位置，解码前后检查的对象是否一致？不能把它套进任意 JSON 字符串。 |
| 普通标记与 JSON 中的 `"\u0070robe-A"` | JSON 解析后是否得到同一个普通字符串？若根本不解析 JSON，过滤放行无意义。 |

先通过这些对照确定真实语义，再为原漏洞选择一个有依据变体。所有样本共享所属发现/实验及任务总预算，不为“绕过阶段”另起一套请求额度。

## 实验记录与退出

每个变体至少记录 `parent_hypothesis`（纯解析观察可为空并关联 observation_id）、改变的层/字段、原始请求引用、预期后端语义、网关结果、应用结果及剩余预算。通常先做正常基线、被拦样本和一个有依据变体；若没有新增信息，不继续组合 tamper。

“放行”只结束网关分支，漏洞确认仍按 SQLi/XSS/SSRF 等原专题标准。正常标记能到达、无敏感内容反射或网关 403 变 200，均不自动形成漏洞 Finding。保留未复现/条件不足的结果，不保证任何技巧可通用绕过。

不启用无界载荷库、不伪装身份规避限流、不为超限测试堆大请求或提高并发。[请求走私](request-smuggling.md) 属于隔离专项；不能当作普通 WAF 变体在共享生产连接执行。

## 归档案例补充：内容编码和双解析器

对有文档/流量/代码依据的 Content-Encoding，支持未知时先辨明支持情况，用小型普通标记核对压缩前后大小、媒体类型、最终解码值和同一业务路径；415、不解析 body、忽略字段分别记录。不能继承文章的产品成功率，也不构造高膨胀数据。验证器与恢复器的实现/版本/输入类型必须分别记录，CTF 额外依赖不能视为目标已有。见 [K11–K12](../research/crawl-xz-patterns.md)。

若获准源码或配置暴露了基于共享值的放行分支，跟踪该值的来源、设置主体、校验位置、部署版本与实际规则顺序。公开代码中的常量不等于生产启用的秘密，更不等于全局关闭 WAF；只在允许的受控普通标记上确认该分支的作用，后端漏洞与真实权限仍独立验证。

参数名称与参数值可能在不同阶段规范化。名称编码变体要保存原始键、各层解码后的键、同名/重复键冲突及最终选值，用受控普通标记确认仍到达同一功能。302变200或未再拦截不能证明原漏洞成立；不要将仅适用于URL参数名的编码直接套到JSON属性或其他输入层。

浏览器fetch设置referrer时，记录页面来源、请求配置、有效Referrer-Policy及最终发送的Referer，不把配置字符串视为线上头值。strict-origin-when-cross-origin在跨源安全请求中发送origin而不保留路径，降级还可能不发送；路径中含目标域字符串不能据此证明绕过。代理重放头与真实浏览器可构造性分开，放行后仍按原漏洞验证。标准依据：[Referrer Policy算法](https://w3c.github.io/webappsec-referrer-policy/#determine-requests-referrer)（2026-10-09），未请求源帖目标。

## 双向显示控制与请求逻辑字节

%e2%80%ae经一次百分号字节还原并按UTF-8解释对应U+202E，和LF/CR、TAB、NUL分别建模。[Unicode双向算法§2.2](https://www.unicode.org/reports/tr9/#Directional_Overrides)将其定义为RIGHT-TO-LEFT OVERRIDE（2026-10-09核对检索文本）；它影响显示顺序，不能据屏幕上的倒排顺序假设后端语法或请求字节也被倒排。

原始请求以转义字节/码点视图留证，固定字符集、解码次数和各层规范化，核对过滤器、业务解析器与实际危险消费者收到的值。日志/编辑器视觉差异与过滤绕过、实际执行是独立观察；字节变化、移除或拒绝控制字符需要真实处理证据。不能把四种编码字符清单当通用WAF绕过，HTTP状态改变也不代替业务效果。

## U+FFFF、字面转义与标签语法

帖子里的\uffff文本、实际U+FFFF码点和传输编码字节分别记录。[Unicode官方FAQ](https://www.unicode.org/faq/private_use.html)明确U+FFFF是非字符，但仍可存在于合法Unicode字符串；“非法Unicode”不能作为所有解析器会删除它的依据。

[HTML标签名状态](https://html.spec.whatwg.org/multipage/parsing.html#tag-name-state)对未列出的字符追加到标签名，不普遍把插入字符忽略。因而scr加U+FFFF再加ipt不自动等于script；若中间层删除/替换，须给出实际字节变换及最终标签/消费者证据。WAF放行图不证明浏览器执行，只静态比较获准合成表示，不发原载荷或宣称现行通用绕过。2026-10-09核读两个官方相关段落。

## 文件填充、检查范围与源站完整字节

大量换行填充后追加程序片段的声明，需要核对WAF检查字节数/截断与超限策略、传输编码/解压、请求总长度、源站收到内容和真正解释器。源命令先生成file1.php再追加到file.php，两者不是同一制品；Python版本/print语法也影响实际生成结果，不能把示例自动修成已验证成功流程。

在获准配置/既有逐层日志或隔离合成普通标记中比较相同文件的前后标记是否被检查、传递、保存与消费，记录hash及完整性。接受上传/漏检查与RCE各有证据；过滤绕过后若只存为图片/附件并不执行。不制作巨型填充文件、运行程序片段、压测生产或称当前Cloudflare普遍存在该缺陷。

## 同页Referer放行与补丁保护的业务对象

自设Referer指向被拒页面后规则放行，提示补丁可能依赖客户端可提供的来源文本。区分代理重放的任意头、真实浏览器最终发送值、边缘规则是否依赖该字段以及后端对实际受保护资源的授权；源图只有GET/Host/Referer示例，没有放行响应或业务能力。

对获准已有规则/日志关联补丁前后版本、原始拒绝基线、单字段变化和最终私密内容/操作，公开fallback或后端仍拒绝为反例。不要把该Referer声明与CSRF自动混为同一问题，也不能因成功绕过一个403就认全部补丁失败。重测沿原根因和范围，不执行源请求或全量403头变异。

## 百分号编码的十六进制大小写

[RFC3986§2.1](https://www.rfc-editor.org/rfc/rfc3986.html#section-2.1)规定百分号编码中A–F与a–f等价（2026-10-09核读），所以%3C与%3c在对应百分号解码后表示同一字节。该规则不意味着任意路径、字段值、HTML/JS字符串都大小写不敏感，也不自动让JSON文字里的百分号先解码。

用获准普通标记固定输入位置、原始编码、各层规范化及实际后端值，比较只改变十六进制字母大小写的样本。403变allow提示过滤或其他处理差异，但还须证明请求到同一业务处理器；缓存、路由、忽略字段或后端仍拒绝为反例。旧img示例没有事件属性/执行结果，标签接受不构成XSS，不渲染原载荷或推广为当前通用绕过。

## Unicode码点窄化与HTTP控制字节

%E5%98%8A经正确百分号到字节、UTF-8解码对应U+560A，不等于LF；离线仅对单字符编码观察到UTF-8字节E5 98 8A，显式取码点低8位才得到0A。这是不同变换，不能将U+560A→0A当Unicode正常规范化。[RFC3629§3](https://www.rfc-editor.org/rfc/rfc3629.html#section-3)定义UTF-8多字节编码（2026-10-09核读）。

从获准源码/既有逐层日志追字节解码、字符类型、窄化/截断或替换函数、校验时点、实际HTTP序列化API与下游字节。没有实际窄化证据时只保留候选；保存普通文字、拒绝转换或安全API过滤等反例。即使产生LF，也需独立证明进入响应头/协议流并改变消费者边界，不能推CRLF注入、XSS或请求走私。本次不发送控制字节或污染共享连接。

## 表单表示转换与百分号字段语义

旧图从application/x-www-form-urlencoded改为multipart/form-data，前后仍是POST；不能称作HTTP方法变化。比较boundary、Content-Disposition字段名、part的Content-Type/charset、原始字段字节及应用实际解析值。[RFC7578 §4.4](https://www.rfc-editor.org/rfc/rfc7578.html#section-4.4)规定part Content-Type可选，缺省text/plain；标注一个媒体类型不保证框架会递归套用该解析器。

[URL Standard表单解析](https://url.spec.whatwg.org/#urlencoded-parsing)定义加号替换与百分号解码（2026-10-09核读相关段）；multipart正文里的%22/%20不能无证据套用同一结果。仅在相同业务身份/语义被证实后比较WAF与应用消费者，否则“通过”可能只是处理器忽略字段。请求成功不证明SQL控制或全部WAF绕过，先审已有脱敏日志/隔离普通标记，不执行来源SQL片段或自动变体扫描。

## PHP参数名转换与不完整百分号编码

旧帖说PHP替换空格、ASPX删掉后面不是两个数字的百分号。[PHP外部变量说明](https://www.php.net/manual/en/language.variables.external.php)针对表单变量名称的点/空格转下划线，不能推广为任意值或JSON字符串都会删除空格。[RFC3986§2.1](https://www.rfc-editor.org/rfc/rfc3986.html#section-2.1)的百分号语法是两个十六进制位，包含A至F，不是两个十进制数字（2026-10-09核读）。

保留原字段位置/字节、每层解码和规范化后的键值、碰撞/重复项及最终业务消费者，使用离线合成标记对照同一功能。ASPX具体版本/配置行为未被来源证实，可能拒绝、保留或不同解析，不能写统一删字符规则；改变字节或WAF放行也不证明后端同值/漏洞成立。未执行来源编码载荷或发生产请求。

## 重复等号与文件参数消费者

旧帖把file=rce.php改为file===rce.php，声称WAF由阻断变200。这是一个参数中出现额外等号，与重复file键不同；若解析器在首个等号处分键值，值是==rce.php，不能先假定后端仍选择原文件。实际解析规则、后续去前缀/规范化、文件查找与解释执行分别取证。

用离线合成普通文件标记比较每层键值、实际选中对象与正常拒绝分支。200、文件名含php、WAF放行均不证明上传、存储、PHP解释或RCE。其他帖将文件名换shell.php仍属相同假设，不重复计新机制；不执行原载荷、访问旧目标或把额外等号写成普遍有效旁路。

## 非十六进制百分号片段的来源错误

旧编码帖将%2s/%2u称为角括号的URL编码，另一些重定向例写$2f%2f；这些字节必须按原样保留。s/u不是十六进制位，美元符号也不是百分号，不能静默修成%3C/%3E或斜杠并把修正结果归原帖。

沿原字节、每层拒绝/保留/解码和最终上下文比较，只有实际版本消费者证据才能说明容错行为。复用本页百分号编码语法边界，不从编码外观认Cloudflare旁路或最终脚本执行；不运行原载荷或试当前目标。

## AEM点号路径与Sling资源分解

旧两行示例同时把/node改成/nod并改变点号串后称JSON绕过；这些变化不能证明命中同一资源，更不能把省略样式点串恢复成确定selector数量。记录原始target、当前资源结构/映射、Dispatcher允许决策及最终处理器/受众，分别变更资源路径与表示字段。

## 事件名中的百分号、NULL与最终HTML属性
