# SQL 查询输入验证

## 适用信号与前提

查询、筛选、排序、分页、JSON/表单参数及存储后被检索的输入。报错或组件指纹只构成线索；先捕获正常请求与响应基线，识别可能数据库和驱动条件。

## 最小实验

固定身份、数据和其他参数，针对观察到的语法上下文选择对照：正常值与语法扰动、可解释的真/假条件，或受控查询结果标记。比较业务字段和错误，而不是只比较长度。

优先非延迟、非写入的实验。只有时间差测试已获准且有请求/时延预算时，使用短、有限的交错对照并保存原始样本；不同时大并发制造延迟。不同 DBMS/版本语法需核对，不把字符串拼接结果当作可执行 SQL 关键字。

二次注入只创建允许的测试数据，并记录写入到触发的路径。不要自动转为全库枚举、堆叠写入、读系统文件或操作系统执行。

## 确认与反例

确认输入改变了服务端查询语义且能通过对照归因；单引号报错、一次慢响应、WAF 拦截、版本匹配不充分。排除输入校验、全文搜索语法、结果排序变化、缓存、限流与网络抖动。

时间实验在有限预算内无法区分噪声时记录待补证，不继续增加延迟。sqlmap 等工具只有确认模板、参数和请求限制后才用于该实验，扫描结论仍需证据复核。

## 下一步、停止与报告

仅证明必要查询能力，优先自建数据或非敏感常量；不拖库、不枚举真实用户记录。报告写明输入上下文、数据库依据、基线与对照、原始样本、实际能力和未验证影响。遵守 [验证](../verification.md)；必要时读 [解析差异](waf-bypass.md)。

## 调研补充：可执行检查点

- 先区分字符串值、数值、排序/列标识符与 JSON 包装参数；从实际查询行为选择适用数据库语法，不跨方言盲试。
- 有回显时用无害常量与成对逻辑条件观察受控结果；语法错误只能建线索。黑盒时间信号采用交错对照，网关重试或负载波动未排除时不确认。
- 二阶入口必须记录“存入→后续检索/报表”关联；初次写入正常既不能证明安全，也不能证明后续拼接。
- 确认查询结构被非预期改变后停止；无需导出库表、账户或凭据证明存在。WAF 变体仍按同一数据库语义验证。

## 归档案例补充：查询分支与条件差异

ORM 的条件绑定与原始表达式可能走不同实现，跟到具体重载与参数绑定，不按框架名定性。错误类别作为观察通道时，先用受控常量的成对条件排除业务校验和网关干扰；不以真实字段逐字取数替代最小证明。见 [K05、K13](../research/crawl-xz-patterns.md)。

Salesforce/Apex 的动态 SOQL 材料沿“输入字段→实际变量→查询字符串→Database.query→受控结果”追踪，先确认输入确实进入查询结构。教学伪代码若表单绑定 userinput、查询却拼接未定义的 input，或基线邮箱与展示查询不一致，须保留缺口，不能作为可运行正例。查询语言、绑定方式与当前可用操作分别确认，不把其他数据库的 UNION、写入或系统执行能力直接套用；最小证明仍使用自建对象和已知合成字段。

搜索输入中的 `%`、`_` 或其他模式字符导致结果扩大时，先区分产品允许的通配符查询、未限制的匹配范围、对象授权与查询结构注入。用已知合成数据比较字面量搜索和模式搜索，并沿实际参数绑定/转义位置核对；返回更多行不自动证明 SQL 注入，也不为确认通配符作用读取生产整表。

MySQL字符串比较是否区分大小写，取决于操作数类型、字符集、排序规则和表达式的实际转换，不能把等号一概当作不区分大小写。[MySQL8.4字符串搜索说明](https://dev.mysql.com/doc/refman/8.4/en/case-sensitivity.html)区分非二进制字符串的collation与二进制字节比较（2026-10-09核对，不代替目标版本实证）。已有查询注入假设时，先在获准隔离样例用已知普通字串建立大小写/真假/错误对照，另核LIKE的模式字符和转义；LIKE BINARY的历史建议不自动适合当前表达式，异常或页面正常不证明查询控制，不推断/枚举真实秘密。

## 运算语义与工具任务差异

[MySQL8.4正则文档](https://dev.mysql.com/doc/refman/8.4/en/regexp.html)定义REGEXP/RLIKE为字符串正则匹配并给出NULL语义，它们不是AND/OR的通用替代（2026-10-09核对）。按真实DBMS/版本、参数类型、查询构造、运算优先级与编码链解释差异，WAF响应变化不证明数据库实际求值；只用隔离合成查询理解表达式，不将帖子载荷投向真实服务。

Firebird历史sqlmap图中，前图报告数据库枚举/命令执行不支持，后图更换为表枚举并显示表数；任务不同，不能归因为提高risk/level后“绕过成功”。同时核对工具版本、参数边界、命令拼写、动作类别与输出证据，--dbms只是提供假设，不代替识别。现有注入证据优先；提取数据库名/表/记录及增加风险、线程均需在原授权和预算内，不为验证截图执行批量枚举。

## 图片相关请求中的数据库错误

图片/相册请求的路径或参数可能进入数据库查询，是否返回图像不决定注入类别。现有SQL错误图展示输入相关查询和后续查询失败时，分别记录真实入口/参数、SQL语法位置、数据库/版本线索和错误暴露；报错中出现UNION字符串不证明任意查询已成功、跨表读取或当前部署仍受影响。

从获准日志/源码或有限合成正常对照恢复消费者，排除查询日志原样展示与其他失败来源；不按图枚举19列、导出真实学生/客户数据或执行来源SQL载荷。截图仅显示报错时保留影响缺口。

## 工具恢复结果与当前请求证据

SQL工具的stored session、resuming back-end DBMS、resumed injection points等提示表示复用了既有状态。恢复出来的MySQL/布尔/时间/UNION标签与当前连接请求、有效正常基线及本次消费证据分开；旧结果可能绑定不同身份、参数、版本或部署，不能由一次截图证明13个目标全部当前可注入。

保留缓存/原结果来源时点、目标键、身份引用与实际此次动作；新判断使用独立证据关联，不删除用户现有会话缓存或盲重跑全量sqlmap求“新鲜结果”。gf sqli名单只是参数候选，--batch/level1/random-agent也不把主动验证或枚举变为普通读取；本地材料提炼不执行这些命令。

## 转换脚本与展示载荷

数据库dump题名配图实际上展示UNION类型、五列工具推断、MariaDB banner及24个表名，未显示表内行数据。工具提醒tamper脚本转换不包含在展示payload中，所以展示字符串不能代替实际发送字节或完整证据。

## 可执行注释、版本条件与关键字重组

URL百分号解码、过滤器替换、SQL客户端处理和数据库解析分别记录，MySQL注释规则不能套到所有DBMS。[MySQL8.4注释说明](https://dev.mysql.com/doc/refman/8.4/en/comments.html)区分普通注释、可执行扩展、版本条件及优化器hint，并说明版本号后的空白条件与客户端/服务器解析差异。

关键字嵌套后会不会重组取决于大小写、删除次数/递归方式和实际结果；不要因为WAF接受就称数据库接受同义查询。只从已有数据库上下文与获准离线规则算清转换结果，以合成常量检验语义；不投源码片段、枚举库或把缺少1–15条的16–20条列表称完整通用绕过。资料核对：2026-10-09。

结构化参数的正则条件与计数/异常观察见 [NoSQL：结构化条件与计数观察](nosql-injection.md)。

## 数组类型与查询格式错误

用户名从字符串变成JSON数组后出现MariaDB ER_PARSE_ERROR/1064，只证明该输入触达某错误路径。可见查询片段含逗号分隔的引号值，可能涉及参数类型和驱动格式化；未给查询构造、绑定方式或结构控制证据，不能确定是SQL注入或从数据库错误推出RCE。

保留原始请求媒体类型、字段类型/元素、解析后值、类型校验、驱动/版本、参数绑定与脱敏查询错误之间的关联；客户端截图中的Content-Length也不能代替实际线上字节。优先审已提供代码及获准离线合成数据，比较合法标量与拒绝数组的路径，不执行来源SQL、延迟、枚举表或用真实登录凭据补证。

恢复入口的email类字段也须跟输入→解码→实际驱动/查询构造；%2b到加号的层次、排版弯引号、SQL类型/上下文与数据库方言分别保留。PostgreSQL的pg_sleep与另一方言的sleep不是通用同义载荷，[PostgreSQL延迟说明](https://www.postgresql.org/docs/current/functions-datetime.html#FUNCTIONS-DATETIME-DELAY)明确当前会话延迟还受平台/负载影响（2026-10-09核读相关段落）。

图中一次20.658秒响应/true正文没有正常与交错对照，可能含应用、邮件队列、限流或网络等待；不能从200确认查询控制，更不能从载荷列表承诺100%发现。优先获准源码/隔离非延迟常量对照，时间验证仍要求有限短延迟预算，不执行来源10/20秒sleep或触发真实恢复邮件。

## 界面校验、序列化与实际请求字段

登录框直接输入引号失败而改请求email后出现SQL错误，可能差在前端校验、序列化/编码、字段是否发送、代理改写或服务端路由；不先认定“只有Burp能触发SQLi”。保留正常界面请求、界面变体及请求变体的原始字节、方法/MIME、实际身份和消费者，每次只改变有依据的一层。

错误文本只说明异常通道，需要实际查询构造/驱动/方言和无害结果对照确认结构控制；页面未发请求与服务器拒绝不同。来源四步图没有完整请求或查询证据，不能把SQLerror标题升级为认证绕过或数据读取，不对真实登录盲试载荷。

## 扫描器检测与数据库取证动作分界

从历史URL模式筛选到SQLmap检测，再到读取banner/current user/database/hostname是不同阶段和动作。来源图在53次HTTP请求后询问是否继续exploitation，随后显示数据库元数据；一个示例参数确认也不证明全列表均受影响，更不替生产目标授权读取数据库。

保留输入来源/时点、筛选损失、实际参数与查询语境、每阶段请求预算、失败分母和无害控制结果。工具布尔/时延/UNION结论需对应原响应与实际消费者；有明显方言条件和时间阈值仍不能省略反例。只提炼已有图，不运行自动batch、SLEEP、重查询或数据库读取。

## PHP查询返回false与结构注入证据

源站IP加Host并关闭TLS校验后出现mysql_fetch_array期望resource却收到boolean，说明消费链得到不符合预期的值；不能仅由这条警告证明输入控制SQL结构或已取到数据。查询失败、合法返回布尔结果、不同vhost/库连接、旧驱动和代码错误均需同版调用点判别。

保留正常查询、有限无害变体、驱动返回值和真正SQL构造的脱敏证据；同时区分入口WAF拒绝、源站路由到达和权限边界。insecure取消客户端证书校验不是服务漏洞证明，公开IP也不是探测许可；本次不发来源UNION请求、连接源站或使用数据库秘密。

## 布尔盲注分治的稳定判定与工作量

分治加速依赖真实、稳定的真假观察器及可按条件划分的有限候选空间；每次可靠判定将候选区间缩小，和逐值猜测的请求需求不同。记录合成值范围、比较语义/排序、真假基线、未知响应、重复确认、总请求和每次成本；响应长度、超时、权限拒绝不能直接当真假。

先在获准离线合成观察器/已有日志中比较相同任务的完成率、误判、请求数量与耗时，保留边界/未知结果，不因15分钟到3分钟宣称所有数据库提速。实际数据取证有独立动作许可与最少数据要求；本次不运行SQL、读取数据库秘密或实现批量外带。

## 二阶查询的独立观察页面与代理改写

二阶SQL涉及植入/保存输入与后来检索/报表消费者。来源建议用Burp给响应添加Location让sqlmap去另一页面观察，实际图仅显示Response header规则，没有原状态码、真正跳转或SQL证据。保留原响应、规则生效方向/范围、改写后状态与头、实际后续请求的方法/身份/对象；工具添加的跳转不能写成应用原生行为。

在获准已有合成记录中关联写入提交、存储标识、第二页面真实查询构造及稳定观察信号，核对当前工具跟随跳转的版本/状态/方法条件。第二页面无变化也可能因没提交、不同会话、错误对象、没跟随或输出截断而未知；不能当二阶安全结论。不运行SQLmap、外带数据或通过代理全局改写线上响应。

## LIKE下划线模式与SQL语法注入分开

“SQL请求中_像正则.”应限定在实际LIKE模式，不能推广到等号、标识符或所有查询。[MySQL8.4比较文档](https://dev.mysql.com/doc/refman/8.4/en/string-comparison-functions.html)定义_匹配一个字符、%匹配任意数量，并给出ESCAPE及SQL mode条件（2026-10-09核读）；数据库、collation、真实模式构造和转义仍需当前证据。

参数化查询也可能按产品设计消费模式字符；多匹配一个合成条目不证明SQL语法注入或越权。用隔离普通字串比较字面下划线、模式下划线和明确转义，沿查询→结果集合→调用者权限核对是否突破有依据的精确匹配/数据可见性规则。合法搜索模式作反例；不据通配差异枚举真实账号/秘密，不运行源SQL表达式或盲目把它判成注入。

## 无逗号表达式的方言与结果形状

历史图列出LIMIT替代、SUBSTR的FROM/FOR形式及派生表JOIN，不能仅按字符限制认这些表达式在全部数据库等价。[MySQL8.4 SELECT](https://dev.mysql.com/doc/refman/8.4/en/select.html)明确offset,row_count与row_count OFFSET offset的参数次序；[JOIN说明](https://dev.mysql.com/doc/refman/8.4/en/join.html)指出MySQL的JOIN/CROSS JOIN/INNER JOIN可语法替换，标准SQL并非同样规则（2026-10-09核读相关段）。

固定数据库/版本/SQL mode、插入语法位置、函数名/参数形式、派生表别名、列数/顺序/类型与行数。把列清单改成SELECT *加JOIN会改变结果形状，也可能增加行，UNION仍有匹配要求；能解析、WAF放行与应用消费受控结果分别验证。只读审计已有脱敏查询或隔离普通常量，不运行源UNION、数据库枚举或自动tamper组合。

## 认证查询结果与独立密码比较

教育图的authenticate伪代码先按username拼查询取password，再把$result与md5(password)比较；它没有说明db.execute返回标量、行集、游标还是错误，亦未展示绑定主体的会话。查询结构可控和最终密码比较是两个检查点，扩大WHERE结果不自动消除后续摘要比较。

按实际实现核对查询构造/参数绑定、字段/行的提取、空结果/多结果/错误处理、比较类型与最终稳定账号ID，优先用已有合成记录确认消费者。图中混合伪语法不是某个已知驱动的运行证据，MD5名称也不证明该实例可被接管；不把通用OR条件当可直接登录的答案，不跑SQL或使用真实密码/修改账号。

## 注入时序与结果观察通道分开建模

旧SQL类型图把Second Order或Out Band放同一框，但二次注入描述存储后再被不安全查询消费的时序，带外描述结果经另一通道观察；两者可以组合，也各自独立。[PortSwigger SQL说明](https://portswigger.net/web-security/sql-injection#second-order-sql-injection)分别讲存储输入的后来查询与带外网络观察（2026-10-09核读相关段）。另一HTTP页面观察二次结果不因此自动成为OAST。

分两轴记录植入/提交/存储/再次读取/实际SQL消费，以及同响应内容、布尔、时间或DNS/HTTP观察器。DNS事件可能来自解析、预览或扫描器，耗时也可能来自网络/限流；每轴需要独立来源与基线，未触发或观察器缺失保持未知。本次不生成外带查询、启动接收服务或取真实数据库内容，复用二阶观察页面及稳定判定条目。

## 数据库中凭据表示与恢复令牌的不同能力

旧帖建议SQL注入无法“解密密码哈希”就转取重置token，并称常未加密或盐弱。哈希不是一般可逆加密，salt也不决定某个恢复token是否会被服务端接受；应按实际存储的单向摘要、密文、随机秘密或普通标识区分用途。SQL结构控制、可读某字段、有效恢复能力与最终错误主体的登录是不同边界。

优先以获准源码/脱敏模式及合成记录核对存储形式、读者权限、账号/用途/有效期/单次消费、验证器及恢复后的稳定身份。数据库保存明文恢复秘密可能扩大已发生读取的影响，但正文没有证明其当前有效或全部账号接管。最低必要证据充分即停止，不枚举密码/重置表、破解真实哈希、取得或消费他人恢复token。
