# 大模型应用、RAG 与 Agent 权限

触发：聊天/文件/知识库、模型服务或权重入口、检索与向量索引、Agent、工具/插件、代码沙箱、多模态输入。先沿 [发现流程](../discovery/ai-and-devices.md) 建立实际功能图；不要求一开始已证明漏洞。小米项目再加载 [MiSRC §4.2.4](../policies/xiaomi-misrc.md)，其他项目使用自身规则。

## 建模与候选

记录产品、模型/应用版本（不可见则未知）、账号/租户、会话、文件/知识库归属、输入来源、检索器、工具执行身份、确认机制、沙箱与外部消费者。主体→输入→检索/模型→授权→工具/输出消费者→实际结果，是每条假设的骨架。

| 线索 | 候选边界 | 有区分价值的最小实验 |
|---|---|---|
| 文件、对话、向量检索或缓存混用身份 | A 能否读到 B 的私有内容 | 两个隔离测试账号，各放独有非敏感标记；确认无共享/委派；比对检索引用、对象 ID 和实际内容。不能只看模型自述来源 |
| 外部网页、文档、图片、检索片段影响指令 | 不可信输入能否改变工具授权或受保护状态 | 用自建内容的普通版与受控变体，关联实际摄取片段、tool call 和授权决策；只观察已允许的无害测试动作 |
| 工具参数、MCP/插件能力或委派身份过宽 | 模型建议是否绕过确定性授权/必要确认 | 从正常调用选一个受保护测试对象；记录发起者、工具主体、参数、确认状态和资源终态，区分调用被提出、被允许与已执行 |
| 代码运行、文件系统、网络工具 | 是否越过声明的沙箱资源边界 | 先列合法目录/网络/能力；仅在获准隔离环境以边界两侧的受控标记区分，不读取宿主秘密或枚举内网 |
| 模型输出被页面、命令、查询或文档处理器消费 | 输出处理是否进入非预期执行上下文 | 按真实消费者路由到 [XSS](xss.md)、[命令](cmd-injection-rce.md)、[SQL](sql-injection.md) 等；生成危险字符串不等于下游已执行 |
| 权重、训练数据、微调任务或模型制品 | 非授权读写、来源/完整性或隔离缺陷 | 先核对资源是否本来公开、调用权限和制品归属；用获准合成训练/测试标记及制品元数据验证，禁止批量抽取真实数据或构建影子模型来凑影响 |
| 数据/模型投毒线索 | 写入者能否越过知识库/发布审批边界影响其他主体 | 只在授权隔离副本用可清理标记关联写入、摄取、版本发布和另一测试主体结果；合法维护者改自己的知识库不是漏洞 |
| token/任务放大或长时调用 | 额度/费用/可用性约束是否失效 | 优先读已有计费、队列与隔离事故材料；单次慢响应或长输出不证明全局 DoS，不向在线服务施加耗尽负载 |

这是本 skill 的实验设计，不是平台已支持上述全部功能的声明。没有对应功能即据证据记不适用；有功能但缺账号、工具日志或部署边界则记缺口。

## 执行与判读

1. 选具体保护规则与对照；复用正常功能基线和现有身份。受害者为何会摄取输入必须有现实路径，不能由测试者手动把任意内容放进高权限上下文后省略该前提。
2. 固定本轮版本、会话、工具配置、文件与输入变体，预算包含模型调用、重试、工具子请求、轮询及许可内费用上限；无法计数时先做可控单步，不自称自动限额已实现。
3. 保存实际输入与被摄取部分、响应、检索引用/对象、工具参数、执行日志和资源终态。文本“已执行”“已读取系统文件”及伪造的 tool transcript 都只属于模型输出。
4. 将不确定性定位到具体环节：未摄取、模型未采纳、授权拒绝、工具失败、实际越权。一个变体没有触发只说明该条件未复现；有限复测记录成功/失败次数与版本，不为了稳定性无限请求。
5. 证据充分时及时确认已证明的边界并交付；不要为升级成模型完全接管继续取数。清理仅涉及自建会话、文件、知识条目与测试任务，保留原证据。

内部工具日志不可见时，可以用隔离身份对照、受控接收记录及权威资源终态证明黑盒可观察的越界；例如无权会话实际取得独有私有标记且排除输入/共享来源。不要强制索取厂商内部 trace 才确认充分证据，也不能补造内部调用链或从外部结果断言特定执行权限。结论限定到实际证明的边界。

## 关键反例

- 模型准确输出公开信息、当前用户自己的上传内容、被合法共享的文档，不是训练数据泄露。合成私有标记也需排除从本轮 prompt、缓存或合法上下文进入；无模型训练/数据血缘证据时只称已证明的应用数据泄露。
- 能运行代码是沙箱正常功能时不构成 RCE 漏洞；root 字符串、容器内 UID 0、宿主风格路径都不证明宿主权限。逃逸需要实际隔离边界证据。
- 提示注入影响回答但无相应项目认可的安全影响，保留观察或规则排除；提示注入造成真实跨账号读取则不能被“模型问题默认忽略”覆盖。
- UGC 插件缺陷与官方执行器越权分开；用户可控内容只是入口，不自动改变缺陷归属。未知归属保留 rule_review。
