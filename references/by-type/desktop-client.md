# PC 客户端与本地服务

触发：授权 Windows/macOS 客户端、安装包、更新器、本地监听/IPC 或远程输入链。先保存产品/版本/签名、OS、进程与服务权限、配置、攻击者初始能力和受害者交互。小米专属受理限制读 [MiSRC §4.6](../policies/xiaomi-misrc.md)，不得移植到其他项目。

## 有依据的验证分支

| 线索 | 最小对照 | 有效结论与反例 |
|---|---|---|
| localhost 服务、IPC、URL handler | 低权限测试调用者/受控网页与合法客户端对照，核对来源/身份/消息校验和实际资源状态 | 本地监听不是互联网暴露；关键在无权主体是否获得受保护能力 |
| 更新器/高权限 helper、文件解析 | 跟远程或普通用户可控输入到验证与高权限操作；仅在批准隔离环境用无害标记 | 已能改安装介质、调试配置或同权限文件后执行同权限代码，不自动获得新的权限边界 |
| WebView/Electron/桥接 | 关联实际不可信输入、渲染上下文、桥与原生效果；保留原版配置 | 风险配置不是利用证明；技术成立与小米当前 Electron 类排除分别记录 |
| 通信、账户或设备操作 | 用两个受控身份核对 token/对象绑定及实际结果 | 根因在服务端就按 Web 规则；不能把只影响自身流量的 MITM 写成所有客户端接管 |

保持本地准备与攻击前提分离，记录 DLL/配置/目录修改究竟需要什么初始权限。远程性、额外权限、用户交互和真实业务影响分别证明；批量/持久控制只作为已有证据的影响分析，不实施持久化或扩大目标数量。

报告给版本/OS、调用链/截图、可复现 PoC、实际初始与最终权限、触发条件和必要视频。AI 静态结果/扫描线索若尚无人工分析验证，不冒称满足小米该要求；无需因此中断其他已授权的分析工作。技术充分但明确平台排除时保留 confirmed/excluded，不反复改标题。

本专题是基于 [小米 V11.0 §4.6](https://sec.xiaomi.com/#/notice/detail/244) 的条件实验设计（2026-09-17 核对）；并未完整审计各 OS/Electron 机制。具体 API/版本行为应查相应一手文档，不依靠通用载荷推断。
