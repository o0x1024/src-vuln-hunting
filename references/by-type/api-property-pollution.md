# API 属性授权、批量赋值与服务端参数污染

适用信号：响应出现隐藏字段、复杂 JSON、BFF 转发或批量接口

## 检查与最小实验

从正常响应、客户端代码、OpenAPI 找候选属性，分清“可读”与“可写”。为自建对象建立允许字段集合；一次加入一个不应可写的属性，读取权威状态确认它被忽略、拒绝还是生效。检查父对象授权之外的敏感字段访问。

服务端参数污染先证明前端接口确实构造了另一条后端请求。对重复参数、嵌套路径或结构类型差异，用两个受控标记观察实际选择顺序；不能默认框架永远取首值或末值。若有链路日志，对比每层结构化值。

## 证据与反例

多返回一个字段可能是正常模型；未知字段被 200 接受也可能被忽略。必须对应违反规则的读/写结果。格式切换只说明不同解析路径，不自动算授权绕过。

## Agent 行为

优先补正常接口已有的字段面，不做无界字典喷洒。每个批量元素计入逻辑操作预算；独立授权判断见 [访问控制](idor-access-control.md)，过滤差异见 [WAF](waf-bypass.md)。

参数名称/位置、值与类型、重复项和有依据的字段交互，按 [定向 Fuzzing](../targeted-fuzzing.md) 生成候选并根据输入是否被消费调整下一步；未知字段返回成功不等于可写。

有实际方法覆盖机制时，比较传输方法、覆盖头/字段与最终处理器所执行的动作，核对网关和后端是否对同一方法做鉴权。覆盖头被接受不等于 PUT 写入成立，写入成立也不等于服务器会执行文件；方法覆盖、对象授权、文件存储与执行链分别证明。

## 敏感字段的替代写入入口

专用改密处理器要求旧密码时，还要沿实际资料更新、导入或批量接口检查同一敏感字段的写入路径。以自有账号核对字段白名单、目标主体、重新认证要求和密码的权威终态，再恢复测试状态；普通资料更新返回成功不代表密码已改变。字段授权缺陷与 CSRF 分开判断：跨站触发仍需证明真实浏览器可构造请求并自动附带有效身份。

若实际处理器可能接受 GET body，分别记录传输字节、Content-Type、网关保留情况、框架选值与应用最终对象；用两个受控标记辨明 path/query/body 同名字段的优先关系。客户端允许发送 JSON 不证明服务器消费，服务器消费也不证明授权已绕过；不默认所有代理都转发或所有框架都忽略这类正文。

## 身份提供方的属性写入边界

用户池属性的 mutable、app client 的可写权限、实际API调用身份和业务信任用途分别核对。对 Cognito，[当前app client文档](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-settings-client-apps.html)明确不允许 app client 获得 email_verified/phone_number_verified 写权限；历史CDK配置陈述须绑定其当时版本，不能推广到当前部署。[UpdateUserAttributes](https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_UpdateUserAttributes.html)使用含所需scope的已登录用户access token，[AdminUpdateUserAttributes](https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_AdminUpdateUserAttributes.html)则需要IAM授权并可设置验证状态。scope名称含admin不等于AWS管理员权限。用获准配置或自有用户核对属性终态、验证流程和下游信任，不由schema标志或请求接受直接推导邮箱验证绕过；可能触发邮件/短信的调用计入独立许可。官方资料核对：2026-10-09。

单个对象参数被拒绝、重复参数却返回多个对象时，保留每层原始重复项与结构化结果，关联验证器检查的对象集合和业务消费者实际读取的集合。用两个已知自建对象逐个/重复对照，确认每个返回标记的归属与允许受众；不能只凭200或默认框架取首/末来解释。原生批量接口同样按每个元素核对，重复项与各自操作共同计入预算。

URL被重新写入链接或后端请求时，分别核对HTML转义、URL组件编码和下一次query解析。某个字段中的分隔符先被解码，再拼入新URL，可能变成额外参数；HTML中安全显示不保证下一层仍是一个参数值。保存原始字段、生成的href/实际请求及每层参数集合，以两个受控标记辨明选值和允许动作，不能从源帖混杂PHP/引号的伪代码认定当前实现或通用取末值。

## 隐藏email字段与账号身份变更

个人资料接口原本只显示firstName/lastName/mailingList，手动增加email后出现变化，提示后端字段绑定需要检查。前端隐藏/禁用字段不等于服务端禁止它；只看到提交JSON也不能证明存储、验证状态或登录身份确已改变。

以合成账号比较正常编辑与额外字段的权威读回、邮件所有权验证、登录/找回账号映射、组织身份及旧会话/凭据代际。区分联系邮箱和安全身份邮箱、允许修改与需要重新验证的变更，保留产品政策反例。只变更自有合成地址，不向真人收件人发验证/重置消息；没有后续能力时交付字段写入边界，不能直接叫完整账号接管。

## 隐藏角色字段与实际能力变化

普通资料编辑请求出现is_admin等字段后，区分客户端可提交、服务端存储、权威角色分配及受保护动作实际授权。页面状态变成管理员文字或提交成功，可能只是回显/无效字段；以自有隔离账号与授权规则核对写入前后及独立受保护读操作，保留会话代际、角色来源与正常编辑对照。动态角色、缓存或身份提供方映射也需真实消费者证据，不能从单个隐藏字段推完整提权。

## 从JS词汇批量生成JSON的语义限制

JS中包含UUID的词汇不证明它们都属于同一个接口，更不证明每个字段允许同一UUID字符串。记录静态词所在调用点、对应路由/方法、结构类型、字段必选性及对象所属角色；布尔标志isUUID、组织/司机/车辆标识与大小写不同的属性分开处理。

一次塞入全部候选会混合未知字段、错误类型、重复键及字段相互作用，无法归因哪个值被消费。先恢复正常请求，再按单一有依据的字段差异和必要交互观察权威结果；保留序列化前键序列与服务端实际解析对象。帖子示例的全部字段同值与请求截图没有响应，不代表漏洞、正确字段模型或爆破授权。

## 否定状态的false、null与空数组

把banned从false改为null或空数组，不只是变布尔值：字段缺省、JSON null、数组、合法布尔、schema拒绝、默认值及持久化清除是不同分支。旧图给false→401与null→204→unbanned，但缺服务端读回和真实能力；204只证明响应无内容，不能补成状态解除或授权成立。

沿字段绑定→类型验证→业务条件→权威状态→受保护动作，用隔离自有对象分别对照缺字段、合法false/true及一个有依据的类型差异。核对“未禁止”的判定是否错误地来自未设置/未知状态，或字段本就不可由该角色写入；严格拒绝、忽略未知字段、保持原状态与合法更新作反例。保留代码/读回证据，不向所有入口塞null/数组，不解除真实用户限制；字段写入、否定逻辑与会话权限分别报告。

## ID的标量、数组、嵌套对象与通配消费者

旧API图把id标量改数组/嵌套对象、URL重复id和user_id星号并列为401/403后绕过招式。数组改变类型与集合基数，嵌套对象改变绑定路径，重复项需逐层保留首/末/集合规则，星号只有实际消费者解释成通配时才有该语义。原数字、字段名或成功状态不足以证明另一受众对象可读。

用两个获准自建对象的不同普通标记核对解析→schema/类型→验证对象集合→实际读写集合→响应受众，一次选择一个有依据的变体。严格拒绝、未消费、仅公开摘要、合法批量且逐项授权均作反例；整组输入预算与返回字段最小化。不发送victim ID、以星号索取全库或把这些表示称通用认证绕过。

## 申请状态字段与审批转换的权威结果

pending0→1或PENDING→Accepted只是字段候选，不同产品枚举/状态含义不同。将对象所属身份、字段写权限、当前状态、审批者资格、允许转换/前置条件和服务端权威状态分开；保存或回显Accepted可能没有触发真正审批及下游权益。

在隔离合成申请或获准源码/日志中比较正常申请、合法审批、普通角色字段更新与拒绝条件，关联状态版本/原子转换、审批来源和实际受保护能力。可自改草稿/撤回、未知字段忽略、严格拒绝及未触发权益作反例；不批准真人申请/支付/权限变更，accepted奖励图不补全审批链。来源：[保存帖](https://x.com/i/status/1398622552851845123)。
