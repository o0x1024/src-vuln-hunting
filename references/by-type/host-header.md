# Host 与代理头信任

适用信号：绝对链接、密码重置链接、虚拟主机、代理转发

## 检查与最小实验

固定获准目标连接，记录 TLS SNI、Host/:authority 与代理头各自角色；从实际流量/配置选择候选头，逐项用受控标记比较 URL 生成和后端路由。

密码重置场景仅给自建邮箱触发一次获准流程，检查生成链接是否带敏感令牌及落点。缓存场景转专门手册；不要在普通测试里制造重复 framing 头或 desync。

## 证据与反例

Host 被反射到无敏感文本不等于账号接管；外部 Location、重置链接污染和缓存跨请求复用是不同影响。虚拟主机正常选择也不证明内部服务越权。

## Agent 行为

不要因共用 IP 就测试未知租户；代理头或 Host 改动不能扩大 Scope。保存原始目标/头值与实际落点，报告只到已验证边界。

## 归档案例补充：范围与服务身份

Host/SNI/连接地址及应用资源可能指向不同边界，先逐一核对授权及服务身份。代理正常路由不是漏洞；不从历史 DNS 或共享 IP 派生无限组合请求。见 [K14](../research/crawl-xz-patterns.md)。

## 邮件模板与共享托管错误页

头值进入密码重置邮件时，区分URL构造、模板变量输出和拼入模板源码。Host污染成立不自动说明X-Forwarded-Host被模板编译；只在已有数据流依据的分支比较无害常量表达式与字面量，保留原始邮件/响应和真实渲染端，按[SSTI](ssti.md)核对服务端解释边界。表达式回显、算术结果和执行能力分别记。

共享托管代理的404页也可能有独立消费者。若正常流量/配置提示某代理头决定租户路由，关联连接目标、头值、选中租户、错误页内容来源与缓存键；在获准隔离租户及合成路径上比较带标记响应和随后不带该头的普通请求。读取自己可定制的404、一次路由变化或命中页面不证明污染另一租户缓存。实际缓存跨请求复用转[缓存投毒](cache-poisoning.md)，服务商与其他客户范围分别核对，不注册付费托管账号或测试未知客户补证明。

## absolute-form与Host的不同消费者

旧密码重置图把origin-form改为含正常目标authority的absolute-form，同时Host仍为另一主机，叙述从404到生成污染链接。[RFC9112 §3.2.2](https://www.rfc-editor.org/rfc/rfc9112.html#section-3.2.2)要求代理和源服务器在absolute-form使用request-target的主机信息，不能假定每层实际实现都按同一字段生成邮件（2026-10-09核对）。

固定连接/SNI、原始请求形式、代理改写、路由选值和应用URL构造分别追踪；前层选中正常服务不证明后层Host已可信。源图只有示意请求/链接，没有原始邮件、令牌消费或接管结果。用获准自有恢复流程的无秘密标记核对构造，不改真实收件地址、重放生产恢复链接或直接认定ATO。

## Laravel代理可信来源与可信字段

历史图正文称X-Forwarded-For，示例实际使用X-Forwarded-Host，须保留字段差异。[Laravel 12.x请求说明](https://laravel.com/docs/12.x/requests#configuring-trusted-proxies)分别配置可信代理与可信头，并另设Trusted Hosts；Host参与absolute URL生成（2026-10-09只核读相关段落）。这份版本文档不证明所有历史/当前Laravel默认都可被任意头覆盖。

沿真实部署版本、入口代理/改写、来源限制、有效可信头位、host校验与重置URL消费者逐边核对。连接目的地、客户端IP和URL host不同；恢复链接里外域、令牌被提供与最终恢复能力还需分别留证，不能从示例POST直接认ATO，不修改线上配置或触发真人恢复。

## localhost头值与真实连接和路由

把Host批量替换为localhost不会把原TCP连接、TLS SNI或真实客户端IP自动变成本地。分别确认入口、虚拟主机选择、代理后端路由、可信头处理及受保护业务能力；默认vhost公开页或WAF返回变化不是身份绕过。

规则限定到获准目标与既有普通请求，先静态比较有效配置/日志并保留替换前后完整出站数据。未知路由可能进入另租户或内部服务，范围另核；不从“could bypass”把所有文件目录暴力枚举接到全局替换规则。

## 源站Host路由与限流执行面

历史xmlrpc/pingback找到源地址之后修改Host的叙述，还缺实际TCP目的地、TLS SNI、代理路由、后端身份和限流执行位置。Host头值不会自动改连接地址；边缘、应用、单接口或业务状态的限额也可能按IP/用户/token/租户不同键执行。

在获准配置与已有日志中将正常入口和候选路径关联到同一处理器/限额键，只对已证的具体操作表述差异。一个请求/一个接口的响应不能证明“所有功能都没有限流”，回连源IP也不证明唯一生产源站；不触发pingback、绕过实际限额或对真人账号增加尝试。

## 下划线主机名的解析层与同源边界

带下划线的域名候选和HTTP400截图不能证明SOP被绕过。域名注册规则、DNS标签、证书命名、浏览器URL解析、应用正则和代理路由是不同消费者；某一层接受或拒绝不代表其他层相同。[WHATWG禁止主机码点](https://url.spec.whatwg.org/#forbidden-host-code-point)列表没有下划线，但这不保证任意含下划线域名可注册、可访问或被所有部署接受（2026-10-09核读）。

保留输入字节、每层解析后的hostname/规范化结果、真实连接地址与浏览器最终scheme/host/port来源。黑名单漏掉字符串可能只是过滤缺口；需另证允许的资源、目标上下文或保护能力确实越界。400只说明当前请求失败，没有真实跨源读者或注册状态；不要由示意域名反推当前国家域注册规则或把解析差异当已复现同源绕过。

## 转发字段角色与逐跳可信选择

Host覆盖清单混列X-Forwarded-For、Proto、Host、Server和自定义Override；名称相似不能认定它们都覆盖URL主机。[RFC7239 §5、§8.1](https://www.rfc-editor.org/rfc/rfc7239.html#section-5.3)分别定义for的节点、host的请求主机和proto的协议，并说明转发字段可由客户端/中间节点伪造（2026-10-09核读）。非标准头只有真实应用消费才参与该边界。

按实际入口协议/代理链记录原始字段、删除/覆盖/追加策略、可信来源、多个元素/重复字段选择、应用最终host与URL消费者。absolute-form请求行、Host字段和连接/SNI分开比较；换行示意和重复Host不是通用合法请求或普遍绕过。Burp全局加头规则还会污染正常基线和其他域，配置截图不证明请求已发送或后端已采用；已有获准记录需标明规则生效范围及真实出站字节。

## 同IP、DNS与虚拟主机路由的不同事实

vhost配图说多个名称到同IP意味着在该主机etc/hosts中配置；这推断不成立。名称解析可来自DNS/客户端静态配置等，服务器依据TLS SNI、Host/:authority、端口/代理及具体virtual-host规则选消费者；共享IP不证明同租户或同权限。

固定真正连接目标并记录各层名称、实际后端、默认站点和允许/拒绝响应，核对同IP多个应用的身份/缓存/流隔离。每个新Host或租户仍需正式范围，即使连接IP没变、速率有限也不能自动覆盖第三方。以获准配置/既有日志或合成虚拟主机解释路由，不继承图中任意名字穷举或因作者判断风险低就跳过具体隔离证据。来源：[保存帖](https://x.com/i/status/1402936148578783233)。
