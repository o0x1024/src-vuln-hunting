# 汽车终端与组件条件专题

触发：明确获准的车端材料、零部件、仿真/台架或已有漏洞证据。记录整车型号、零部件硬件修订/固件、组件版本和测试环境。小米规则见 [MiSRC §4.5](../policies/xiaomi-misrc.md)。持有车辆或车机不自动授权云端、其他车辆、道路测试或安全关键动作。

## 选择下一步

先从已有架构和流量关联云端账号/App→车机/TBOX→网关→功能域。每条边独立标已观察、材料支持、未知；车机可执行普通代码不能直接推导车控或整车接管。

| 线索 | 可推进工作 | 确认边界 |
|---|---|---|
| 云端车辆对象/轨迹/指令接口 | 对既有受控账号和测试对象做身份、归属及正常结果复核；获准时按 API 专题做最小验证 | 服务端身份授权问题；一个测试对象不证明任意车 |
| 车机/组件 IPC、应用加载与权限 | 离线跟输入/签名/权限路径，有批准隔离台架时以无害标记观察执行主体 | 普通/特权进程及组件权限，不能外推网关或其他功能域 |
| 蓝牙/Wi-Fi/NFC、网关消息 | 核对协议、配对、距离、重放条件及接收链；仅在明确范围的仿真/台架观察状态 | 协议可达或消息 ACK 不等于执行车控；真实效果需要权威状态 |
| crash/故障/恢复线索 | 复核已有日志、输入、版本、恢复方式和实际影响；是否允许隔离复现另按动作许可 | 可复现的组件故障与整车可用性分开；fuzz 报错不直接确认 |

本 skill 不执行真实车辆的制动、转向、动力、解锁/开走等安全关键控制、破坏或持久化。无合适隔离环境时交付静态候选/已有证据分析及缺口，不能为满足严重等级进行道路或真实车控试验。即使有台架，动态动作也需在原任务明确范围内且不产生安全关键物理后果。

保留所用供应链/诊断资料来源；泄露诊断工具/账号、厂商已知中继问题和未知但不可复现的现象按当前条款分别处理，不能以汽车高价值绕过排除。材料不足时不声称具备故障注入、侧信道、CAN 或 ECU 全覆盖能力。

交付型号、版本、权限/网络/物理条件、利用链各节点证据、实际组件与整车影响、PoC/源码与必要视频、修复建议和恢复状态。零部件与整车范围独立定级，原始技术证据不因平台拒收删除。

资料：[小米 V11.0 §4.5](https://sec.xiaomi.com/#/notice/detail/244)，2026-09-17 核对。这里只提供任务分流与证据方法，具体车端协议需按实际授权产品另查一手资料。
