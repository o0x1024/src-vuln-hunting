# XSSI 与 JSONP 跨站数据读取

> 需要提升危害、判断值不值得交，或当前思路挖不动时，先读这些语料与 [成交语料索引](../research/corpus-index.md) 的过审率表，再回到下面的实验设计。

适用信号：动态脚本、回调包装、JSONP 表示或按登录身份返回数据的脚本资源。来源提示“改成.jsonp”仅为格式候选，先确认真实处理器接受什么。

## 检查与最小实验

以自有账号的合成私密标记建立正常与未登录响应对照，保留响应类型、回调包装及实际数据。再从获准受控外站，以真实浏览器核对资源能否被作为脚本消费、身份是否自动附带，以及该外站是否真正取得标记。记录浏览器版本、Cookie策略、响应头和错误；不能手工补入攻击页无法获得的令牌。

## 确认与反例

需要不应获知该内容的来源实际取得身份相关私密数据。JSONP格式存在、脚本请求发出、回调名可改或200响应不充分；公开数据与允许的跨域接口作为反例。callback语法注入、数据泄露和目标站点XSS分别判定，读取成立也不自动证明接管。

## Agent 行为与来源

只观察合成标记，不读取真实用户数据。旧浏览器的错误消息或原型技巧需对应版本和可达消费链，不能将历史示例当当前支持。跨站状态变化转[CSRF](csrf.md)，XHR/fetch跨源读取转[CORS](cors.md)，目标上下文执行转[XSS](xss.md)。

机制依据：[OWASP WSTG v4.2 · Cross Site Script Inclusion](https://wstg.owasp.org/stable/4-Web_Application_Security_Testing/11-Client-side_Testing/13-Testing_for_Cross_Site_Script_Inclusion/)（2026-10-09核对）。受控实验是本skill的综合设计，未在当前目标运行。

搜索URL中出现callback只补接口候选，也可能是支付/事件回调文档或普通字段。先读取获准正常响应确认脚本包装和实际处理器；搜索摘要、截断URL或参数名不能证明JSONP，更不能证明CSP绕过或身份数据外读。

MIME声明、响应脚本内容、nosniff、请求destination与真实浏览器处理分别记录。nosniff会对script-like目的地要求JavaScript MIME；该检查未阻挡不代表整个加载流程允许，也不保证身份数据外读。用正常/未登录对照及浏览器错误区分格式拒绝、其他加载限制与实际取得合成标记，不采纳“application/json且缺nosniff必成功”。机制核对：[WHATWG Fetch §3.6.1](https://fetch.spec.whatwg.org/#should-response-to-request-be-blocked-due-to-nosniff)（2026-10-09）；此处未在目标实测。

## 接收器依赖与真实跨站读取

正常响应若确实调用嵌套命名空间或依赖预先定义的函数，在获准受控页面先按实际调用签名提供最小接收器，再加载该脚本，分别记录依赖未定义错误与接收合成标记的结果。接收器只是恢复脚本消费者的必要环境，不能使普通JSON自动成为可执行脚本，也不能补出浏览器未自动携带的身份。回调成功、异常消失与跨站取得私密数据分别判断；不要运行来源中的完整PoC或用手工认证头代替外站浏览器条件。

## JSON数组、CORS与跨站请求的区别

JSON响应长成数组/对象，不自动成为可外读脚本。CORS按当前外源、身份、响应许可及实际读取判断；JSONP/XSSI还需真实脚本/回调消费者或可观察的跨站通道，CSRF则核对自动身份附带的非预期状态动作，三种结论不能互相代替。

只说“让用户点击链接把数据送走”缺少浏览器如何读到私密字节的关键边。保留Content-Type、包装/前缀、身份取得、浏览器解析/CSP及合成私密标记的真实接收证据；公开JSON数据和只发请求但读不到内容作反例。缺细节时不复制旧JSON-hijacking全套PoC，也不诱导真实用户点击或外送私密响应。
