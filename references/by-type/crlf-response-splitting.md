# 响应头注入与 CRLF

触发：路径、跳转参数、文件名或其他可控值参与 Location、Content-Disposition、自定义响应头或响应构造。先关联输入→解码/规范化→应用或网关响应头 API→实际响应，区分每一层。

## 最小对照

用正常值和唯一无害标记建立基线；只在有具体响应构造线索时，选择一个分隔符或编码变体。保留实际发送字节、HTTP 版本、重定向各跳和原始响应，核对是否新增了独立响应头，还是仅在原值/正文中显示了字符。HTTPS 跳转前的 301/302 响应也需观察，不能只看最终页面。

代理界面可能重新排版或解码响应，不能用展示换行证明线上存在头边界变化。网关拒绝、应用转义、协议编码与浏览器处理分别记录；单个组件的行为不能推广到整个栈。使用受控资源和单次有界请求，不在共享响应中注入会话、缓存或执行内容。

自动匹配应区分真实头区、正文和工具展示，保留原始字节及唯一标记。固定大小写、冒号后空格和单行格式的正则可能漏掉等价展示，也可能把正文样例误判成新头；匹配结果仍需解析边界及接收方证据，不使用测试 Cookie 覆盖现有会话来补证明。

## 能力与反例

新增无害测试头可证明有限的响应头注入能力，但不能自动证明响应拆分、XSS、会话覆盖或缓存投毒。每种影响继续核对接收方、可控头/正文、浏览器处理、缓存键及实际受保护状态；需要浏览器效果时保存真实浏览器证据。

输入原样反射、百分号编码被保留、Location 含可控字符串或状态码改变都不是独立头注入证明。开放跳转按 [重定向](open-redirect.md) 判断，共享缓存效果按 [缓存投毒](cache-poisoning.md) 判断；解析差异沿用 [WAF 与逐层解析](waf-bypass.md)。

报告交付输入位置、处理链、基线与变体、原始响应、已证明能力及影响限制。此方法提炼自已保存的历史帖子，不表示已复现历史产品或当前目标。
