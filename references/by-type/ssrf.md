# 服务端请求边界

## 适用信号与前提

URL 导入、预览、截图、PDF、webhook、代理或下载。先确认功能是否本来允许外部请求及被禁止的目的地/协议边界；准备获准的受控接收端、唯一随机标记和日志。

## 最小实验

先发正常基线，再更换为获准受控 URL，关联请求窗口和接收事件，判断是浏览器、后端服务、网关还是异步验证器访问。预期 webhook 回调成功本身不是 SSRF 漏洞。

有明确限制绕过假设时，依据实际 URL 解析/重定向行为选择一个变体；重定向每跳和实际目的地必须仍获准。仅在目标与动作同时明确允许时验证内部边界，不默认探测内网端口或云元数据。

## 确认与反例

确认服务端请求违反了有依据的目的地/协议/数据访问规则。DNS 回连只证明解析行为；不能据此声称读到内网 HTTP、凭据或执行命令。外部 HTTP 回连也可能是正常预期功能。

排除客户端加载、安全网关预取、异步扫描、共享 DNS 缓存与旧标记。每个实验使用新标记，带外日志不可混为一个发现。时间差需要独立对照，不能从端口超时直接推断服务存在。

## 收录与证明边界

按 [影响与收录](../impact-and-acceptance.md) 区分 DNS 解析、已归因的服务端请求、内网差异响应与真实回显。项目可能对这些能力设置不同等级或排除项，不能跨平台套用；用户提供的 [规则样例](../policies/src-policy-examples.md) 只供比对。

若当前项目明确提供授权验证服务并规定回显即满足最低证明，取得该服务的可归因回显后即按有限能力评估，不要求继续读真实内网数据。只有 DNS 日志、缺乏后端归因的 HTTP 回连，或正常允许的 URL 抓取均不能冒充该证明。最低条款满足不等于已经证实内网凭据或系统权限。

## 下一步、停止与报告

不把 SSRF 自动升级为内部服务写入、持久化或获取生产元数据凭据。不能确认边界时保存请求能力线索；证据不足可以待补证。带外标记不包含系统输出或敏感信息，只用已获准接收端。

报告区分解析、HTTP 请求、内容读取和更高能力，附触发归因、边界与未验证限制。云细节见 [云入口](../cloud/cloud-security.md)，通用标准见 [验证](../verification.md)。

## 调研补充：可执行检查点

- 画出输入→URL 解析/校验→DNS→重定向→实际连接链；只比较获准受控地址。原始字符串看似在白名单内与最终目的地相同是不同命题。
- 为每个实验、异步任务和回跳分配独立标记；带外接收时间、协议和服务端任务 ID 要能关联。浏览器预取、邮件扫描和安全设备也可能回连。
- 对跳转和解析差异先在本地验证 URL 语义，再按目标规则检查每一跳；不因初始 URL 在 Scope 内就允许越界落点。
- HTTP 到达只能证明已归因的取址能力；功能本就允许任意公网抓取时，需再指出具体被突破的限制。没有获准内网靶点时不能自动扫内网或读取云元数据凭据。

## 归档案例补充：文档任务归因

HTML/PDF 预览、转换和后台抓取分别归因到任务与消费者；格式保留、外部回包或浏览器弹窗不能直接证明后台越界请求。优先项目指定的无害验证方式，详见 [文档处理](document-rendering.md)。
