# 服务端请求边界

## 适用信号与前提

URL 导入、预览、截图、PDF、webhook、代理或下载。先确认功能是否本来允许外部请求及被禁止的目的地/协议边界；准备获准的受控接收端、唯一随机标记和日志。

## 最小实验

先发正常基线，再更换为获准受控 URL，关联请求窗口和接收事件，判断是浏览器、后端服务、网关还是异步验证器访问。预期 webhook 回调成功本身不是 SSRF 漏洞。

有明确限制绕过假设时，依据实际 URL 解析/重定向行为选择一个变体；重定向每跳和实际目的地必须仍获准。仅在目标与动作同时明确允许时验证内部边界，不默认探测内网端口或云元数据。

## 确认与反例

确认服务端请求违反了有依据的目的地/协议/数据访问规则。DNS 回连只证明解析行为；不能据此声称读到内网 HTTP、凭据或执行命令。外部 HTTP 回连也可能是正常预期功能。

排除客户端加载、安全网关预取、异步扫描、共享 DNS 缓存与旧标记。每个实验使用新标记，带外日志不可混为一个发现。时间差需要独立对照，不能从端口超时直接推断服务存在。

## 收录与证明边界

按 [影响与收录](../impact-and-acceptance.md) 区分 DNS 解析、已归因的服务端请求、内网差异响应与真实回显。项目可能对这些能力设置不同等级或排除项，不能跨平台套用；用户提供的 [规则样例](../policies/src-policy-examples.md) 只供比对。京东 JSRC 另有强制口径：测试必须使用其官方验证目标，并按资产类型×回显程度×可利用协议分档，纯固定格式探测与"不通内网"资产入忽略档，见 [JSRC 配置](../policies/jd-jsrc.md)。

若当前项目明确提供授权验证服务并规定回显即满足最低证明，取得该服务的可归因回显后即按有限能力评估，不要求继续读真实内网数据。只有 DNS 日志、缺乏后端归因的 HTTP 回连，或正常允许的 URL 抓取均不能冒充该证明。最低条款满足不等于已经证实内网凭据或系统权限。

## 下一步、停止与报告

不把 SSRF 自动升级为内部服务写入、持久化或获取生产元数据凭据。不能确认边界时保存请求能力线索；证据不足可以待补证。带外标记不包含系统输出或敏感信息，只用已获准接收端。

报告区分解析、HTTP 请求、内容读取和更高能力，附触发归因、边界与未验证限制。云细节见 [云入口](../cloud/cloud-security.md)，通用标准见 [验证](../verification.md)。

## 调研补充：可执行检查点

- 画出输入→URL 解析/校验→DNS→重定向→实际连接链；只比较获准受控地址。原始字符串看似在白名单内与最终目的地相同是不同命题。
- 为每个实验、异步任务和回跳分配独立标记；带外接收时间、协议和服务端任务 ID 要能关联。浏览器预取、邮件扫描和安全设备也可能回连。
- 对跳转和解析差异先在本地验证 URL 语义，再按目标规则检查每一跳；不因初始 URL 在 Scope 内就允许越界落点。
- HTTP 到达只能证明已归因的取址能力；功能本就允许任意公网抓取时，需再指出具体被突破的限制。没有获准内网靶点时不能自动扫内网或读取云元数据凭据。

## 归档案例补充：文档任务归因

HTML/PDF 预览、转换和后台抓取分别归因到任务与消费者；格式保留、外部回包或浏览器弹窗不能直接证明后台越界请求。优先项目指定的无害验证方式，详见 [文档处理](document-rendering.md)。

请求来源 IP 只提供归因线索：与客户端 IP 不同不自动说明来自业务后端，相同也不能单独排除后台请求。关联一次性标记、触发窗口、实际协议、跳转链及可用任务证据；网络出口、安全扫描与浏览器加载仍需区分。开放跳转和请求能力分别成立，也不代表组合链已经越过目标限制。

遇到 localhost、回环地址或本地端口引用，先确定名字由谁解析、连接由浏览器/测试机/后端哪一进程发起，以及受控服务实际位于哪里。测试者在本机启动服务后看到页面，不能证明目标服务器访问了自己的回环接口。用受控端记录和调用链区分客户端导航、本地开发依赖与服务端取址；同一个名称在不同执行主体上不代表同一目的地，不为消除歧义探测未知内网。

## 中继协议的两段边界

出现TURN/WebRTC中继线索时，分别记录客户端到中继与中继到peer的协议、测试身份、allocation/permission与目的地限制。客户端使用TCP/TLS不证明peer侧也可用TCP；RFC8656定义的peer侧是UDP，其他能力须有具体扩展/实现依据。分配成功和正常通话不证明可达被禁止网络；仅用获准受控peer与无害标记关联实际中继数据、身份和边界，不探测未知内网/元数据或测试带宽洪泛。

协议依据：[RFC8656 §3.1、§21.2](https://www.rfc-editor.org/rfc/rfc8656.html)（2026-10-09核对），包含传输分层与peer地址限制；上述实验是本skill的综合设计，未复现源帖所称平台能力。

“localhost编码列表”先拆成地址表示、DNS名字和URL语法三类，跟到真实解析库、地址族、规范化、解析结果与连接主体。[RFC4291 §2.5.2–2.5.3](https://www.rfc-editor.org/rfc/rfc4291.html#section-2.5.2)（2026-10-09核对）将::定义为未指定地址、::1定义为环回地址；URL中的[::]不能直接当成[::1]的等价写法。若实现对未指定地址有本地特殊处理，需具体库/版本和受控结果，不能反推协议定义。数字、八进制外观、域名或表情字符也不保证被同一客户端接受或连接环回；先离线解析，获准连接仅对受控目的地，列表文字不补内网测试许可。

短IPv4写法不是任意删除字符串中的零。将点分部件、每部件数值/进制、最后部件承载范围和最终序列化地址一起保存；[WHATWG IPv4解析算法](https://url.spec.whatwg.org/#concept-ipv4-parser)（2026-10-09核对）对少于四个部件记录验证错误后仍有后续数值处理，这与立即拒绝不同。真实后端库可采用不同规则，URL文本缩短或本地规范化不证明WAF绕过/目标连接。只在离线和获准受控目的地核对校验与消费端差异，环回/私网地址例子不自动允许连接。

参数作为下游URL一部分时，保存原输入→每次百分号解码→组件编码/拼接→解析/校验→实际下游请求的顺序。%2523一次解码是%23，两次才是#；%23%32%35一次解码是#25，不能把它们当同一个“井号双编码”。只要#最终作为URL片段分隔符，其之后的内容按[RFC3986 §3.5](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.5)在解引用前与其余URI分离（2026-10-09核对）；若仍是编码组件数据，则需按实际消费者判断。下游报错可能来自截断/无效路由，不直接证明改变目的地主机或SSRF。只以已有调用线索和获准受控资源核对，不探内网。

## 缓存层的ESI消费者

XSS与ESI解析是两个入口/消费者条件。有缓存不代表已启用ESI，浏览器执行也不意味着可控制缓存层解析的模板字节。[Varnish ESI官方指南](https://www.varnish.org/docs/users-guide/esi/)示例通过beresp.do_esi启用响应解析，具体实现只支持其ESI子集（2026-10-09核对）。按目标当前配置/版本、响应所在层、标记消费和实际子请求归因，再核对可控制目的地/头与被禁止边界；合法片段包含作反例。来源include字符串不能保证绕Cookie/XSS过滤或发起任意外部请求，不污染共享缓存、接触元数据或扩大到内部写入。

## 公开表单的回连与模板执行分开

联系表单中的HTML/Markdown图片触发受控接收端请求时，分别关联请求标记、时间、请求者和处理阶段：浏览器预览、邮件客户端、安全扫描器或后端抓取都可能解释回连。某种引号形式命中，只说明该输入可能被其中一个消费者解析，不能推已经进入服务端模板。

SSRF需要该后端请求跨过实际目的地边界；SSTI另需表达式进入真实模板引擎并被求值的独立证据。优先隔离合成工作流及已有日志/调用链，不因一次回连就组合模板载荷或让真实支持人员消费内容。

## URL用户信息与后端认证

URL里的user:pass@属于用户信息，不等于所有后端客户端都会发认证头、凭据有效或已登录内部服务。[浏览器fetch文档](https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch#exceptions)列出URL含凭据可导致TypeError（2026-10-09核对）；服务端HTTP库的接受/认证行为则需当前实现证据，不能从浏览器或字符串格式推广。

从获准配置/已有脱敏请求区分URL解析目的地、实际客户端、认证方案、头构造/挑战、重定向后的凭据转发与最终主体能力。只能在授权合成服务里使用自有测试凭据，错误码、userinfo保留或请求发出不证明内部登录；不猜内网密码、使用泄露凭据或凭SSRF题名扩展内部访问。

## NAT Slipstreaming的执行主体与ALG消费者

浏览器发起流量与服务端取址分别建模。历史NAT Slipstreaming线索涉及网页可控数据、浏览器/网络分段、网关的应用协议解析及动态连接映射；网关因误认信令而建立入站通道，不能把这类效果直接记成目标后端SSRF。[原研究概述](https://samy.pl/slipstream/)明确ALG支持等前提，并区分2020 v1与2021 v2（2026-10-09只读核对概述）。正文的“任何TCP/UDP、无论防火墙”不是当前所有部署结论。

审阅获准配置或隔离实验时分别绑定浏览器构建/端口限制、网关固件和ALG状态、实际执行主机、网络位置、映射变化及合成服务的连接结果。网页请求成功、内网地址猜测或公网出口相同均不证明映射已建立；即使建立通道，服务认证与敏感能力仍另有边界。保存两段协议证据，不从研究页运行PoC、探测未知内网或改变生产防火墙。

## 邮件域、投递链与连接归因

邮箱字段首先经过校验、队列和投递组件，域名的DNS解析不等于应用已经直接连接该域的A记录。[RFC5321§5.1](https://www.rfc-editor.org/rfc/rfc5321.html#section-5.1)规定MX查找及无MX时的隐式回退；还须区分外部邮件提供商、转发、解析器与最终SMTP连接者。通配DNS服务把名字解析成某IP，不自动证明邮件进入该IP的25端口。

按受控域/已有日志分别关联输入、查询类型、MX/地址结果、任务/队列、连接端与响应。不存在域和正常域的错误差异可能只来自校验/DNS失败；缺限流也不能直接定为localhost DoS。用合成收件流程及许可内证据说明越界消费者，不指向真实内网、localhost或第三方动态DNS、不制造邮件洪泛；观察不到连接仍是未验证分支。2026-10-09只读上述RFC相关段落。

## 地址表示、未指定地址与解析边界

环回地址候选清单先核语法：IPv6主机与端口边界需要正确括号；历史http://0000::1:80不能直接当有效IPv6URL。[RFC4291§2.5.2–3](https://www.rfc-editor.org/rfc/rfc4291.html#section-2.5.2)分别定义::为未指定地址、::1为环回，二者不能简单归为相同目的地。[WHATWG地址解析](https://url.spec.whatwg.org/#concept-ipv4-parser)另有整数、十六/八进制及少于四部件的处理，不能默认所有后端库采用同一算法。

沿原串→校验器→URL/地址解析→DNS/实际连接→重定向每跳关联目的地，userinfo中的@、特殊表示、非法语法和本地规范化分别记录。离线解析成功不是SSRF或WAF绕过证据；只用已提供日志和明确获准受控目的地，不按清单连接环回、私网或重定向到内部服务。2026-10-09核读规范相关段落，未进行目标连接。

旧地址清单还把0177.0.0.1标为十进制：按WHATWG算法其前缀部件按八进制处理。自写离线整数运算结合规范规则核对：2130706433与017700000001对应127.0.0.1；三部件0x7f.0x1.0x1对应127.1.0.1，不能都写成同一个127.0.0.1。http://0解析到0.0.0.0时仍是未指定地址，不应直接归为环回；实际库拒绝/规范化/连接行为保持未知。本次只作算术与规则核对，无目标连接。

## WordPress pingback的历史修复条件

XML-RPC入口存在、方法名可见和pingback实际发起越界请求是不同能力。[WordPress3.5.1公告](https://wordpress.org/news/2013/01/wordpress-3-5-1/)于2013-01-24说明修复pingback相关SSRF/端口探测并提及此前版本；这是历史修复信息，不能由旧帖子或当前/xmlrpc.php状态推定所有现行WordPress可用。

核对实际核心/插件版本、补丁、方法注册/启用条件、网络出口、输入校验与请求归因；被禁止、缺方法和无连接不能合并为成功。优先代码/配置/已有受控日志和无害合成引用，实际连接仍需独立许可，不扫描端口、指向真实内网或放大请求。2026-10-09核读公告相关正文，未访问来源PoC。

## 上传控件类型与服务端取址契约

把HTML input的type=file改为url，只改变客户端控件/序列化候选，后端可能仍期待multipart文件、忽略字串或拒绝它。沿实际字段字节、媒体类型、后端处理器、任务与取址者核对；存在URL输入或上传格式支持不保证有服务端网络访问。

SVG/XML/视频/PDF的外部引用分别依实际解析器、支持协议/版本、策略和任务消费，不能推“SSRF always there”。用获准已有配置/日志或小型普通标记分析单个有依据的分支，保留纯客户端处理、禁用外部引用与拒绝格式反例，不改真实上传控件投载荷、全格式遍历或把CT名称接入70并发ffuf。

## 原始响应、页面源码与回连观察通道

界面没有显示结果时，先核对原始响应、HTML源码/嵌入序列化数据及解码层，不能据可见DOM就认定blind SSRF。回连出现与响应正文可取得分别记录，并绑定同一请求、服务端实际消费者、接收时点和内容来源；回显可能是输入反射、缓存或另一后台任务。

逗号分隔地址或追加第二地址时，需沿实际输入类型、分隔解析、目标选择及每一跳权限解释，而不是由一个拼接字符串认定通用metadata绕过。目录名、元数据正文、临时凭据可用性和后续进程执行是不同能力，版本/会话要求也各自留证；本次不请求元数据或使用来源凭据。

## Sentry filepath字段到制品消费者

事件堆栈中的filepath可能只是显示元数据，也可能被符号解析、源码制品查找、debug renderer或其他任务用来定位资源。把可控字段、事件来源/权限、任务配置/版本、实际URL或路径解析、出站进程与反馈通道关联起来；任意URL写进字段不等于Sentry必然取回。

## CONNECT隧道目标与上游代理归因
