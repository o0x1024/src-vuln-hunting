# 上传、处理与文件访问

## 适用信号与前提

头像、附件、导入、富文本、解压、预览和异步文件处理。准备自建文件及已知上传/访问规则，记录存储 origin、访问权限和处理组件。

上传权限取决于当前业务的开放策略。先按 [业务预期判定](../business-intent.md) 分开核对创建、读取、覆盖、删除与处理权限；缺少登录机制或上传成功不能单独证明越界。一项操作合法不豁免其他访问或处理边界。

## 最小实验

正常上传带唯一标记的无害文件，确认存储和访问基线；按实际线索单独改变后缀、MIME、内容、文件名路径或访问身份。双扩展、大小写、特殊后缀是否有效取决于实际服务器/配置，不能直接套旧解析漏洞。

关注上传到处理再到下载的边界：是否被重新编码、是否可跨租户访问、是否被当成主动内容、是否发生路径逃逸。脚本执行验证仅在已明确允许且隔离的测试位置使用无害标记；普通 txt 可读只能证明存储/读取，不能证明代码执行。

## 确认与反例

分别确认不应允许的文件存储、私有文件读取、危险解析或执行，不能混为 RCE。排除改名、内容重编码、attachment 下载、独立 origin/sandbox、合法分享与无效异步任务。

仅上传成功、Content-Type 可伪造、文件名包含脚本都不充分。需要实际访问/处理路径与目标上下文证据。

## 下一步、停止与报告

不上传 webshell、解析控制文件（如 .htaccess/.user.ini）或覆盖已有文件来改变服务配置。路径/解压测试只针对获准自建位置和有限小样例，不制造资源耗尽。

保存上传请求、实际存储/访问 URL、处理状态与证据；清理获准自建文件或记录平台清理需求。相关实验见 [路径](lfi-path-traversal.md)、[XSS](xss.md) 和 [验证](../verification.md)。

## 调研补充：可执行检查点

- 将“上传接受→保存位置→转换处理→下载/渲染”拆开记录；只改变文件名、声明 MIME 或内容签名中的一个因素，检查真正消费内容的组件。
- 扩展名或 Content-Type 绕过仅证明校验弱；服务器把文件作为下载返回不能证明执行。客户端 SVG/HTML 渲染、服务端解释与解析器漏洞分开验证。
- 多租户检查上传凭证绑定、目标对象与下载授权；归属类证据转访问控制，外部资源解析转 XXE/SSRF。
- 压缩包仅用小型受控样本；路径落点转路径穿越。不得部署 webshell、覆盖配置、制造压缩炸弹或依赖真实管理员打开文件。

## 归档案例补充：容器与失败路径

上传对象若经历本地临时落盘、检查、搬到对象存储和清理，按实际实现记录每一阶段的位置、可访问性和处理身份。最终落点安全不代替临时阶段检查；短暂可读也不证明能执行。竞态假设先用获准源码、日志或隔离副本确定顺序和窗口，线上并发仍按 [竞态](race-conditions.md) 的独立许可与最小预算，不追求反复命中生产窗口。

外层文件名检查不代替归档条目规范化；解包或后置检查失败后需核对是否已留下受控文件。把写入位置、检查顺序和清理结果作为证据，不以“上传失败”认定没有副作用。见 [文档处理](document-rendering.md)。

以 object ID 和唯一标记关联原文件、缩略图/转换副本、预览及下载；分别记录每个产物的 origin、访问角色、Content-Type 与 Content-Disposition。文件是否位于 CDN 不单独决定安全性；直接访问与预览采用不同响应头或身份时，分别确认实际消费者与影响，并清理相应派生产物。

异常文件检查先保留可成功处理的小型正常样本，再只改变一个有依据的结构字段，关联上传接受、异步任务、解析器报错、产物和清理/重试状态。扩展名相同的损坏文件或XML格式错误不自动证明XXE、执行或可持续拒绝服务；错误响应与队列恢复能力分别记录。优先隔离副本和已有日志，只使用最小无害样本，不为验证错误处理投入实体膨胀、巨型文件或反复生产任务。

文件内容的magic bytes检查与文件名/后缀进入页面的编码规则分别核对。哈希重命名可能保留后缀或另存原名；记录原文件名、存储键、派生产物与列表/下载/管理员视图中各个实际输出位置，而不从“已改成hash.jpg”断言所有元数据已安全。只用自建文件的无害文本标记追踪进入属性/HTML/JSON的路径；接受特殊文件名不证明执行，必须有真实浏览器消费者、跨身份投递前提和无害执行结果。文件名HTML注入、内容SVG执行和服务端文件解释是独立分支。

## 上传声明与下载响应嗅探

上传multipart文件部分的Content-Type、服务端存储/转换和最终预览/下载响应的Content-Type分开记录。上传声明留空不保证最终响应也留空，更不保证所有IE/Edge版本都会执行HTML。按当前浏览器、destination、nosniff、Content-Disposition及origin核对消费者；[MDN X-Content-Type-Options说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Content-Type-Options)区分脚本/样式阻断与其他上下文的类型嗅探（2026-10-09核对）。正文只是作为附件保存或在独立来源不可执行时保留反例，不运行来源恶意文件。

## 归档格式与被当成程序执行

归档内可控文件名可能含脚本语法；工具把同一归档交给shell解释，与普通解包是不同消费者。历史图片在本地将tar加执行位后运行，并出现命令输出及格式字段的command-not-found；这不证明未知服务器会执行上传归档或完整通用多格式载荷。保存谁能提供字节、谁选择解释器和实际权限，静态查看获准成员/元数据即可提出假设；不运行不可信tar、改执行位或复制图中命令。

## 文件类型到处理消费者的分支

上传扩展名只指向可能的消费者，不能从后缀直接得出RCE/XSS/SSRF/XXE。用原始字节、实际声明/识别类型、保存位置、处理依赖与版本、输出响应类型/来源/读者建立上传→存储→转换/读取→输出的可达关系。先用获准合成无害文件确认实际分支，不投放webshell、资源耗尽文件或会访问真实远端的制品。

| 线索 | 必须补的消费条件 |
|---|---|
| 服务器脚本后缀、归档 | 是否进入可执行处理器或后续include/加载器；允许保存不等于服务器执行，归档成员提取与加载另证 |
| SVG/HTML/JS/GIF | 实际下载MIME、浏览器解析上下文/来源与CSP；图像解码或纯下载不等于脚本执行，外部资源引用需实际服务端消费者 |
| CSV/XML | 后续电子表格单元格解释或XML解析器/外部实体配置；仅文本保存不触发这些机制 |
| AVI/PDF/PPTX | 当前转换/预览/文档解析组件是否消费外部引用或路径；后缀不保证支持相应引用机制 |
| PNG/JPEG等位图 | 解码尺寸、资源预算与具体库的已知诊断；不能按“pixel flood”标签做生产压力实验 |

目录的父路径要求登录而某个子路径显示上传控件时，分别核对路由、操作鉴权和文件消费者。单有“上传rce.php”的故事不能补出执行回执，发现阶段也不触发此类上传。

## SVG的图片与文档消费者

SVG上传成功、扩展名放行和浏览器执行脚本分别记录。图片中的公开DTD声明、polygon和script只是源文件内容；是否形成XSS取决于实际响应MIME、最终URL/origin、嵌入方式、脚本限制、上传者与受保护读者。retire.js识别组件不证明SVG执行能力。

[MDN SVG作为图片](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)说明图片上下文可禁用JavaScript/外部资源，这些限制不同于直接查看或iframe/object/embed文档上下文（2026-10-09核对）。由此应分别登记图片预览和独立文档的条件，不能承诺打开任意SVG均弹窗。XML解析器是否读取外部实体属于另一条服务端链，不由DOCTYPE存在直接认定。验证只用获准制品和无外联标记，不诱导第三方打开上传物。

## 归档成员名进入网页目录预览

外层JAR文件名、归档成员路径、成员字节、解包路径与网页目录项是不同输入。成员的.class后缀不意味着此问题通过执行Java字节码触发；若成员名被原样写入网页，消费点可能是目录列表的HTML。沿获准自建归档的普通标记追踪上传→成员枚举→页面模板→实际DOM，保留成员身份与读取角色。原生归档工具显示含脚本语法的名称，只证明可存储该名称，不证明网站渲染或他人浏览器执行。与归档路径穿越分别判断。

## 文件名尾部标点与保存后的解释器

尾部句点/引号的差异可能位于multipart解析、应用后缀检查、存储规范化或下载路由。原始Content-Disposition字节、框架解析的文件名、存储键/实际名称及最终内容消费者分别保存，不能由帖子称“很多站点有效”推出当前平台一定去掉尾部标点。

只接受名称或显示上传请求，未证明保存、可访问或服务端执行。用合成普通文件与有限有依据的元数据差异追踪实际各层，保留拒绝/重命名/纯下载反例，不上传PHP/Webshell或执行图中内容。

## 同一文件名的路径、数据库、页面与命令消费

文件名可能进入存储路径、数据库字段、列表HTML或处理命令，但这些是不同消费者。路径片段只有进入文件定位才涉及穿越，类似SQL/延时/命令语法只有到达相应解析器才涉及注入；参数化数据库值和独立进程参数是反例。HTML/SVG字样作为文件名不等于文件内容或浏览器执行，源示例document.comain拼字也不能补成真实读域结果。

用获准普通文件名标记追踪multipart原名、规范化名、实际保存键、元数据、页面输出与处理调用；优先已有源码/隔离日志，一次核对一条消费边和权限。只接受特殊名称、一次变慢或返回成功不确认任何链，不上传脚本、不投延时载荷或执行文件名中的指令。

## 归档库漏洞与实际处理配置

历史Drupal公告相关清单含两个CVE编号，但产品名不足以确定依赖版本及部署条件。[SA-CORE-2020-013](https://www.drupal.org/sa-core-2020-013)说明使用PEAR Archive_Tar，并把允许上传及处理特定归档类型列为相关条件；仅允许上传、仅保存文件和真正进入有问题的归档处理器分开。

核对实际依赖/补丁、类型判断、上传主体、归档消费步骤和文件/代码执行边界；上游修复范围与本产品可达性分别记录。优先既有配置、脱敏日志与离线合成成员，不构造写入/执行归档或上传PoC补证。2026-10-09只核读官方公告相关段落，不把历史公告当当前所有Drupal均可利用。

## 冒号文件名、NTFS流与Web映射

file.php:.jpg等冒号名字须先确认真实操作系统、文件系统、写入API和路径处理。[Microsoft文件流说明](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams)给出filename:streamname:streamtype结构（2026-10-09核读）；NTFS流语义不能推广为所有系统的扩展名绕过，浏览器上传名也不一定原样存储。

沿客户端文件名、服务端规范化、实际基文件/流、内容校验、存储位置、Web路由和解释器映射逐边记录。CTF成功标题不证明生产会执行PHP，接受文件或生成URL也不等于解释执行；用隔离普通文本/元数据验证路径语义，不上传活动代码。

## 额外等号的查询值与执行映射

file===xx.php按常见首个等号分隔形式得到键file和值==xx.php，不能未经证据把它当file=xx.php。实际服务器可能使用不同解析或再次规范化，需保留完整request-target、网关/WAF解析、应用字段、落盘名字和最终请求映射。

过滤器未拦、上传接受、文件存在、内容被提供和解释器执行分开验证；先用隔离普通文件及已有处理器代码核对差异，不自动修写来源字节或从bypassed标题认定PHP执行。多等号既可能改变值，也可能被拒或走另一字段契约。

## 媒体解码器的HLS引用与嵌套消费者

上传清单把FFmpeg/HLS、SSRF与本地文件泄露放在一起，需要展开实际链路：上传对象→内容识别/转码器→播放列表解析→嵌套资源URL/协议→进程网络与文件权限→输出制品/返回受众。文件名扩展、MIME与真正解码格式不同；接受上传不证明后端使用某版FFmpeg或允许嵌套外部引用。

优先核对获准源码、转码配置、协议白名单、沙箱和现有日志，在隔离材料中用自有合成引用/文本标记检查每一跳。外部引用被禁、无网络/文件权限、只读取自身缓存或不向攻击者返回内容都是反例；不运行来源HTTP监听器、上传系统路径播放列表、扫端口或制造像素/文件名资源耗尽。

## 删除图片的保留契约与可访问副本

已删除图片仍可用旧地址读取，应核对当前产品/隐私承诺、删除生效时点、允许保留窗口、软删除/备份、CDN缓存与原始/缩略派生副本。保存对象稳定ID/版本和删除前后允许读者，区分内部合规备份保留与对旧公众地址继续提供内容。

在获准已有证据或可恢复合成对象中关联权威删除状态、源存储/缓存响应、失效时间与当前受众；仅一张Triaged/P4图没有独立重现，也不能因公司大自动提高等级。超出明确保留承诺并仍向不应访问者服务相同内容才形成具体影响，不访问真人旧照片或以评级截图代替契约。

## 图片元数据的来源、派生制品与隐私受众

EXIF可能承载拍摄位置等元数据，不能假定每张图都有IP或秘密。对照用户原始文件与应用交付的原图/缩略图/转码产物哈希、字段来源、处理/去除策略、下载响应与预期受众，区分用户自己携带信息、应用额外添加信息和本应隐藏但被公开保留的信息。

优先获准离线合成图片/现有脱敏字段核对真实产物；只列存在且确有受众边界影响的最少字段。把图片或下载URL粘到第三方读取站可能泄露文件/地址并由该服务另发请求，不能作为默认补证步骤。源文未给实际EXIF内容，本次不上传照片、访问外部解析服务或声称全部位置/IP都泄漏。

## 图片注释中的程序文本与真正解释器

exiv2/exiftool将PHP片段置于图片注释，只说明可写入某个元数据位置；JPEG/PNG正常解码不会因此成为PHP执行。记录最终文件真实格式/元数据块、上传校验、重命名/转码是否保留该块、服务端处理器映射、include或其他解释器消费者与执行身份。

优先获准已有代码/合成普通文本元数据确认保存/剥除和消费链，区分普通图片数据、元数据HTML渲染和服务端程序解释。源示例PNG与JPEG名字/弯引号也不能静默当同一工具语法；缺实际解释器则只保留候选。不运行exiv2/exiftool源命令、写webshell或上传执行文件。

## 文本载荷字典的后缀与预览消费者

将字典生成器的标准输出重定向为xss.doc只改变名称，不创建有效Word文档。原图仅展示1.6M文件大小与查看开发者控制台建议，没有文档解析/预览输出或脚本执行证据；生成器全部内容、依赖实现与后续上传也未保存。字节格式、multipart声明、实际识别格式及存储/预览响应需分开。

在已有源码或隔离无害标记中定位文本是否进入列表、索引摘要、文档转换或浏览器HTML，每个消费者有自己的编码、MIME、origin、CSP及读者权限。解析失败、转义纯文本、独立下载和不可执行的图像上下文作反例；一次提交所有载荷既无单条归因，也增加资源和观察混淆。选择当前消费边需要的最少合成文本，不安装来源包、生成全字典、上传恶意文档或把控制台错误当XSS。

## 编码井号、保存文件名与URL片段

旧图的example.jpg%23.html是文件名建议，不是实际处理结果。multipart filename中的%23通常仍需应用明确百分号解码；文件系统不会仅因为井号就自动理解URL片段或选择HTML解释器。字面%23、解码后的#和构造URL里的片段分隔符必须分别记录；[RFC3986片段条款](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.5)描述URL解引用前的片段分离，不是磁盘后缀规则。
