# 收尾与复盘检查

这是验收检查，不是强制扫描所有技术的清单。每项记录通过、缺失或不适用及依据；缺账号/工具不属于不适用。

| 检查项 | 通过标准 |
|---|---|
| 目标与范围 | 项目、规则快照及变化、实际目标和动作均可追溯 |
| 执行条件 | 账号、会话、工具、预算计数和异常已记录 |
| 信息收集 | 必需来源/角色/功能的实际采集、分页/截断、归属与授权、接口差异和队列缺口可追溯；按 [发现退出条件](asset-discovery.md) 收尾，不以 URL 数量代替完整性 |
| 覆盖 | 按端点/动作/身份/业务状态记录实际执行，必需缺项明确列出 |
| 假设处置 | 无未解释的测试中状态，线索与已确认发现分开 |
| 确认质量 | 基线、边界突破、反例检查和原始证据齐备 |
| 业务预期 | 公开/匿名相关结论有操作、字段、受众、授权方式及规则来源；正常功能不计漏洞，规则未知保留待补证，匿名入口的独立越界仍单独评估 |
| 业务影响 | 受保护业务、受影响主体和实际能力有证据；规模与价值推断不冒充已执行事实 |
| 收录评估 | 当前有效规则与具体排除项已检查，技术/影响/可提交/平台回执状态独立；缺项明确 |
| 攻击前提 | 准备者与攻击身份分开，关键 ID/令牌来源、受害者动作和部署条件可追溯，未知条件明确保留 |
| 领域与产品层 | AI 生成内容/真实执行、客户端/服务端、模拟器/真机、组件/整车影响分开；版本、网络、物理条件与实际覆盖一致 |
| 平台材料与奖励 | 必需版本/PoC/视频/人工验证有真实记录；普通收录与专项资格分别判断，历史活动/未知奖励不承诺有效 |
| 独立性与后续 | 根因/共享修复依据、成熟报告交付时间、真实回执与复测范围分开记录，不用 URL 数量充当独立发现 |
| 报告 | 步骤真实，影响不越过证据，脱敏和评级依据明确；线索数不冒充可提交或已接收数量 |
| 清理 | 自建资源变更可追溯，允许的清理已执行或交接 |
| 任务结束 | 完成要求满足才 completed；缺项用部分完成/等待输入等真实状态 |
| 增量水位 | 仅在本批次完整处置且宿主允许时推进，不能跳过受阻项 |

规则变更或新业务出现后，只有用户已授权持续任务才安排后续测试。复盘依据误报原因、已知评测集漏报、重复请求、恢复失败和实际成本改进方法；平台拒收不能一律算误报。

修改 skill 后使用 [离线评测](../evals/protocol.md)，不要只检查文字是否齐全。发现新问题优先修正具体决策或工具契约，避免不断添加泛化禁令。
