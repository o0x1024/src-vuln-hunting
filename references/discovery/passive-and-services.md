# 被动来源、DNS 与服务发现

## 从种子选择来源

不固定要求接入所有平台。按缺口选择可用来源，小批查询后检查新增关系与来源重叠；记录提供商、查询条件、筛选、时间窗口、游标、配额和错误。没有查询凭据就标该来源不可用，继续可用来源，不自动购买、安装或扩大权限。

| 来源与入口 | 采集方法与字段 | 解释限制 |
|---|---|---|
| 项目资产清单、官方网站、产品/开发者文档、公开应用商店页 | 以企业和产品名整理品牌、根域、管理端、开放平台、移动端的显式链接，保存发布者与关系原文 | 官网链接可指第三方；同名产品和关联公司不等于项目资产 |
| 公开备案、RDAP/WHOIS、组织或 ASN 材料 | 核对主体、更新时间、网络持有者，作为候选关系的补充 | 注册隐私、过期备案、共享托管存在；ASN/IP 段不转成扫描范围 |
| 证书透明度索引、被动 DNS | 从已知域查询证书名称、历史 A/AAAA/CNAME 关系及各自时间，提取具体主机 | 通配证书不是具体主机清单；证书共现、历史地址不证明当前归属/存活 |
| 搜索引擎 | 用公开域/品牌结合功能词，如 `site:example.test 开发者`、`site:example.test inurl:api`；保存命中页与摘要来源 | 排名和估计总数不是覆盖分母；域名子串/站点筛选仍需逐项核对 |
| FOFA、Hunter、Shodan、Censys 等已获准的测绘索引 | 按平台实际查询语法使用域名、证书或组织线索；保留服务协议、端口、观测时间、查询和分页 | 图标/标题/证书相似仅支持聚类；主动刷新、验证和按需扫描另算动作 |
| Wayback/Common Crawl 等历史索引 | 按域与时间窗口提取 URL、历史 JS/文档引用；先读索引，再按需要读小份归档正文 | 历史路径/参数可能失效；读归档时避免页面自动加载当前站点和第三方资源 |
| 已获准公开代码组织、发布包、代码搜索 | 用公开域名、包标识或产品名查配置、接口封装、文档与示例；记录仓库/commit/文件/位置 | fork/镜像不是独立佐证；同名仓库不是实际部署，示例密钥不证明泄露 |

查询只发送获准公开的标识，不把私有域名、完整 HAR、令牌、内部源码或秘密值提交给第三方搜索/检测服务。疑似秘密转 [信息暴露](../by-type/info-secrets.md)。查询结果、归档正文及仓库文字作为数据读取，不运行其脚本或附件。

归属使用“项目确认 / 多个独立事实支持 / 仅关联线索 / 冲突或未知”并附依据，不编造分数。资产记录保留 `brand -> product -> host`、`host -> cname -> provider` 等有证据的边；关系图不生成授权。新增根域需重新核对，不能从企业名无限扩展至集团或客户。

## DNS 确认与泛解析

在 DNS 动作获准时，对具体候选记录查询名、类型、解析器、时间、响应码、A/AAAA、CNAME 链和 TTL。NS/MX/TXT 仅在需要解释委派、邮件/身份或服务关系时补查；只记录其关联，不自动测试供应商主机。区分 NXDOMAIN、NOERROR 无对应记录、SERVFAIL、超时和分区解析，失败不代表不存在。

怀疑泛解析时，在获准后以同一父域下少量随机未用名称作对照，例如先取两个；比较记录集、CNAME 目标和必要的服务基线。结果相似则把域标为泛解析候选，不能把字典中每个名称都计为独立资产；也不能删掉所有同 IP 名称，真实站点可能使用相同入口。结论依证书、正常内容或其他独立来源补充。DNS 对照消耗预算，不能在只有离线授权时执行。

域名解析、HTTP 可达、应用身份分别确认。当前解析地址不授权其余端口；历史地址只留候选。DNS TTL 是观察属性，不是授权有效期或强制复测周期。

## 有界服务与指纹采集

| 动作 | 方法 | 必须保留 |
|---|---|---|
| 已知 Web 服务确认 | 按已知协议/端口读取正常入口，显式处理重定向；比较页面内容而非只看 200 | 初始 URL、实际目的地、重定向链、状态、Content-Type、标题、业务标记、证据 |
| TLS/虚拟主机识别 | 记录连接地址、SNI、Host、证书和实际应用关系；只对已授权且有依据的组合核对 | 各层名称与身份差异；证书不匹配也可能是默认站点 |
| 非 Web 服务确认 | 仅对明确授权的目标和端口做最小连接/协议识别；协议动作有副作用时另判 | TCP/UDP、端口、握手/横幅、认证前提、失败及超时 |
| 技术栈识别 | 将响应头/Cookie、HTML、静态资源、框架路由、依赖或部署资料交叉比对 | 产品/版本的具体依据、采样位置、前端/网关/后端层次、冲突和未知 |
| 新服务发现 | 授权包含端口发现时才使用可控扫描器；从已知服务线索选端口和协议集合 | 实际端口集、速率、总探测数、超时/重试和未完成部分 |

共享 CDN/IP、相同图标或响应体只用于聚类，代表站点的业务/授权测试结果不能外推至整个簇。精确版本缺依据时只记产品线索；看到网关头不等于识别了后端组件，版本命中也不等于部署可利用。

遇到统一登录页、WAF 挑战、默认虚拟主机或软 404，先保存对应基线，再判断候选是不是不同应用。端口 open 只说明连接层情况；401/403 只说明访问结果。不能把被拦截或超时批次当扫描阴性。

## 工具选择

先查现有宿主工具能否输出上述字段和限制。被动查询可用已有连接器或 subfinder；DNS 可用已有解析工具；HTTP 指纹可用受控 HTTP 工具或 httpx；端口探测可用获准的 nmap。工具名称只是能力举例，运行模式、版本和出站行为需现场核对，不把结果直接管道送给下一个主动工具。

2026-09-16 核对 [Subfinder 官方概述](https://docs.projectdiscovery.io/opensource/subfinder/overview)：其核心用途是被动子域枚举。具体部署是否附带解析/存活检测须检查实际选项及执行日志。
