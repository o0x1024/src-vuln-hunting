# Web、前端与 API 采集

## 建立采集计划

从当前目标的正常入口、已有流量/文档和 [业务模型](../business-modeling.md) 建立 `角色 × 功能 × 状态` 表，字段包括入口、会话引用、前置资源、允许动作、已观察接口和缺口。优先覆盖登录前/后、不同测试角色以及列表/详情/搜索/导出/上传/异步任务等实际存在的功能；不凭通用清单编造该产品能力。

同一角色先走一条代表性正常路径，记录页面到请求及业务对象的对应关系，再补未覆盖分支。没有第二角色、管理员或测试资源时标 blocked；页面未显示功能不等于它不存在。普通账号的抓包不能代表全部角色。创建资源、导出、发送通知、购买和删除按语义核对许可，表单提取不等于获准提交。

## 页面、元文件与爬行

1. 从初始 HTML 与渲染 DOM 提取站内链接、表单 action/method、隐藏字段、iframe、注释、脚本/样式引用和显式文档入口，记录提取位置。相对路径按实际文档基址解析，含 `<base>`、协议相对 URL 和跨源重定向时先核对目标。
2. 在已允许正常读取的站点查看 robots.txt、sitemap 及引用的 sitemap index、Web manifest；把路径作为候选。robots 指令不构成测试授权，security.txt 中的政策链接需与宿主规则核对，不能改写已有 Scope。
3. 爬行器采用有限深度、时长、请求总量、页数和响应大小，显式配置目标/路径与动作边界。排除重复日历、排序/筛选组合、随机参数和无限翻页；是否继续取下一页依据新接口/结构，而非为了抓全业务数据。
4. 对 JS 渲染、点击后加载和登录后页面，用受控浏览器补采。只执行已确认语义的导航；禁用未经授权的自动表单提交。浏览器加载产生的子请求、预取和外链也需计数及出站控制，URL 输出过滤不等于阻断出站。
5. 遇到统一跳转、相同模板或软 404，在已允许的只读路由上下文使用少量不存在路径作基线；结合最终 URL、页面结构、业务字段和身份判断。不要全局按状态码/长度丢弃结果；403、空数据、挑战页保留观察及限制。

爬虫输出只含看见或排队的链接时，不能标记它们已实际请求。默认主域范围可能宽于项目指定主机；开始前核对当前工具配置。停止后确认后台请求已结束。

有移动端关联线索时，正常公开的 App Links/Universal Links 关联文件也可提供应用标识、域名与路径规则。先核对实际项目材料中的声明/引用，按当前授权保存关系；文件公开不自动构成泄露，规则中的路径也不证明当前可达或已授权操作。

正常响应的 CSP 域引用可补服务/消费者关系。保留具体指令和来源页面，区分项目主机、第三方 CDN/服务及历史配置；策略中允许某域不证明页面实际使用它、企业拥有它或当前获准测试它。

## JS、source map 与运行时配置

- 先分析正常页面实际引用的脚本、路由表、动态 import/chunk manifest、配置对象、Service Worker 引用及 API 请求封装。按内容哈希复用已解析文件，再沿与未覆盖业务有关的懒加载模块补采，不盲目下载所有构建产物。
- 提取 base URL、相对 path、方法、Content-Type、参数构造、认证头名称、功能开关和调用位置。动态拼接只记录可证实片段与未知变量；找到 `/api/` 字符串不代表知道完整 URL 或方法。
- 从明确的 sourceMappingURL 或已有发布资料定位 source map；先核对范围与文件体积。解析映射中的源码/位置供静态观察；嵌入的 sourcesContent 与需要另外请求的 sources 区别处理，后者不自动抓取。缺图、缺模块或混淆无法解析均记录限制。
- 前端哈希路由保留为导航状态。API 地址仍以实际请求为准；测试/生产配置、未启用分支、第三方 SDK 和示例代码分别标记，不能自动执行静态提取的请求。
- 签名/加密封装先通过已获准正常样本恢复请求结构与动态字段依赖，方法见 [小程序请求封装](../by-type/miniapp-security.md)。不猜密钥或把签名失败当业务接口安全。

## API 与参数结构

用三类来源互相补充：正常流量（浏览器/受控代理/HAR）、静态客户端或获准源码、接口文档（OpenAPI/Swagger、Postman 集合等）。取并集并保留来源差异，不把交集当完整覆盖。文档版本、servers/basePath、环境变量、认证方式和外部引用都要核对；导入文档不能触发全量请求，集合中的脚本/测试代码不自动执行。

API 根路径空响应时，从已有链接、客户端依赖或框架线索核对文档入口，不据根路径判断没有 API。除 OpenAPI/Swagger，实际 Jersey/WADL 等描述材料也可提供方法、资源与代理引用；历史固定路径只是候选。发现端点后反查它在 JS、页面或请求历史中的引用，恢复真实方法、参数和前置状态，再建立有效正常请求；正则提取 URL 不能代替调用语义。

| 要记录什么 | 提取办法与限制 |
|---|---|
| 协议、主机、端口、方法和路由 | 方法来自实际请求或明确声明；只有 URL 时记 unknown，不默认 GET。HTTP/HTTPS、API v1/v2、GET/POST 分开 |
| 参数位置与结构 | 保存 path/query/header/cookie/body 位置，JSON 嵌套字段路径、数组、表单/multipart、类型和来源；可读响应字段不等于可写参数 |
| 参数语义 | 记录资源/租户/角色、分页过滤、文件/URL 输入、状态或额度线索；只有观察时才能判断必填/默认/枚举，否则写 unknown |
| 会话与动态字段 | 用身份引用记录认证前提、CSRF、nonce、时间戳、签名的依赖；敏感值留在受控凭据系统，不进普通接口清单 |
| 响应和数据关系 | 保存响应结构、业务错误、资源归属、列表到详情/导出/异步任务的关联；空返回与接口不存在分别处理 |
| 版本与环境 | 对照当前客户端、历史 URL、旧文档和部署资料；差异只生成待核对项，历史接口不直接标当前可达 |

参数发现优先从正常请求、可用文档、表单及客户端构造取候选；有明确线索且参数探测动作获准时才做小候选单变量对照，使用自建资源/普通标记。不得从正常读取预算推导大字典参数 fuzzing，更不能把字段名线索升级为批量读写真实数据。

需要从已观察的接口/目录规律推导新候选、区分参数名称与值的变异或根据响应调整下一批时，按 [定向 Fuzzing](../targeted-fuzzing.md) 执行。发现阶段无需先证明漏洞；静态推导、实际请求、输入被消费与安全约束被突破分别记录。

## 非 REST 与间接入口

| 信号 | 发现产物 | 边界 |
|---|---|---|
| GraphQL 正常操作或可用 schema | operation 类型/名称、字段路径、变量结构、查询指纹及身份；详见 [GraphQL](../by-type/graphql.md) | 一个 `/graphql` URL 不是一个业务操作；不自动发起全量 introspection 或大批量查询 |
| WebSocket/SSE 流量 | 握手/订阅入口、消息或事件类型、资源引用、会话及连接生命周期 | 不能只统计握手；未观察的消息类型记未知，不长期挂后台采集 |
| SOAP/WSDL、gRPC/protobuf 材料 | service/method、消息结构、调用地址和已有调用点 | 解析外部 import/include 先登记引用并校验；反射/在线描述查询需匹配许可 |
| OAuth/SSO、第三方 SDK、支付或存储跳转 | 参与方、回调地址、信任边界、状态关联及第三方归属 | 记录引用不表示获准测试 IdP、供应商或云账号 |
| Webhook、导入、导出、队列/后台渲染 | 用户输入→接收接口→任务 ID→消费者/回调→结果的已知连接 | 看不到消费者就标 unknown；不为收集全链路而擅自触发通知、账单或远端请求 |

## 交付与工具限制

### 页面状态与条件响应

Cookie/隐私提示出现、关闭或作出选择时，页面可能消费不同的 URL 字段或执行不同渲染分支。仅对实际存在的状态保留输入到 DOM 的对照，记录用户动作及其前提；不能将“忽略所有提示”当成统一采集步骤。

304 与浏览器展示的缓存正文要分别记录。保留 If-Modified-Since、If-None-Match、ETag、Last-Modified、会话与缓存来源；在获准的受控只读资源上，比较正常条件请求与去掉条件头的请求，先恢复有效正文观察基线。304 不证明资源为空、接口不存在或身份检查通过；跨身份结论仍需独立会话及合成私密内容证据。

按 [发现记录](records-and-incremental.md) 保存接口及角色/状态覆盖；把“文档声明、代码引用、实际请求、业务确认”分别记录。提取到越权/输入边界线索后转相应检测专题，不把信息收集结果直接转 Finding。

工具可选择已有浏览器、受控代理/HAR 解析器、静态解析器或 Katana 等爬行器。先确认是否会执行 JS、自动填表、跟外链、加载文档远端引用，及能否保存实际请求证据；只有离线解析器时照实交付静态候选。

2026-09-16 核对：[WSTG 入口识别](https://owasp.github.io/www-project-web-security-testing-guide/v42/4-Web_Application_Security_Testing/01-Information_Gathering/06-Identify_Application_Entry_Points)、[执行路径](https://owasp.github.io/www-project-web-security-testing-guide/v42/4-Web_Application_Security_Testing/01-Information_Gathering/07-Map_Execution_Paths_Through_Application)、[元文件](https://owasp.github.io/www-project-web-security-testing-guide/v42/4-Web_Application_Security_Testing/01-Information_Gathering/03-Review_Webserver_Metafiles_for_Information_Leakage)、[Katana 模式与配置](https://docs.projectdiscovery.io/opensource/katana/running)。这些资料支持方法选择；本地工具版本、可用能力及实际覆盖须另行记录。

客户端功能开关可作为未覆盖UI/路由的线索。先保存真实开关响应、部署版本、条件分支和调用位置；在获准受控环境观察某个显示分支后，核对实际后端请求、身份及允许动作。代理改响应仅证明本地UI可出现，不能证明服务端开关失效、取得新权限或该功能对所有用户启用；不要自动开启所有开关、触发未知计费/写操作。客户端登录成功分支中的跳转地址也只是路由候选，直接打开页面后的实际私密数据/操作仍由服务端授权证据判定。

## 已引用接口的版本候选

已有getUser接口的V1/V2/Beta后缀可提示客户端或文档中的版本分支，优先从真实引用提取少量候选。名称和200响应不证明旧版缺鉴权或IDOR；把方法、身份、对象归属及受保护字段分别关联各入口，以两个受控对象核对。图片声称暴力找出“全部端点”没有完整真值，不据此递归猜后缀或批量请求。

## 主机标签与路由大小写候选

主机标签可能出现在应用路径中，但不是所有子域都对应同名目录。从现有导航、脚本/文档或部署线索建立少量路径候选，保留虚拟主机和方法；只有名字相似时标推测，不据此递归跑词典。/api拒绝而/Api成功先区分不同路由、默认页面、重定向、网关规范化和后端角色检查，以同一受控对象/身份核对真实响应能力；大小写变化和200本身不能证明鉴权绕过。

## 从JSON字段猜路由的候选层级

JSON中的person/cars/friends/family/count可帮助提出路由假设，但对象结构不是API路由契约。/person/cars/1、/name或嵌套字段路径可能根本不存在，也可能是前端虚拟结构；字段名称、数组序号、对象标识和授权主体分开记录。

优先用获准的客户端调用、接口描述或已有流量确认方法、路径和语义，再选择最少的合成对象验证实际功能/字段权限；图片列出Other Possible Endpoints不是存在/越权证据。保留不存在、不同版本或仅公开资源的对照，不自动把全部字段递归成请求或字典。

## PDF提取结果的消费者与覆盖范围

先把获准既有URL的路径/查询与实际内容类型分开；以.pdf结尾的正则会漏带查询参数的地址，也不能确认响应为PDF。对已有离线文档分别记录正文文本、注释/链接URI、嵌入对象与扫描页/OCR的读取范围；正文提取结果为空不等于文档没有链接或信息。

保存文件指纹、页码/对象来源、解析版本和失败记录。流水线隐藏stderr、去重后的链接数量与300并发均不能证明覆盖完整；未知extract脚本仍需静态检查其下载/执行行为，候选URL先按来源和归属处理，不把文档中所有链接自动导航。

## 引号包围的JS路径正则仅生成候选

只匹配引号后斜杠及少数字符的正则会遗漏编码、Unicode、动态拼接与其他URL形式；用独立的前后引号匹配也未保证引号成对，甚至可能从注释或正则字面量抽出字符串。保存原始制品、字节位置、周围语法和未匹配范围，再结合静态调用点还原base、方法和变量。sort去重不能丢来源；/、//或路径样式文本不证明真实接口。无需求值JS或把提取值送入shell才能整理候选。

另一保存的一行正则在斜杠后的字符类没有量词，即便字符类能被该引擎接受，其字面形状也只容纳一个后续匹配字符再要求引号；不会因此匹配普通/admin长路径，更不能称all endpoints。字符类里的连字符位置也应按实际PCRE确认，前后引号独立未配对。保持原pattern不静默补+，静态分析与改写后的离线普通例子结果分别保存，未运行来源cat/grep/tee流水线。

## security.txt与私有项目邀请

搜索security.txt能定位披露联系与政策线索，不能证明发现了私有奖金计划或获得邀请。[RFC9116 §5.5](https://www.rfc-editor.org/rfc/rfc9116.html#section-5.5)明确其存在或缺失不隐含测试许可；按实际政策核对对象、活动、时间及报名条件。文件自己的域/IP适用范围也不等于其父域/子域全部纳入项目。保留检索来源与当前政策版本，不从搜索命中推奖金承诺、测试权限或批量联系授权。

## 历史URL生成词表时保留丢失维度

把历史URL按斜杠切第4/5段只生成有限深度的路径词，主机、协议、端口、更深路径与查询参数可能被丢弃；不同来源同一个词也未必对应同一业务功能。URL解析后完整path提取与浅层词表是两个派生产物，不能只因后者输出更多就称覆盖更完整。

保存原始URL→派生词的映射、时间/归档来源与截断规则。按当前消费者需要决定保留层级、参数名或规范化索引，同时保留原始编码；根路径/静态资源/失效旧接口分别处理。不把其他项目的历史词直接拼到全部当前目标或以sort去重丢掉授权上下文。

## 爬虫展示格式与源脚本关系

旧hakrawler输出经grep from、awk首列和删引号，只在对应展示格式下抽取部分相对路径；绝对URL、协议相对地址、非ASCII路径、其他输出模式和带空格的记录可能丢失。候选去重仍保留来源脚本、相对基址、位置、角色及缺口，优先结构化输出或获准离线解析，不把人类可读日志当稳定API。

后续拼接/Fuzz是另一动作：若主URL已有尾斜杠而候选带前导斜杠，生成的路径可能变化；非404匹配不证明真实功能或授权，认证材料也不能随意发给派生第三方地址。正常调用点先恢复方法/参数/消费者，不把全部候选统一GET或照旧20进程深度2爬虫运行。

## 公开API集合与实际泄露边界

documenter.getpostman.com的索引可提供已发布API集合候选，但文档公开可能是正常设计；端点名称、参数样例与可用服务端秘密分别判断。登记发布者/项目归属、版本、环境变量、认证声明及具体暴露值的位置和预期受众，不由“sensitive APIs”题名直接确认私有数据可读。

从获准现有集合离线恢复请求结构及来源，不自动执行collection脚本、认证示例或整套请求。生产凭据只保留安全指纹/引用，调用能力另按[秘密边界](../by-type/info-secrets.md)核对；历史公共文档不继承当前第三方目标授权。

## Sling/AEM路径分解与真实资源选择

历史端点图中的content.json、数字/infinity/tidy选择器、jcr:content及feed/xml等形式只生成产品相关候选。[Sling URL分解](https://sling.apache.org/documentation/the-sling-engine/url-decomposition.html)按资源路径、selectors、extension、suffix处理，资源路径边界依赖实际资源结构，不能按第一个点机械切割（2026-10-09核对官方文本）。不同选择器/表示可能命中不同Servlet或脚本，需要实际部署与请求解析结果。

优先既有正常流量/获准配置，用同一受控资源和角色核对Dispatcher/网关过滤、Sling资源解析、仓库ACL及返回字段。200或JSON扩展不证明读取管理员资料、JCR版本或配置；合法公开内容、登录页与不存在资源的分解也作反例。原列表含深层内容和查询候选，枚举深度/输出量另设许可及预算，不把infinity或整个清单作为默认扫描动作。

## 外部平台断链与被引用身份

官网的外部平台链接要记录实际href、重定向、被引用账号/项目标识、页面位置和原用途。断链只证明一次访问结果；外部资源是否释放、能否重新注册、是否仍由原组织控制，需要该供应方与项目的具体证据。它与悬空DNS接管分别建模，不能把外部平台名字或历史奖金当当前可认领能力。
