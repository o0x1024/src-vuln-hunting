# 发现记录、去重与增量

遵守 [状态与证据](../state-and-evidence.md) 的存储和脱敏规则。以下是本地语义，优先映射宿主已有资产、Run/coverage/artifacts 或受控任务文件，不向 API 杜撰字段、不建立冲突事实源、不把运行资料写入 skill。需要文件回退时按需创建 `discovery.json`（计划/来源/队列）和 `observations.jsonl`（追加观察），已有宿主等效结构则不另存一套。

## 最小记录

| 对象 | 字段及作用 |
|---|---|
| 发现计划 | run_id、种子引用、必需/条件覆盖及来源、数值限制、验证预留预算、时间窗口、当前阶段和退出条件 |
| 来源批次 | source_id、提供商/材料引用、查询/过滤、来源观测时间、采集时间、材料版本、输入/下一页游标、批次 ID、错误/截断、已持久化标记 |
| 原始观察 | observation_id、source_id、证据引用/提取位置、安全的原值或受控原件引用、观察类型、时间、工具/版本及解析限制 |
| 候选资产/服务 | candidate_id、类型、规范化键、所有来源引用、归属状态/依据、scope 决定/版本、可达性观察、指纹/可信度、业务关系 |
| 接口 | endpoint_id、origin/协议、方法或 unknown、实际路径及路由模板依据、参数位置/结构、操作标识、认证前提、客户端/文档版本、来源与状态 |
| 关系 | 起点/终点、关系类型、证据、已观察或推测；如页面→接口、角色→功能、接口→任务、域名→云资源 |
| 工作队列 | work_id、候选/来源引用、动作、角色/状态、授权与资源前提、优先理由、pending/running/done/blocked/deferred、尝试/消耗、下一步 |
| 发现覆盖 | 来源/资产/角色/功能、必需性依据、done/partial/blocked/not_applicable、证据或缺口、终止原因 |

观察类型可用 `historical_reference`、`static_reference`、`normal_traffic`、`service_response`、`provided_inventory`。类型不是递增认证等级；历史引用可与当前正常流量同时保留。可达性用当前条件下的 observed/unreachable/unknown，401/403/WAF 等响应结果单列；unreachable 不删除旧观察、不证明业务停用。

归属、授权、可达性、接口发现、漏洞覆盖是独立维度。“当前有响应”不等于属于项目，“项目资产”不等于获准该动作。只做发现时 `hypothesis_status=null`，漏洞类别覆盖仍为 not_tested；发现工作可单独 done，不冒充检测 confirmed。宿主状态映射遵守 [工具契约](../tool-contracts.md)。

## 去重规则

先保留原始观察再建索引；聚类不删除证据。候选来源合并不合并不同角色的实验覆盖。

- 主机使用可靠 URL/IDNA 解析，scheme/主机大小写可统一，DNS 尾点和默认端口可在索引键中规范化，但原始表示与实际连接语义仍保留。不能用最后两段字符串判断所有根域；不确定公共后缀时保留完整主机，授权由宿主判定。
- 服务键含主机、协议和有效端口；共享 IP、相同证书、标题/图标/正文哈希只建聚类关系，不合并为一个资产。HTTP 与 HTTPS、TCP 与 UDP 分开。
- 路径不默认转小写、删尾斜线、解码 `%2F` 或压缩重复斜线；URL query 的顺序、重复键、空值和编码保留在观察中。不得用重建后的 URL 覆盖可重放证据。
- 接口键至少含 origin、方法和路径；路由模板只有得到文档、源码或充分正常样本支持时才能分组。数字段不自动替换成 `{id}`；API 版本、静态 `/latest` 和对象 ID 可能是不同处理器。
- 参数形状可以另建索引，包含位置、字段路径/类型、重复键与数组结构；形状聚类不抹掉签名依赖或值相关业务语义。请求样本的敏感值按凭据/受控对象引用保存，普通索引只含脱敏结构。
- GraphQL 按操作类型/查询结构和字段路径区分，operationName 可为空也可能重名；WebSocket 按连接上下文与消息类型，gRPC 按 service/method 记录。不能只按传输 URL 去重。
- 哈希片段可从 HTTP 传输键分离，但保留 SPA 导航键及其触发的接口。内容哈希仅用于解析复用；不同发布位置或身份引用仍保存。

例：`GET /api/v1/orders/42`、`POST /api/v1/orders/42`、`GET /api/v2/orders/42` 是不同接口；A/B 两个角色观察到同一 GET 接口可以共享接口条目，但角色覆盖各自记录。`?tag=a&tag=b` 不改写成单个 tag。只有静态 `/orders` 字符串时方法为 unknown，不凭名称生成请求。

## 队列、分页与恢复

同一 `来源+查询/窗口+页游标` 的批次内容先落盘并校验解析完成，再记录 next_cursor。故障恢复从最后持久化边界继续，已保存观察幂等合并；请求超时且未得到页面时不能猜下一页。游标失效时记录重新查询窗口和去重依据，不把重复结果算新增。

工作去重使用 `候选/来源 + 动作 + 方法/参数结构 + 角色/状态 + 材料或前提版本`。内容未变但角色、授权、功能开关、客户端配置、业务状态变化时，可重新打开对应分支；同样的文件内容不意味登录后的覆盖不变。

队列被容量上限截断时，保留溢出清单引用或可恢复的来源游标、数量/未知量与原因，发现状态为 partial，不能把已截断的空队列当完成。done 需要实际动作/结果；已登记但没执行为 pending/deferred。deferred 必需项仍是未完成，不能从分母移除。

来源游标只是采集恢复位置；不等于宿主的 `commit_watermark`。只有符合宿主和用户完整处置条件才推进项目增量水位，不能跳过受阻资产。改变窗口、重启、换工具均不得清零请求消耗。

## 变化与收尾

比较首次/最近观察、内容哈希、接口方法/参数形状、角色/状态与资产关系。新增、变化、当前未观察到、受阻分别输出；一次未返回不叫“已下线”，静态文件未变也不叫“全站未变化”。变化驱动当前授权任务中的相关分支，不自行创建监控或定时任务。

统计原始观察数、独立候选数、来源合并数、已授权数、当前响应数、新接口/业务关系数、未处理/受阻数及各来源状态。覆盖比例只有可解释分母时才给，例如“计划的 8 个角色/功能格已观察 5 个”；不能用发现的 URL 数作整个互联网资产或全部接口的分母。召回率仅用于有已知真值的隔离评测。

纯发现任务完成按 [资产发现退出条件](../asset-discovery.md) 判断；漏洞挖掘 Run 仍保留后续验证要求。恢复摘要只带计划/缺口、候选摘要、批次/游标、预算与证据引用，不把所有 URL、源码和响应塞进上下文。
