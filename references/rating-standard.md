# 评级与影响边界

## 平台规则优先

读取当前项目实际评级规则，记录来源、版本/日期和条款。本文不定义跨平台统一 S0–S3 标准，也不设数据数量线、测试环境固定上限或漏洞名称对应等级。平台明确使用 S0–S3 时才按其映射；无规则时给出严重/高/中/低的暂定意见与不确定性。

区分三个独立问题：漏洞是否成立、影响有多大、平台是否接收。重复、超范围、暂时无法复现不能统一归为“没有漏洞”；分别记录接收状态、范围决定和证据状态。

奖金另按资格与有效活动条款判断，不从严重度直接承诺金额。采用小米规则时查 [MiSRC 分层配置](policies/xiaomi-misrc.md)：Web/AI、移动、智能硬件、汽车和 PC 有不同业务范围、攻击前提及排除项；基础奖励、守护计划与历史活动不能混算。

## 收录评估先于等级优化

按 [企业影响与收录](impact-and-acceptance.md) 先判断可证明影响和当前收录条件，再按资产重要性、数据敏感性、实际能力、利用条件与可信规模定级。用户提供的 [三组规则样例](policies/src-policy-examples.md) 已保留，包含具体阈值与排除条款；来源/版本未知时不能作为默认有效规则。

低危不自动忽略，已确认也不自动接收。等级证据不足时给保守等级或待定；已知不收录的问题不因换成 RCE/高危标题而重新变为候选。一个数据总量字段不能证明全部可遍历，不通过批量取数、真实资损或服务中断满足评级条件。

## 影响评估字段

| 维度 | 记录什么 |
|---|---|
| 安全边界 | 原身份/能力、实际获得的数据/动作/执行上下文 |
| 资产 | 业务用途、环境、生产关联及证据；未知就写未知 |
| 数据 | 已观察样例类别、归属、敏感性；规模推断的依据和限制 |
| 用户/租户 | 实际验证范围与可推导范围，不能把两个测试账号写成全部用户 |
| 资金/资源 | 测试状态的真实变化、约束、次数与成本条件；不制造实际损失证明上限 |
| 利用条件 | 登录/角色、交互、网络、配置、时序、稳定性 |

不使用没有取值规则的乘法公式；置信度独立于严重程度。若用 CVSS，记录平台接受的版本、向量及各项依据，不凭漏洞名生成精确分数。

## 已证明与潜在影响

报告分别写已证明影响、潜在影响及待满足条件。不得为证明“批量/百万条/核心权限”增加真实数据访问、破坏性动作或内部横向测试。受限验证也可以支持有条件的影响分析，但不能把分析写成已执行事实。

| 类型 | 评级所需依据 | 不足以直接定级的线索 |
|---|---|---|
| SQL 注入/命令执行 | 实际执行/查询能力、身份和资产重要性 | 名称为 RCE 或扫描器标高危 |
| SSRF | 已突破的请求边界、可读内容和目的地条件 | DNS 回连直接推为内网读取/核心云控制 |
| XSS | 执行上下文、触发角色、受影响功能 | 存储型一律高危、DOM 型一律低危 |
| 越权/认证 | 资源规则、真实越界动作、数据与用户范围 | 改 ID 后 200、单次登录异常 |
| 云配置 | 有效策略及可达权限，是否违反预期边界 | 公网端口、匿名认证开关、身份查询成功 |
| AI / Agent | 数据归属、输入摄取、工具执行主体、授权决策与真实终态 | 模型自述执行、纯越狱、公开内容、预期沙箱能力 |
| 移动 / PC | 原版环境、初始权限、远程/本地、实际交互、最终进程/系统能力 | root/调试器修改结果、同权限执行、纯配置或重打包 |
| IoT / 汽车 | 型号/固件、网络/物理条件、绑定关系、实际组件/设备状态与可推导范围 | 自有设备正常控制、模拟器结果直接外推真机、组件权限直接外推整车 |

测试环境结合实际隔离、数据、凭据与生产关系判断。不能为查清关系主动进入未授权生产资源。

## 漏洞链与提交

每个节点和连接分别标为已验证、证据支持但未执行、未知；链条跨越新目标或动作需重新授权判定。按平台合并/拆分规则提交，既不重复计算影响，也不默认所有节点只能合并一份报告。

最终字段：暂定等级、规则来源/条款、已证明事实的证据 ID、影响状态、收录评估/排除原因、潜在影响、限制和平台实际接收状态。无规则或无法确定时保留待定，不能套用历史平台门槛。
