# 阶段 3：漏洞检测（按价值排序）

## 第一梯队：业务逻辑漏洞（SRC 高分值洼地）
- 越权（IDOR）：水平（改 ID 看他人数据）、垂直（低权限调高权限接口）
  - 验证：替换 ID/批量参数、切换账号对比、直接调用未授权 API
- 支付逻辑：金额篡改、优惠券重放、并发下单、负数金额、组合优惠溢出
- 验证码：短信轰炸、绕过（响应回显、万能码、可爆破、前端校验绕过）
- 密码重置：token 可预测/可爆破、重置他人账号、短信验证码接口逻辑缺陷
- 业务流程绕过：订单/积分/抽奖/邀请返利/会员升级流程跳跃
- 并发竞态：并发领取、并发提现、并发兑换（超发）

## 第二梯队：认证与访问控制
- 未授权访问：后台、管理 API、调试接口、actuator、swagger
- JWT：alg 混淆（none/HS256 爆破）、弱密钥、payload 篡改
- Session/OAuth/SSO：会话固定、redirect_uri 校验、state 缺失、token 泄漏

## 第三梯队：经典 Web 漏洞
- SQL 注入、XSS（存储型优先）、SSRF、CSRF
- 文件上传（内容/后缀/解析绕过）、命令注入、反序列化、任意文件读取

## 第四梯队：组件与基础设施
- 中间件/框架历史 CVE（需确认版本、在范围内、真实业务）
- 未授权：Redis、Memcached、MongoDB、ES、数据库端口暴露
- 存储桶配置错误、云服务错误配置

## 快速验证要点
- 每个发现先确认「是否在范围 + 是否真实业务 + 危害能否证明」
- 用最小请求证明漏洞，避免产生破坏性副作用
- 高危发现优先验证数据可达性，但不要真的导出用户数据
