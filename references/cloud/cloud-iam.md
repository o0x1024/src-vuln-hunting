# 云身份、策略与信任

## 适用信号与前提

过度授权、跨账号信任、角色委派、MFA/生命周期规则和疑似凭据暴露。只使用用户明确提供并允许使用的测试身份；发现生产凭据不等于获准使用。没有身份时可继续脱敏位置/策略分析。

## 最小实验

先确认当前身份及作用资源，再读取获准策略材料或调用明确允许的非敏感测试资源动作。身份策略、资源策略、边界、组织约束、会话条件和显式拒绝共同决定有效能力，单一通配条目不足以证明管理员权限。

`aws sts get-caller-identity` 返回调用者身份，不能枚举有效权限，也不能证明身份可管理资源。[AWS 官方说明](https://docs.aws.amazon.com/cli/latest/reference/sts/get-caller-identity.html)。其他厂商采用各自实际 API，不通过名字相似推断行为。

信任/MFA/角色问题优先结合只读配置与获准测试身份验证，记录委派前提和资源范围。不修改信任、不新增账号/密钥、不绑定高权限角色来证明提升。

## 确认与反例

确认为泄露、配置偏差或越权能力中的哪一种。公开疑似 key 文本不证明凭据有效；身份查询成功不证明高权限；静态策略片段不证明最终允许。

排除示例/已撤销凭据、条件约束、显式拒绝、预期服务角色权限和未生效配置。无法确认有效权限时保留限制，不探测更多生产管理 API。

## 下一步、停止与报告

最小边界证据充分即停；需要生产凭据或管理动作的分支记录受阻。凭据只保留受控引用与脱敏位置，不进入报告、模型上下文或带外请求。

报告记录身份别名、策略来源、规则、实际成功/拒绝操作、权限上限及未验证部分。遵守 [验证](../verification.md)。

## 调研补充：有效权限的证据

将“识别身份”“读取策略”“实际获准能力”分开。AWS GetCallerIdentity 不要求调用权限，其成功结果不能推断高权限。角色信任、主体策略与资源条件必须对应具体动作；缺证据就列出待验证能力，不能用创建管理员、修改信任或读取真实秘密来证明。
