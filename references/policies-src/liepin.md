# 猎聘 猎聘安全应急响应中心（LPSRC）报告处理规则摘要
- 状态: official；置信度: 高
- 来源: https://security.liepin.com/announcement/msg/139（查阅于 2026-10-12）；规则版本/更新: 《LPSRC漏洞处理和评分标准》V5.0，2024-03-05 施行（V1.0 2021-08-09 → V5.0 2024-03-05 共 5 版）
> 公开规则检索摘要，供选题与定级预判；非授权，不保证当前有效，提交前必须核对官方原文。

## 收录范围
- 适用范围：猎聘安全应急响应中心网站（security.liepin.com）收到的安全漏洞情报。
- 业务范围：猎聘互联网业务，包括猎聘发布的 PC 端网站、APP 客户端、微信小程序等。
  - 核心应用：liepin.com 域名下面向公众的招聘和求职应用。
  - 一般应用：www.duolie.com、www.lebanban.com、www.duomian.com。
  - 其他应用：上述域名下的其他应用。
  - 客户端应用：猎聘 app、多面 app、乐班班 app。
- 第三方服务和产品、操作系统、中间件、SDK、组件类漏洞：作为安全情报处理，视对猎聘影响程度酌情奖励，按"其他应用"类别计分。

## 等级与奖励
- 奖励单位为贡献值；安全币 = 贡献值 × 10（LPSRC 有权调整公式）；安全币在站内虚拟市场兑换礼品，未使用不过期；礼品次月月初发放。
- 特别重大漏洞有特殊奖励（形式由 LPSRC 决定）；不定期积分加倍、排行榜、节日活动。
- 等级：严重 / 高危 / 中危 / 低危 / 无效（要点）：
  - 严重：获取后台最高管理权限（RCE、可利用 webshell、重大危害弱口令）；核心库 SQL 注入、批量简历/订单等敏感信息泄露；任意账号登录/改密、支付绕过、大量资金损失逻辑、盗用官方身份发消息。
  - 高危：后台一般权限、任意文件下载、不含敏感信息的 SQL 注入；刷猎币等高利益逻辑；绕过认证访问敏感后台、大量内网敏感信息 SSRF（不得内网扫描）；移动端任意代码执行/本地提权。
  - 中危：需交互触发（存储 XSS、核心功能敏感操作 CSRF）；XXE、SSRF（按附录证明可访问内网且不得扫描）；任意文件上传、暴力破解；普通越权；GitHub 内部代码/邮箱密码泄露；小额优惠券重复领取等；客户端敏感信息泄露（弱加密、明文存储密码等）。
  - 低危：特定环境才能触发（反射 XSS/DOM-XSS）；SVN/phpinfo/logcat/配置文件/webpack 泄露；重要子域 URL 跳转；无回显内网 SSRF；无限制短信轰炸（参考 30 条/单手机号/分钟）；客户端本地拒绝服务、本地 SQL 注入（仅库名/字段/cache）等。
- 注：贡献值分档数值表在原文中以表格/图片呈现，本次抓取文本未保留具体数值，需站内核对。

## 忽略/不收项
- 无效漏洞：无关安全的 bug；无法利用的"漏洞"（无意义扫描器报告、Self-XSS、无敏感信息 JSON Hijacking、无敏感操作 CSRF、无意义源码泄露、内网 IP/域名泄露、401 基础认证钓鱼、明文传输等）；运营预期内或不造成资金损失的问题（多账号领小额奖励的正常活动）；业务方不认可且不会修复的轻微越权、无意义 CORS 等。

## 测试红线
- 禁止影响业务系统正常运行、影响用户体验、批量获取数据、越权修改或删除他人信息、对可用性和基础设施破坏性测试；违者作废奖励并可能追责。
- 禁止上传病毒、木马、后门；禁止 DoS/DDoS、自动化扫描测试、高频请求；发现服务中断应第一时间通知。
- 涉及内网/数据库的漏洞证明存在即可，禁止内网横向探测；SSRF 按附录（http://ssrf.tongdao.cn/ssrf.html）方式证明。
- 禁止公开传播漏洞信息；越权测试自行注册 AB 账号，违规以无效处理并禁止提现；短信/邮箱轰炸用自有账号。

## 报告要求
- 通过 LPSRC 平台提交；同一漏洞只奖励最先提交者，后续按"重复漏洞"忽略。
- 争议可在漏洞后留言，或发邮件 src@liepin.com；必要时引入外部人士共同裁定。

## 处理流程与时限
- 提交后下一个工作日内展开评估；三个工作日内处理并反馈评估结果。
- 修复时效：严重 1 个工作日、高危 5 个工作日、中危 7 个工作日、低危 10 个工作日（客户端受版本发布限制）。
- 业务保护机制：同一系统短时间大量同类型漏洞，业务确认已知后只收录第一个，其余降级或不收并公告。

## 易错点
- 安全币=贡献值×10，但各业务/等级的贡献值分档数值需站内核对，不能凭空估算奖励。
- 第三方组件/中间件漏洞不按漏洞计，按"其他应用"情报酌情奖励。
- 同系统同类型漏洞有"只收第一个"的业务保护机制，批量提交前先看公告。
