## 收录范围
- Web 服务：.ximalaya.com、.qingxuetang.com、.himalaya.com、.qijizuopin.com、.ximalayaos.com、.xima.tv、.xiaoyastar.com、.zhishidashi.com；.xmcdn.com 与 .test.ximalaya.com 只接收高危及以上；第三方服务仅接收能影响喜马拉雅的高危及以上漏洞（v2.1 范围，V3.0 可能有增删）。
- APP 服务：喜马拉雅FM、喜马拉雅急速版、喜马拉雅儿童、喜马拉雅精品、喜马拉雅主播、轻学堂、小雅助手、奇迹小说、Himalaya、宝贝听故事、小雅AI音响、妙呜、顶空。
- 同时接收针对喜马拉雅的威胁情报与业务安全问题。
## 等级与奖励
- 评分公式（v2.1）：1 安全币 = 1 元人民币；安全币奖励 = 漏洞分值 × k（k 按业务重要程度动态调整）。
- 分值范围：严重 90-100、高危 50-85、中危 25-45、低危 5-20、忽略 0；k 值：核心业务 10≤k≤20、一般业务 5≤k≤10、边缘业务 1≤k≤5。
- 等级定义（v2.1）：严重=核心系统权限/核心库大量敏感数据/核心业务严重逻辑；高危=一般系统权限、核心越权敏感操作、整站源码或大量员工/用户信息泄露、客户端远程代码执行、核心存储型 XSS 等。
- 影响特别广泛、危害特别严重的漏洞可给特殊高额奖励；曾设年终奖励计划（2021 起，高危及以上 3 倍活动等）。
## 忽略/不收项
- 【忽略】无危害（v2.1）：不可利用的 Self-XSS、反射 XSS、非重要交互（查询类）CSRF、静态文件目录遍历、401 认证钓鱼、内网 IP/域名、无敏感信息的 JSON 劫持、横向短信轰炸、Spring-boot actuator 接口泄漏、SPF 邮件伪造、无法复现、内部已知/处理中、无意义扫描器报告、非接收范围、无法造成安全风险的功能 BUG。
## 测试红线
- 需遵守《SRC行业安全测试规范》与《网络安全法》；对正常业务造成明显干扰的漏洞降分或 0 分，恶意拖取数据等越界行为追究法律责任并配合公安取证（V3.0 补充说明）。
- 漏洞修复前，报告不得存放于互联网开放服务（网盘、代码托管平台等）；修复前被公开/泄漏的报告作 0 分（V3.0）。
- 同一处漏洞最早提交者得分；同一漏洞的多个利用点/链按危害最高的利用思路奖励（V3.0）。
## 报告要求
- 使用官方《喜马拉雅SRC漏洞模版 V1.0》，图文形式在线撰写（无需上传 word），上传图片用"插入全部"插入文本框。
- 必备要素：【漏洞复现】按步骤呈现接口参数与测试过程，附 PoC/工具/技术信息；【测试源信息】越权/未授权/内网/金钱类漏洞需给测试账号、订单号、测试 IP 等便于溯源；【修复方案】给出针对性方案。
- 缺关键因素（文字描述、图片证明、测试过程、风险接口和参数）、排版混乱、无法稳定复现的报告做降级/忽略处理。
## 处理流程与时限
- 承诺每份报告专人跟进、分析和处理并尽快答复；具体时限未在索引摘要中取得。
## 易错点
- 官方站对当前网络直连被 TLS 拒绝，规则正文需真实浏览器/国内网络核对；本摘要来自官方页面的索引快照，v2.1 与 V3.0 并存，以站内最新版为准。
- 修复前把报告传到网盘/GitHub 等开放服务直接 0 分——写报告时的存储习惯要格外注意。
- 奖励是"分值×k"乘法模型：同一漏洞在核心业务与边缘业务的金额可差 10-20 倍，报告应明确资产归属与业务重要性。
- .xmcdn.com（CDN 域）与测试环境只收高危及以上，低危提交会被忽略。
- 测试源信息（账号/订单号/IP）是溯源审核必需，漏给会被退回或降级。
