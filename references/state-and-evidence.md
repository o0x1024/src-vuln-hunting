# 状态与证据协议

## 存储位置与权威来源

优先使用已连接宿主的 Run、资产与 Finding 存储；工具接入见 [工具契约](tool-contracts.md)。无此存储时，在宿主批准的任务输出目录创建 `runs/<run-id>/`。不把运行数据、账号或请求写进 skill 安装目录。

授权与预算以用户/宿主为权威；原始证据以执行工具为权威；模型生成的摘要和假设是可修订解释。文件哈希用于完整性比对，不构成不可篡改存储；需要强审计时由宿主提供权限隔离。

## 最少数据

| 记录 | 字段与用途 |
|---|---|
| 任务 | schema_version、run_id、模式、目标、项目/授权快照引用、预算/消耗、状态、起止时间、完成要求 |
| 发现 | 来源批次/游标、原始观察、候选资产/接口、关系、工作队列、角色/功能采集覆盖；结构与去重见 [发现记录](discovery/records-and-incremental.md) |
| 选题 | 项目资格/规则引用、候选事实、关键未知、选择理由与成本；探索短记录见 [选题与探索](hunting-strategy.md) |
| 实验依赖 | 请求模板/实际证据关联、会话引用、动态值来源、攻击与准备身份、资源状态及结果判定；按需记录，细则见 [实验设计](experiment-design.md) |
| 领域上下文 | AI 的版本/摄取/检索/工具主体/沙箱；客户端的签名/OS/初始权限/交互；设备的型号/固件/网络/绑定/恢复状态；按选中专题记录，不强填无关字段 |
| Fuzz 候选与反馈 | 种子引用、推导规则、变异维度、基线/模板版本、实际消耗与证据、下一步及重开条件；按 [定向 Fuzzing](targeted-fuzzing.md) 附于已有队列/实验记录，未执行候选不算覆盖 |
| 业务 | 功能用途、角色/租户引用（含匿名）、资源归属、操作/字段允许受众、授权方式、状态转换、规则及来源、未知项；公开/匿名场景见 [业务预期判定](business-intent.md) |
| 假设 | hypothesis_id、依据、目标、规则、受保护业务/影响链、实验、确认条件、替代解释、技术状态、影响状态、收录评估、下一步理由 |
| 实验事件 | experiment_id、hypothesis_id、时间、工具/版本、实际目标、身份引用、动作、结果、证据引用、状态变更 |
| 覆盖 | 目标、操作、身份/角色、状态前提、测试类别、状态、证据或未完成原因 |
| 清理 | 自建资源、变更记录、允许的清理动作、执行结果、需平台处理项 |

采用上述字段的可读 JSON/JSONL 或宿主等效结构即可，不创建第二套与宿主冲突的事实源。离线回退可使用 `run.json`、`business.json`、`hypotheses.json`、`events.jsonl`、`coverage.json`、`evidence/`、`cleanup.json`；按需创建，不为空白表格占满上下文。

## 状态语义

| 对象 | 状态 |
|---|---|
| 假设 | pending / testing / needs_evidence / confirmed / not_reproduced / blocked |
| 覆盖 | not_tested / tested / partial / not_applicable / blocked |
| 本地任务 | running / completed / partial / waiting_input / cancelled |

`not_reproduced` 仅指已执行的具体条件；`tested` 不等于目标无漏洞。`not_applicable` 需要目标不存在该能力等依据，缺少账号应为 blocked。宿主状态枚举不同则按实际 schema 映射，在 conclusion/coverage 保留原始语义，不编造 API 状态。必需项缺失时不可映射为 completed。

多分支任务逐个保存假设与覆盖状态；有可执行分支且正在继续时，任务仍为 running，不能因一个分支 blocked 就把整个任务标为 partial。partial 表示本次执行已停止并交付部分成果。汇总状态不能覆盖分支明细。

判读/报告复核任务可以在完成本次审阅后结束，但不把完成状态回写到原挖掘 Run；原任务的覆盖、资源清理与交接仍以实际证据为准。若材料没有提供清理结果，记录未知或待交接，不能将提出清理建议写成已完成清理。

状态变化追加原因、时间和证据引用。修正错误不覆盖原始事件；新证据可以重新打开假设。用户更改目标或授权应保存新版本与影响范围。

## 影响与收录状态

按 [影响与收录](impact-and-acceptance.md) 分开记录 hypothesis_status、impact_status、submission_assessment、platform_status，附适用规则和证据引用。它们是本地评估或宿主等效结构，不代表原生工具已支持同名字段；使用宿主现有说明/证据字段或受控任务文件保存，不能强行向 API 添加未知字段。

confirmed 不自动创建待提交 Finding。无影响、暂不收、重复、修复窗口等结论不删除原始事件；有新证据/规则变更时说明原因后重评。恢复任务同时读取这些处置结果，避免反复验证已明确无收录价值的相同条件。

按需附奖励资格与附件/人工验证缺口，含适用版本、条款、活动状态及未知原因。奖励资格不是平台回执；模型/工具版本、设备固件、共享关系或配对状态变化后，重新判断原证据是否仍适用，不静默继承旧的 ready。

## 证据对象

为每个实际请求/操作生成唯一证据 ID，记录实验 ID（纯发现用来源批次/观察 ID，不虚构假设）、工具、UTC 时间、目标、身份引用、Method/URL、请求与响应引用、HTTP 与应用状态、业务前后状态及错误。工具支持时保存内容哈希。时间差实验额外保存原始样本和对照；带外实验保存唯一标记、触发窗口、接收事件和归因限制。

- 原始请求仅在获准的受控位置保留必要数据；报告与模型上下文使用脱敏副本。敏感原件无法合规保存时，记录删减范围与验证限制，不承诺完整原件。
- Cookie、Authorization、密码、云凭据、个人数据不进入普通日志、报告或知识文件。使用 credential_ref、身份别名和占位符；复现说明写明重新获取凭据的方法。
- 不向第三方带外域名发送命令输出、凭据或业务内容；标记只包含随机实验关联信息。
- 大响应存文件并提供摘要、截断标识、哈希/大小和读取入口。原始证据不可用、被截断且缺少关键字段时，不确认依赖这些字段的结论。
- AI 的生成文本与真实 tool trace 分开引用；设备的请求/帧、云端回执和设备状态关联到同一实验。截图未进入模型视野、动态工具无连接、视频未生成都如实标缺失，不能用文本占位冒充已采集证据。

## 检查点与恢复

有副作用动作前追加意图、资源和操作标识；完成后写实际结果。每个实验结束保存检查点。恢复时读取未结束事件，先核实已生效状态，不能重放所有 pending 动作。

恢复摘要只含当前目标/约束、已确认事实、活跃假设、证据 ID、未完成动作和下一步。重查会话、授权时效及资源状态；已测条件未变不重复测试，条件变化则记录新实验。消耗计数不能在上下文压缩、重启或换工具后清零。

## 去重与清理

按项目、资源/端点、规则/根因、身份边界、状态前提和输入变体识别相同实验；不能只按 URL 去重而漏掉其他角色或方法。Finding 合并保留原证据，不因合并删除审计记录。

仅清理有明确归属和清理许可的自建测试资源，记录清理结果；失败或无权清理交由平台处理。保留证据遵守约定期限，删除证据或宿主记录需独立遵守已有删除授权。
